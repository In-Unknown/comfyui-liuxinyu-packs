# 传入虚拟连接

虚拟连接的**发送端**：接收一条或多条上游数据，通过相同的键交给不同位置的多个同键[传出虚拟连接](LiuxinyuVirtualInput.md)。两端之间不用画线，适合跨画布或嵌套子图传递文档目录、图片、记录数组等数据。

“传入”指其他节点将数据传入此处，因此本节点左侧只有数据输入端口，右侧没有输出端口。运行前，两端会还原为普通连线，下游自然依赖真实上游；节点不保存运行变量，也不需要另设读写顺序。

## 输入

| 参数 | 描述 | 数据类型 | 必需 |
| --- | --- | --- | --- |
| `键` | 配对名称，默认空字符串；直接在文本框填写，无连线端口。按完整文本匹配，区分大小写和空格；空键时不显示任何数据输入 | STRING | 是；建立配对时须填写 |
| `输入 1`、`输入 2`…… | 按编号接入上游数据。填键后按连接动态增长，无固定数量上限；类型随上游和配对接收端同步 | ANY，连接后显示对应的实际类型 | 按需；接收端使用某一路时，该路输入必须连接 |

没有其他控件。键不支持从上游动态计算；它用于编辑和提交工作流时确定连线。

## 输出

本节点没有右侧物理输出端口。数据从同键“传出虚拟连接”的同编号输出送出：

| 输出名称 | 描述 | 数据类型 |
| --- | --- | --- |
| 配对端的 `输出 1`、`输出 2`…… | 分别对应本节点的输入 1、输入 2……，相当于将每路上游直接连接接收端的下游 | 与对应上游相同，包括原有执行列表语义 |

## 直接照做：把文档目录传到远处

1. 添加字符串节点，填入 `C:\project\prompts`。
2. 添加“传入虚拟连接”，键填 `文档目录`；此时出现“输入 1”。
3. 字符串输出连接“输入 1”，该路类型显示为 STRING，并增加下一个空输入。
4. 在远处或嵌套子图里添加“传出虚拟连接”，键同样填 `文档目录`。
5. 接收端“输出 1”连接[在绝对路径中的相对路径](ResolveRelativePath.md)的“绝对路径”，相对路径填写 `卖点提取提示词.md`。

```text
字符串 C:\project\prompts → 传入虚拟连接（键：文档目录，输入 1）
                              · 同键配对 ·
传出虚拟连接（键：文档目录，输出 1）→ 拼接相对路径 → 读取文本文件
```

需要在另一处读取系统提示词时，再添加一个同键 `文档目录` 的传出节点，将其“输出 1”接另一条相对路径链路，填写 `卖点提取系统提示词.md`。两个传出都收到 `C:\project\prompts`，不用增加传入节点或重复连接字符串来源。

拼接结果为 `C:\project\prompts\卖点提取提示词.md`。运行时，接收端下游实际连接到原字符串输出，保留上游依赖。

## 多路配对与端口增长

| 本节点输入 | 配对接收端输出 | 示例 |
| --- | --- | --- |
| 输入 1 | 输出 1 | 文档目录字符串 |
| 输入 2 | 输出 2 | IMAGE 图片批次 |
| 输入 3 | 输出 3 | 完整记录数组 |

键为空时零端口；填写后，如果没有配对端，先出现一个 ANY 输入。传入端或任一同键传出端连接末尾备用口时，全部同键端点同步增加下一路空口。断开连接时逐路检查：只要传入端或任意一个传出端仍连接该路，就在全部端点保留它；只有传入端和所有传出端都不再连接该路时，才同步删除它。中间空路也按此规则收起，后续通道编号依次前移，上游与各下游的实际配对保持不变。末尾始终保留一个灰色任意备用口；全部断开后也保留这一个备用口。

可以先建发送端，也可以先建接收端。先在接收端连接下游时，会根据下游端口确定类型，随后创建的发送端继承对应数量和类型。发送端接入明确类型后，以真实上游类型为依据，同步到所有传出端，并逐个检查是否满足各传出端下游要求。同一路不能为不同传出端提供不同类型；类型冲突时需要调整下游或添加转换节点。

## 同键唯一性与工作流范围

- 同一个工作流中，每个键最多一个传入端（发送端），可以有多个传出端（接收端），数量没有固定上限。主图与嵌套子图共用该范围，不同工作流互不配对。
- 再新增传入端并填写已有传入端的键时，会提示冲突节点编号，清空当前新填写的键；已有配对保持原样。
- 复制传入节点时也检查重名；复制或新增传出节点可以保留相同键。多个下游既可以从一个传出端分叉连线，也可以在各处放置同键传出端。
- `文档目录`、`文档目录 `、`Docs`、`docs` 是不同的键。点号、斜杠仅为名称字符，没有路径或字段访问含义。
- 仅含传出端的子图可以重复实例化，各实例同键传出都连接唯一传入端。如果复用子图中包含同键传入端，仍会造成来源重复；提交前会列出实例路径并拒绝配对，须调整传入端的位置或键。

键、端口与本地连线随工作流 JSON 保存，重新打开或换电脑加载后重新配对。接收端所在电脑需要安装本节点包及前端扩展。

## 数据结构与执行行为

每一路独立还原成原上游连线，不合并数据、不拆分数组、不填充较短的执行列表、不深拷贝对象。

| 上游结果 | 下游收到的内容 |
| --- | --- |
| 完整数组 `[1,2,3]` | 一个完整数组 |
| 执行列表，执行项为 `1`、`2`、`3` | 原来的三个执行项 |
| 字典 `{"topic":"承重"}` | 原字典，保持类型 |
| IMAGE 图片批次 | 原图片批次 |
| 空执行列表 | 零个执行项 |

只使用接收端输出 1 时，仅要求该路的真实上游；没有使用的其他路不会仅因挂在发送端上而被强制执行。多个下游共用同一路时，沿用普通连线的执行与缓存行为。

分包与循环同样按照还原后的连线确定边界。虚拟连接不能绕过原本的依赖、循环边界或类型要求；相当于把那条普通连线隐藏起来。

## 多端连接的保留与收起示例

假设同键有一个传入端和传出 A、传出 B，已经连接了三路数据：

| 操作 | 同键全部端点的变化 |
| --- | --- |
| 传出 B 接上第 4 路备用口 | 传入端、传出 A、传出 B 都增加第 5 路备用口；第 4 路传入尚未接线时运行仍报缺输入 |
| 第 2 路只断开传入端 | 保留第 2 路；传出仍在使用，运行报缺输入 |
| 再断开传出 A 的第 2 路，传出 B 仍连接 | 仍保留第 2 路 |
| 最后断开传出 B 的第 2 路 | 全部端点一起删除第 2 路，原第 3 路及后续通道前移，实际数据配对不变 |
| 所有数据连接都断开 | 每端只保留一个灰色任意备用口 |

如果只是传出端全部断开，而传入端该路仍连接上游，也会保留该路。检查范围是全部同键传出端，包含嵌套子图里的节点。

## 数据端口编号与缺少输入的报错

`键`仅用于配对，不占输入或输出的通道编号。只接一条 STRING 输入时，传入端显示“输入 1 · STRING”和“输入 2 · 任意”，所有同键传出端显示“输出 1 · STRING”和“输出 2 · 任意”。灰色任意口是供后续连接的备用口，不是第二份数据；不会因为键控件而多出一个 STRING 输出。旧工作流加载后会重新计算端口标签和数量，保留实际数据连线。

检查依据是各路是否实际连入下游，不是要求所有可见端口都连接：

| 连接情况 | 运行前结果 |
| --- | --- |
| 只用输出 1，输入 1 已连接，第二路为未用备用口 | 通过 |
| 输出 2 已接下游，但输入 2 未连接或不存在 | 报错并阻止提交，不以空值代替 |
| 任一同键传出端使用了缺少输入的通道 | 报错，指出具体传出端及唯一传入端 |
| 输入连线指向已不存在的上游接口 | 报错，须恢复有效上游连接 |

例如，传出节点 `257:713` 的输出 2 已连接，但传入节点 `722` 的输入 2 未连接，会提示：

```text
键“文档目录”第 2 路缺少有效输入：传出虚拟连接 257:713 的输出 2 已连接下游，但传入虚拟连接 722 的对应输入未连接或上游接口不存在。请连接输入 2，或断开该路传出连接。
```

运行与前端 API 导出都执行此检查；修改扩展后须刷新页面才能使用新检查逻辑。

## 运行前检查与常见问题

| 现象 | 说明或修正方法 |
| --- | --- |
| 填键后又变为空 | 已有同键传入节点；查看提示中的编号，复用已有来源或换一个键 |
| 未填键时没有端口 | 正常；先填写配对名称 |
| 接收端使用第 N 路，但提示发送端未连接 | 将数据接到发送端输入 N，不会自动挪用其他输入 |
| 提示类型不匹配 | 错误包含键、通道编号、传出节点编号、发送类型与下游要求，调整连线或显式转换类型 |
| 上游换类型后已有连线不兼容 | 保留连线供修正，提交时明确报错，不静默删除业务连接 |
| 提示循环配对或执行依赖环 | 检查是否又把接收结果接回同一条发送链；按普通连线规则消除环 |
| 清空键之后连线消失 | 空键必须零数据端口，因此清空会移除本端数据端口及其连接；其他同键端点的键不被清空 |

尚未使用的单端允许保留。接收输出实际接到下游时，提交前必须有唯一发送端和已连接的对应输入。以真实业务下游节点作为执行目标，两端本身是连线标记。

## API 导出与开发验证

安装本扩展的前端在运行和 API 导出时编译虚拟连接：UI 工作流仍保留全部虚拟连接节点，API 工作流中它们被移除，并替换成普通连线。直接把含这些占位节点的原始 UI JSON 交给不支持本扩展的第三方转换器，不等价于此前端导出的 API 工作流；未转换的节点执行时会明确提示刷新前端或重新导出。

节点 ID：`LiuxinyuVirtualOutput`，分类 `liuxinyu/虚拟连接`。Python 定义位于 `virtual_connections.py`，沿用包根自动加载；动态端口、重复键检查和提交转换位于 `virtual_connections.js`。参照同包分包节点的动态端口与工作流转换方式。新增后重启后端并刷新页面。

非 UI 检查：`node tests/test_virtual_connections.cjs`；实际执行器回归：`tests/test_virtual_connections.py`，覆盖同键多个传出、跨子图复用、完整数组、执行列表、图片引用和嵌套分包。
