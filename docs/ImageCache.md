# 图像节点的临时缓存

不增加开关，不修改已保存工作流中的入参。

- 加载批次、拼接、切块、合成等处理节点使用 ComfyUI 原生结果缓存。参数、枚举和上游依赖相同时跳过计算。原生缓存因内存压力被释放后，会正常重新计算。
- 路径加载节点用 SHA-256 检查文件内容和有序文件列表；同名、同尺寸、同修改时间的覆盖也能识别。路径来自连线时，记录之前实际收到的路径，以便下次运行检查文件。目录匹配节点检查目录条目及匹配表达式可使用的文件属性。
- 文本文件和比例绘制节点的蒙版、画笔文件也参加内容检测，避免它们让图像处理链一直重跑或使用过期数据。
- 超长图预览、从批次选择保存、保存到绝对路径：检查实际图像张量的形状、类型、完整像素值及全部参数。完全相同时复用上一份 PNG 和 UI 信息，不重复编码、不重复自动保存。此处会做哈希检查，因此耗时不是绝对为零；不将图像降到 8 位后再比较。
- 每个节点只保留最近一组临时预览。处理整份 IMAGE 列表后统一替换；全部成功才删除旧组，失败则删除本次产生的半成品并保留旧组。不同节点相互隔离，列表缩短也会清理多余旧图。
- 临时 PNG 被手动清除后，下次运行重建预览；重建不重复追加永久保存文件。手动“保存所选”按钮仍会按每次点击追加保存。
- 选路径时的即时缩略图也按内容和尺寸设置复用，保留原有会话、版本防乱序处理。
- 预览命中同一组文件时，前端保留长图查看位置与批次选择状态，不重新创建图片容器。

缓存只在当前 ComfyUI 进程内有效，不写入工作流，也不额外保留大图张量。预览记录最多保留 256 个节点；文件变化检测最多记录 256 个节点、每节点 64 个历史路径表达式，超出时淘汰并使旧原生缓存失效。历史路径也需要检查，是因为原生 RAM/LRU 缓存可能在 A→B→A 时返回早先的加载结果。

为了及时删除旧预览，终端预览节点每次会进入内容检查；不能让原生缓存直接返回已经删除的旧文件引用。带预览输出的路径加载器也会使已退役文件对应的旧缓存失效；切换连线传入的路径后，可能需要额外执行一次加载以稳定原生缓存版本。

只清理本模块明确登记的临时文件，不扫描删除整个 temp，不删除源图片、永久保存结果、input 中的编辑图层。因此旧执行历史中的临时图片在新结果替换后会失效，这是“仅保留最近结果”的预期行为。

后端回归测试：在便携版根目录运行 `python_embeded\python.exe -X utf8 -s -m unittest discover -s ComfyUI\custom_nodes\comfyui-liuxinyu-packs\tests -v`。缓存测试使用真实 `PromptExecutor` 和 RAM 缓存，包含连续复用、文件覆盖、目录增删、参数改变、A→B→A、列表缩短、失败回滚和手动保存。
