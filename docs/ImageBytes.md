# 图像编码与字节数据

这组节点把“像素”和“编码文件”分开传递。适合先控制 JPEG 质量、透明度或无损编码，再把文件字节交给远程 API 或保存节点，避免下游把 JPEG 解码后重新编码为体积更大的 PNG。

## 三种类型

| 类型 | 内容 | 使用方式 |
| --- | --- | --- |
| `IMAGE` | ComfyUI 浮点图像张量，通常为 `[B,H,W,3]` | 裁切、缩放、拼接、绘制等像素处理 |
| `IMAGE_BYTES` | 一个完整编码图像文件的不可变 Python `bytes` | 已验证的图像文件；可直接保存或传入支持该类型的 API 图片口 |
| `BYTES` | 任意文件的不可变 Python `bytes` | 不保证是图片，须经提取节点完整验证后变为 `IMAGE_BYTES` |

两种字节类型都不使用路径、Base64 字符串、URL 或带标记的字典作为运行时值。类型名是连线契约，图片实际格式仍从内容识别，不能靠改扩展名把 PNG 变成 JPEG。

## 动态编码参数

参数名按中文显示，布尔开关显示“开启／关闭”。当前前端会将动态子参数名覆盖为英文键，本包在创建、切换格式和恢复工作流后按schema恢复中文标签；不改参数键、值、连线或节点尺寸。TIFF菜单显示“字典压缩（LZW）”“无损压缩（Deflate）”，实际保存和执行仍使用原值，旧工作流兼容。JPEG、PNG等格式标识保留。更新此显示适配后刷新页面即可，不需要重启后端。

## 透明度与交错分别做什么

PNG 可以同时是“非交错 + 透明”，也可以是“交错 + 不透明”。交错是 Adam7 扫描顺序；Alpha 是每个像素的透明度。希望透明区域变白，关闭“保留透明度”并选白色背景；希望保持透明，则开启“保留透明度”。原始数据没有 Alpha 时，开启保留透明不会自动抠图。

普通 ComfyUI 加载节点常把透明度单独输出为 `MASK`。编码时把该口接到“透明遮罩”，遵循 `1=透明、0=不透明`。不连接时仅使用图像张量自身的 Alpha（如果有）；遮罩连接后覆盖原 Alpha。

## 格式、精度和元数据

- 编码不缩放图片。张量会限幅到0～1，再取最近整数成为8位像素；不保留HDR或16位精度。
- PNG、无损WEBP及TIFF可无损保存这些8位像素；JPEG质量100仍有损，GIF有调色板量化，AVIF此节点使用质量编码。
- 转码和解码按 EXIF 纠正方向，宽高可能因此对调。重新编码不保证保留 EXIF、ICC、文本、动画时间等元数据，不做ICC色彩管理转换；有专业色彩要求须先处理色彩空间。
- 同格式提取与同格式字节保存不改动文件，因此原元数据、动画、编码质量、交错状态全部保留。
- 本地能编码不表示服务商能接收该格式。发送远程视觉模型通常优先使用 JPEG / PNG，服务商的格式、文件大小与图片数量限制仍须遵守。

## 批次、列表和动图

编码节点按张量批次顺序，每张输出一个字节项；这是 ComfyUI 执行列表，不是一个 ARRAY 或拼接后的二进制文件。下游普通图片口可能逐项调用。需要所有图片合在一次请求时，接 Harness 的“列表合并图片”口。

解码、转码、跨格式提取会将动画或多页图逐帧输出，每项一个文件或批次为1的张量，保留帧顺序，不保留播放时序。不同尺寸无需拼成同一个批次。同格式提取保留一个完整原文件，不拆帧。

保存节点把每份 `IMAGE_BYTES` 当一个完整文件：同格式直接写入；多帧文件跨格式保存会报错，需先用转码或解码节点明确拆帧。预览显示首帧，不能把预览张数当动画帧数。

## 典型连接

```text
从路径加载图片 → 图像张量编码为图像字节（JPEG，质量95，4:4:4）
             → LLM 远程回复 的列表合并图片
```

已有 JPEG 文件无需解码：`从路径加载字节数据 → 字节数据提取图像字节（JPEG） → API图片编辑`。本节点组不调用远程接口；API费用、网络上传和超时由 API 节点负责。Base64仍会使请求体约增大三分之一，字节透传解决的是重复图片编码问题。

## 缓存与限制

转换节点使用 ComfyUI 正常缓存；加载节点根据文件内容变化失效；保存预览缓存按字节内容识别变化。字节值驻留内存，多图大文件会增加内存占用；工作流 JSON 记录路径和参数，不嵌入这些运行时文件内容。

无效、截断、空图片会报错，不只检查文件头。任意字节加载器允许空文件，但图片提取不允许。某格式的编解码器不可用、超出格式尺寸限制、文件权限不足时会显示对应错误。
