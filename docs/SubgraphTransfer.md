# 嵌套子图封装时保留内部连线

选中已有子图节点，再与其他节点一起封装成更大的子图时，内部节点、连线及控件状态应随原子图保留。本扩展修正当前原生前端在这个移动过程中提前清理子图定义的问题，无需添加节点或额外操作。

## 问题与触发条件

原生封装流程先复制所选节点的序列化数据，再删除原位置的节点，最后在新子图中创建替代节点。如果被移动的子图没有其他存活实例，原生删除流程会把它判断为无人引用的子图，清理其内部连线、节点存储和生命周期状态。

后续创建外部替代节点时，原先的子图对象仍可能被引用，导致内部节点看起来还在，但连线已经全部消失。边界端口甚至可能保留旧 `linkIds`，而子图的 `links` 已为空。

这个问题与连线是否交叉、端口显示排序或多行文本框高度无关。只有部分子图出现，是因为子图是否还有其他实例，会影响原生清理判断。

## 修复后的行为

| 操作 | 行为 |
| --- | --- |
| 将已有子图节点再封装一层 | 移动时保留子图定义及内部状态，原连接继续存在 |
| 框选多个子图与普通节点一起封装 | 各子图分别保留自己的内部连线 |
| 选择包含子图节点的分组后封装 | 对分组内实际被移动的子图节点采用相同规则 |
| 更深的嵌套子图 | 保留被移动子图及其后代定义 |
| 正常删除节点 | 继续使用原生删除和无人引用定义的清理行为 |
| 删除同一定义的部分实例 | 原生引用判断仍生效，其他实例继续使用该定义 |

修复限定在原生封装过程的节点转移阶段。原位置的宿主节点仍正常断开外部连线、释放自身控件并执行移除回调；仅跳过不该发生的子图定义清理。不会加入临时画布节点、运行时变量或额外执行依赖。

## 使用与已有损坏数据

更新后先保存需要保留的编辑状态，再刷新页面加载扩展，随后按原来的方式封装子图。前端脚本由 liuxinyu 包加载，不需要重启后端。

本修复防止后续封装再次丢线，**不会猜测或自动补回已经被清空的连线**。已有损坏工作流应从完整备份恢复明确的连接，并核对当前节点与端口；不能仅凭残留的边界 `linkIds` 推测整张子图。

## 开发与验证

实现位于 [`subgraph_transfer.js`](../subgraph_transfer.js)，通过包的现有前端扩展注册机制安装到 LiteGraph。适配原生 `_convertToSubgraphImpl` 与 `removeNode`：封装期间标记实际移动的选择集，仅在对应宿主移除时跳过子图定义清理分支，并在 `finally` 中恢复方法与转移状态。普通删除不改变。

命令行测试从当前安装的前端 bundle 提取原生封装、删除及子图存活引用判断方法，模拟外围图形设施与存储清理接口，无需操作用户画布：

```powershell
node tests/test_subgraph_transfer.cjs <当前前端 settingStore-*.js 的完整路径>
```

测试首先不加载自定义扩展，复现两个独占子图的 `22 / 31 → 0 / 0` 条连线；保留第一个子图的额外实例时，对照结果为 `22 / 31 → 22 / 0`。加载修复后，两者均保持 `22 / 31`；另检查分组封装、深层嵌套、原宿主移除回调、正常删除、重复安装和异常后的状态恢复。测试不等同于完整浏览器端到端验收；页面中的实际封装操作仍需刷新后核对。
