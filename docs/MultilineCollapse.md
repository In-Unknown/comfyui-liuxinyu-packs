# 多行文本输入连接后收起

多行文本输入接到上游后，编辑框收起，节点自动缩短，原位置只保留一行带名称的端口。断开该输入后恢复编辑框及原有文字。这样可以去掉提示词、表达式、模板和错误信息编辑框隐藏后留下的大块空白。

这是 liuxinyu 包的前端功能，无需添加节点或执行工作流。适用于经典画布中的本包多行文本输入，也覆盖同时安装的 `comfyui-llm_harness_engineering` 节点和子图提升到外部的多行文本输入。

## 输入与输出

本功能没有新增参数或执行输出，仅调整已有控件和端口的布局。

| 对象 | 行为 | 数据类型 |
| --- | --- | --- |
| 已有多行文本输入 | 只检查该文本框对应的输入是否连接；连接后使用上游数据，未连接时仍使用框内文字 | STRING |
| 原有输出 | 保留节点本身的返回内容、顺序及完整数组／执行列表语义 | 按原节点定义 |
| 保存的文本 | 收起时仍保留，断开后可继续编辑；不将上游值写回原文本 | STRING |

## 使用示例

以“LLM 远程回复”的用户提示词和系统提示词为例：

1. 在两个文本框中分别填写原始提示词。
2. 将上游文本接入用户提示词。用户提示词编辑框收起，只保留对应端口行；系统提示词仍可编辑。
3. 再连接系统提示词。第二个编辑框也收起，后面的参数控件上移，节点高度自动收紧。
4. 断开用户提示词。该编辑框恢复，显示第 1 步填写的文字；系统提示词仍保持连接和收起状态。

“布尔条件返回”的报错信息、“从模板生成文本”的模板、JSON 校验的文本与字段配置等遵循同一规则。例如只连接模板节点的 `t1`，不会收起“模板”编辑框；必须连接“模板”本身才收起。

## 端口行、文本框与节点高度

- 收起的是多行编辑区域，不删除输入口。端口的名称、圆点、命中区域和连线仍可使用，连接索引不变。
- 普通多行输入收起后保留一行正常端口高度，后续控件上移；不再沿用编辑框原先的纵坐标。
- 连接或断开时，按当前可见控件所需的最小高度重新调整节点，宽度保持不变。其他尚未连接的文本框可能恢复到其默认最小高度。
- 状态没有改变时，不持续压缩用户手动扩大的节点；反复布局不会累积增高。
- 重新加载已连接的工作流时，会收紧旧文件中留下的编辑框空白；未连接的编辑框若高度不足，则恢复到可编辑的尺寸。
- “动态多块多行字符串”已有专门的标题／端口行，收起文本区域时沿用该行，不再添加第二行。后续动态增加的文本块也适用。

## 子图和端口排序

将内部多行文本输入提升到子图外部后，外部输入是否连接，决定外部编辑框是否收起。内部端口的连线状态和外部端口各自判断，不把其他端口的连接状态套用过来。

子图加载、重新生成提升控件、重命名或调整端口顺序后，按当前输入与控件的对应关系重新识别，不依赖旧数组索引或旧控件对象。嵌套子图采用相同规则。

与[端口显示排序](PortOrder.md)组合使用时，已连接的多行输入作为一行端口参与 ↑ / ↓ 交换；断开后，恢复的编辑框仍跟随该端口所在行。图的实际输入输出数组、连线身份、控件值和子图内外顺序同步机制保持原样。

## 范围与常见问题

| 现象 | 说明或处理方法 |
| --- | --- |
| 连接后仍有一行高度 | 这一行用于显示端口名称和连接圆点，不是残留编辑框 |
| 连接了别的端口，文本框没收起 | 正常；只在该文本框自己的输入连接时收起 |
| 收起后找不到原文字 | 断开该输入即可重新编辑；原文字没有清空 |
| 子图外部有同名文本框 | 按实际端口绑定判断，不按显示名称猜测来源 |
| harness 节点没有自动收起 | 此功能由 liuxinyu 前端提供，需要安装并启用 liuxinyu 扩展；更新后刷新页面 |
| Note 或预览面板没有缩小 | 它们不是与输入口绑定的多行文本编辑框，不在本功能范围内 |
| 排序后的节点刷新时变高 | 排序布局会先同步原生端口缓存，再计算弹性文本框空间，避免加载时重复增加端口高度。旧版已经保存的较大尺寸可缩回后重新保存 |
| 其他插件节点没有变化 | 普通节点范围限定为 liuxinyu、RunCmd 与 harness；子图提升的多行输入单独支持 |

当前适配经典画布；Vue Nodes / Nodes 2.0 模式不应用该收起布局。没有对应输入口的多行控件不处理。这里只调整显示，不更改模型请求、执行结果、文本内容或工作流业务连线。

## 开发与验证

实现位于 [`multiline_collapse.js`](../multiline_collapse.js)，沿用本包前端扩展加载方式。无需修改 Python 节点、重启后端或重新保存业务连线；更新后先保存正在编辑的工作流，再刷新页面。

```powershell
node tests/test_multiline_collapse.cjs
node tests/test_dynamic_multiline.cjs
node tests/test_port_order.cjs <当前前端 settingStore-*.js 的完整路径>
```

测试覆盖单独与同时连接多个文本输入、断线恢复、原文字保留、加载已连接工作流、动态端口重排和新增、提升控件替换、旧版尺寸接口，以及原有回调保留。组合测试直接使用安装版本的原生控件布局与最小尺寸计算，验证端口排序扩展的两种加载顺序、liuxinyu／harness／子图控件、端口名称绘制及连续布局 100 次尺寸稳定。页面视觉效果由用户刷新后验收。
