# 从路径加载图像批次

从图片路径加载一个同尺寸的图片批次，输出 IMAGE。适合将一组图片统一尺寸后送给其他节点。

## 路径支持哪些形式

- 单张图片：如 `D:\素材\01.jpg`。
- 一个目录：会递归扫描其子目录，查找支持的图片。
- 多个文件的单行 CSV：每个路径用双引号包裹，用英文逗号分隔，例如 `"D:\素材\01.jpg","D:\素材\02.jpg"`。不要用 JSON 方括号。

多文件 CSV 中不允许夹入目录。目录扫描按相对路径字符串排序，并非数字自然排序；想让10排在2后面，可给文件名补零，如01、02、10。

## 尺寸如何确定

| 目标宽度 | 目标高度 | 行为 |
| --- | --- | --- |
| 0 | 0 | 要求所有图片宽高比完全一致，统一到像素最多图片的尺寸 |
| 大于0 | 0 | 以第一张图比例计算高度，全部图片统一成这个尺寸 |
| 0 | 大于0 | 以第一张图比例计算宽度，全部图片统一成这个尺寸 |
| 大于0 | 大于0 | 全部直接缩放到指定宽高，比例不一致时会拉伸 |

“批次”要求所有图片尺寸相同。一次加载一个目录时，只指定宽度并不意味着每张图保留自己的不同高度。

## 详情页图片长短不一时怎样加载

用“从目录中匹配路径或目录”先输出每张图片路径的执行列表，再连接本节点，设宽790、高0。这样本节点逐路径运行，每次只有一张图，能按各自比例得到不同高度；下游收到的是多个独立图片批次的执行列表，可交给“从批次列表拼接图片”。

多个详情页需要各自拼接时，把上述匹配、加载、拼接放进分包子流，否则图片可能被统一合并。

## 输出与注意事项

会按 EXIF 修正方向，转换成 RGB；不保留透明通道。动图和多页图片只加载第一帧。不裁剪、不补边，改变尺寸使用 LANCZOS 缩放。

空目录、损坏图片、路径不存在会报错。宽高为0且比例不一致时也报错，可改为逐文件加载或明确统一宽高。选图阶段的预览不一定代表连接上游尺寸后最终输出的尺寸，最终以执行结果为准。
