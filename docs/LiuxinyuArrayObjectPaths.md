# 可遍历字典的索引列表

按配置遍历对象字段和数组元素，列出每条遍历分支停止位置的索引路径，同时输出完整数组和逐项执行列表。适合读取记录、定位字段、展开某一层数据，或为批量处理提供位置清单。

节点 ID 仍为 `LiuxinyuArrayObjectPaths`，保留原工作流的节点身份；分类：`liuxinyu/结构化数据`。这里的“索引”是相对于输入数据根位置的访问路径，例如 `[0][1]`、`["items"][0]`，不是业务 ID 或文件路径。

## 输入

| 参数 | 描述 | 数据类型 | 必需 |
| --- | --- | --- | --- |
| `完整数据`（`content`） | 遍历起点，接原生对象或数组；JSON 文本应先解析 | DICT / ARRAY | 是 |
| `嵌套读取层数`（`depth`） | 默认 `-1`，表示遍历所有可继续读取的层；正整数最多向下读取对应层数，提前到底则停止 | INT | 是 |
| `遍历字段`（`include_fields`） | 默认 false；开启后进入对象各字段，关闭时将整个对象作为停止位置 | BOOLEAN | 是 |
| `遍历数组`（`include_arrays`） | 默认 true；开启后进入数组各元素，关闭时将整个数组作为停止位置 | BOOLEAN | 是 |

层数只接受 `-1` 或正整数。`0` 不表示无限，也不表示根位置；要直接得到根位置，可同时关闭两个遍历开关。

## 输出

| 输出名称 | 描述 | 数据类型 |
| --- | --- | --- |
| `索引数组` | 全部路径组成的一个完整数组，交给需要一次处理整份位置清单的节点 | ARRAY |
| `索引执行列表` | 相同路径按顺序逐项输出，让普通下游按路径分别执行 | STRING 执行列表 |

两个输出内容和顺序相同，区别在于 ComfyUI 的执行方式。完整数组 `["[0]","[1]"]` 是一个值；执行列表则是 `"[0]"`、`"[1]"` 两个执行项。没有索引时，前者仍输出一个 `[]`，后者包含零个执行项。详见[数组与执行列表](DataLists.md)。

## 层数怎样计算

根输入为第 0 层。每读取一个对象字段或一个数组元素，都向下增加 1 层。

- 层数为正整数时，走到该层就输出当前位置，不继续展开其内容。
- 遇到数字、文本、布尔值或 null 时，已经到底，直接输出当前位置。
- 遇到关闭了对应遍历开关的对象或数组时，把这个容器整体作为停止位置。
- 开启遍历的空对象或空数组没有成员，不产生索引；若该容器因层数限制或开关关闭而没有被展开，则输出它自身的位置。

只输出各分支停止处的路径，不同时列出沿途的所有父容器。数组按下标顺序，对象按字段原顺序，逐分支向下遍历。不修改输入，不按内容去重。

## 示例一：默认只展开数组

输入：

```json
[
  [{"id":"A"},{"id":"B"}],
  [],
  [[{"id":"C"}]]
]
```

使用默认设置：层数 `-1`、遍历字段 false、遍历数组 true。索引数组输出：

```json
["[0][0]","[0][1]","[2][0][0]"]
```

遇到每条对象记录便停下，不进入 `id` 字段。空数组不产生路径，也不改变其他路径的下标。默认行为仍适用于按对象记录处理的工作流。

若把层数改成 `1`，输出 `["[0]","[1]","[2]"]`，对应第一层的三个完整数组，其中包括尚未展开的空数组。

## 示例二：对象字段、数组与提前到底

输入：

```json
{"items":[{"score":2},{"score":3}],"enabled":false}
```

| 层数 | 遍历字段 | 遍历数组 | 索引数组 |
| --- | --- | --- | --- |
| -1 | false | true | `[""]`，根对象整体 |
| 1 | true | true | `["[\"items\"]","[\"enabled\"]"]` |
| 2 | true | true | `["[\"items\"][0]","[\"items\"][1]","[\"enabled\"]"]` |
| -1 | true | true | `["[\"items\"][0][\"score\"]","[\"items\"][1][\"score\"]","[\"enabled\"]"]` |
| -1 | true | false | `["[\"items\"]","[\"enabled\"]"]`，数组不展开 |
| -1 | false | false | `[""]`，根输入整体 |

`enabled` 在第 1 层就到底，即使层数设为 2 或更大，也只产生一次对应路径。

对象字段统一用带引号的方括号表示，字段名含点号、中文、引号或空字符串时仍能准确读取。表格中反斜杠是 JSON 字符串的转义；实际单条路径是 `["items"][0]` 这样的文本。

## 怎样接到其他节点

- `索引执行列表`接[使用js点符号语句读取对象](LiuxinyuReadJSObjectPath.md)的读取语句，完整数据连接同一份输入，可逐个读取位置。
- 需要汇总“路径 → 原值”字典时，将同一条索引执行列表与读取结果接“组装键值对”的键和值，再收集为数组并接[并和数组中的字典字段为字典](LiuxinyuMergeDictionaryArray.md)。索引可能为空时，先用条件分支跳过逐项读取，直接传空字典数组给合并节点。
- 索引数组可接[组装键值对](LiuxinyuBuildKeyValuePairs.md)的“键”，为每个位置关联同一个完整值。组装节点把路径当作普通键名。
- 索引数组先经“将任意数组转为执行列表”，再接[分包跳回](LiuxinyuPacketReturnStart.md)的待分包输入，配合单次读取或插入逐个处理。向字典插入字段时，索引应停在字典上；若已经展开到数字、文本等字段值，就不是合法插入目标。完整覆盖规则由工作流在循环前检查。

路径始终相对于本节点的输入。如果先从外层对象取出 `items` 再遍历，产生的 `[0]` 相对于取出的数组，不能直接用于外层对象。生成路径后若重排或删除数组成员，应重新生成索引。

## 边界与报错

原生输入只能是对象或数组，但遍历可以抵达任意类型的成员。对象字段开启遍历时要求键名为字符串；不会把数字键强行改为另一种键。遇到仍需继续展开的循环引用时报错；到达指定层数后不再访问其内部。

层数无效、输入根类型错误或遍历结构不受支持时，节点报错。它不验证业务字段、不判断对象应属于哪一组；输出位置能否用于后续操作，由接收节点的数据要求决定。
