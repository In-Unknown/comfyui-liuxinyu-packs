# 当前忽略内存检查和回收

等待所有已连接输入完成后，暂停**当前工作流这一次运行任务**在每个调度步骤后的 RAM 内存检查及对应缓存回收。状态作用于该任务之后执行的所有分支、循环和子图。

## 输入

| 参数 | 描述 | 数据类型 | 必需 |
| --- | --- | --- | --- |
| `输入 1`、`输入 2`…… | 等待完成并原样传递的数据，类型跟随对应输入；端口随连接增加，无固定数量上限 | ANY | 否（至少连接一项以确定执行顺序） |

## 输出

| 输出名称 | 描述 | 数据类型 |
| --- | --- | --- |
| `输出 1`、`输出 2`…… | 与同编号输入一一对应原样传递，不深拷贝、不拆数组、不补齐不同长度；执行列表，下游逐项处理 | ANY |

```text
初始数据 → 当前忽略内存检查和回收 → 跳回点 → 循环体 → 条件回归 → 恢复内存检查和回收 → 预览
```

- 没有开关、参数或其他配置；至少连接一项输入来确定执行顺序。
- 输入 1 对应输出 1，以此类推。连接后增加下一对空口，类型分别跟随对应输入，不设固定数量上限。
- 数字、字符串、数组、字典、图片批次以及执行列表均原样传递，不深拷贝、不拆数组、不把不同长度的执行列表补齐。
- 重复执行本节点仍为暂停；任意一次执行“恢复内存检查和回收”即恢复，不使用嵌套计数。
- 未连接恢复节点时持续到本任务结束。任务结束、报错或取消后不会影响下一任务；再次运行同一工作流也默认开启检查。
- 只暂停执行器调度步骤后的 RAM 检查和对应回收。模型加载、显存管理、内存分配失败处理和模型分配过程中的回收继续正常工作。长时间积累大数据时应接恢复节点。
- 独立分支的执行顺序由依赖决定；需要处在暂停区间的分支，应通过此节点的输出连接。

需要本地核心配套的动态端口及任务内存控制接口。节点 ID：`LiuxinyuIgnoreMemoryChecks`。
