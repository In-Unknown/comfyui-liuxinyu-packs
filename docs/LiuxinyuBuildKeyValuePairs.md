# 组装键值对

把已经准备好的键和值组装成一个新字典。例如键为 `owner`、值为字符串 `Alice`，输出 `{"owner":"Alice"}`。键也可以是一组字符串，每个键对应同一个完整值。

节点 ID：`LiuxinyuBuildKeyValuePairs`；分类：`liuxinyu/结构化数据`。适合构造配置项、命名数据、编号到内容的映射，或者为后续插入准备字段对象。输入可来自手动填写、文件、接口或其他节点，没有固定的业务字段或上游格式要求。

## 什么时候使用

| 你现在需要做什么 | 选择 |
| --- | --- |
| 已经有键和值，需要得到一个新字典 | 使用本节点 |
| 多个名称需要指向同一份完整内容 | 将名称数组接入“键”，内容接入“值” |
| 从已有对象中提取某个字段 | 先用[使用js点符号语句读取对象](LiuxinyuReadJSObjectPath.md)，再把读取结果接进本节点 |
| 把构造好的字段加入原对象 | 将本节点输出接[插入字段到字典或者js对象](LiuxinyuInsertJSObject.md)的新增值 |
| 对完整数据中的多个对象增加字段 | 分别提供目标路径和字段对象，用[分包跳回](LiuxinyuPacketReturnStart.md)配合单次插入，携带完整结果逐次更新 |
| 覆盖已有字段、递归合并字典、删除字段 | 本节点只创建新字典，不执行这些修改 |

## 输入

| 参数 | 描述 | 数据类型 | 必需 |
| --- | --- | --- | --- |
| `键`（`key`） | 单个字符串，或不含重复项的字符串数组；文本框默认 `key`，也可以连接上游结果 | STRING / ARRAY | 是 |
| `值`（`value`） | 每个键对应的完整值；保留原始类型，需要连接上游输入 | ANY | 是 |

“键”的文本框填写键名本身，例如 `owner`，不用加 JSON 引号。要提供多个键，应连接原生字符串数组，例如解析后的 `["A","B"]`；直接在文本框中填写这段文字，只会得到一个字面名称为 `["A","B"]` 的键。

“值”可以是文本、数字、布尔值、null、字典、数组，也可以是图片、Latent 等原生值。端口中的 null 是一个实际输入值，不等于没有连接。节点不把 JSON 文本自动转换成对象；要存入对象，先解析文本再连接。

## 输出

| 输出名称 | 描述 | 数据类型 |
| --- | --- | --- |
| `字典` | 本次新建的字典，按键的输入顺序排列；整体输出，不自动拆成执行列表 | DICT |

本节点没有“原始容器”输入，也不会把结果自动塞回某个位置。输出中的值仍是提供给它的完整值，不会从中提取字段、增加业务字段或删除内容。

## 单个键：值是什么，就装入什么

以下表格中的 JSON 用于展示实际数据类型，不表示所有输入都应填写为文本。

| 键 | 值 | 输出 |
| --- | --- | --- |
| `owner` | 字符串 `Alice` | `{"owner":"Alice"}` |
| `score` | 数字 `0` | `{"score":0}` |
| `enabled` | 布尔值 `false` | `{"enabled":false}` |
| `note` | null | `{"note":null}` |
| `tags` | 数组 `["x","y"]` | `{"tags":["x","y"]}` |
| `A` | 对象 `{"owner":"Alice"}` | `{"A":{"owner":"Alice"}}` |

如果值是字符串 `{"owner":"Alice"}`，结果保存的是这段字符串，显示为 `{"A":"{\"owner\":\"Alice\"}"}`；它与上表最后一行的嵌套对象不同。

## 多个键：各键使用同一个完整值

“键”连接原生数组：

```json
["A","B"]
```

“值”连接原生对象：

```json
{"enabled":true,"tags":["x","y"]}
```

输出：

```json
{
  "A":{"enabled":true,"tags":["x","y"]},
  "B":{"enabled":true,"tags":["x","y"]}
}
```

这条规则与值的类型无关。键为 `["A","B"]`、值为 `[10,20]` 时，输出 `{"A":[10,20],"B":[10,20]}`，不会按下标配成 `{"A":10,"B":20}`。需要不同的值时，先把每一项的键和值分别读出，逐项组装；不要把两个完整数组误当成执行列表。

## 跟着接：分别读取键和值

已有对象：

```json
{"name":"shipping","payload":{"days":3,"enabled":true},"note":"无需复制"}
```

1. 对象接第一个“使用js点符号语句读取对象”，读取语句填 `name`，输出字符串 `shipping`。
2. 同一对象接第二个读取节点，读取语句填 `payload`，输出完整对象 `{"days":3,"enabled":true}`。
3. 两个读取结果分别接“组装键值对”的“键”和“值”。

输出：

```json
{"shipping":{"days":3,"enabled":true}}
```

`note` 没有进入输出，是因为上游只读取了 `payload`；本节点不负责判断要保留哪些原字段。若将整个原对象接入“值”，整个对象都会被保留。

## 组装与插入分开连接

假设有一条分配记录：

```json
{"owner":"Alice","paths":["[0]","[2]"]}
```

1. 读取 `owner`，将结果接第一个组装节点的“值”，“键”填 `owner`，得到 `{"owner":"Alice"}`。
2. 读取 `paths`，接第二个组装节点的“键”；第一个组装节点的输出接第二个的“值”。
3. 第二个节点输出如下新字典：

```json
{"[0]":{"owner":"Alice"},"[2]":{"owner":"Alice"}}
```

这里 `[0]` 和 `[2]` 只是字符串键。本节点不查找这些位置，也不验证它们是否存在。若要写回，把路径和对应字段分别读取出来，接单次插入节点；多次修改时用分包跳回携带完整结果。完整示例见[记录数组与路径字段处理](ObjectRecordTools.md)。

## 完整数组与执行列表

| 输入情况 | 行为 |
| --- | --- |
| “键”收到一个完整字符串数组 | 一次组装包含这些键的字典，各键使用同一个完整值 |
| “值”收到一个完整数组 | 将这个数组整体保存为值 |
| 上游提供多个 ComfyUI 执行项 | 每次分别组装，得到多个字典执行项；不会自动合并成一个字典 |
| 需要一次传递这些字典 | 接[执行列表收集为数组](LiuxinyuCollectExecutionList.md)，得到字典数组 |

例如把 `[{"name":"A","score":10},{"name":"B","score":20}]` 接[将任意数组转为执行列表](LiuxinyuArrayToExecutionList.md)，再用两个读取节点分别读取 `name` 和 `score`，连接本节点后得到两个执行项 `{"A":10}`、`{"B":20}`。收集后是 `[{"A":10},{"B":20}]`；需要继续得到 `{"A":10,"B":20}` 时，再接[并和数组中的字典字段为字典](LiuxinyuMergeDictionaryArray.md)。

执行项的配对遵循 ComfyUI 的普通调度规则：两路按位置配对，较短的非空输入会重复最后一项。因此两路最好来自同一批记录，且中间没有独立过滤或排序；一个固定键配合多个值是有效用法。不要用长度不同的独立执行列表表示严格的一一对应关系。详见[数组、执行列表与图片批次](DataLists.md)。

零个执行项与“一个内容为空的数组”不同。记录数组可能为空时，应在逐项处理分支外判断并直接返回空方案；不要让固定读取语句或固定键与零个执行项配对，否则 ComfyUI 可能在调用节点前因空列表取值而报错。完整空键数组 `[]` 作为一次输入则正常输出 `{}`。

## 空值、特殊键与重复键

| 情况 | 行为 |
| --- | --- |
| 键为空字符串 `""` | 产生一个空名称的键，例如 `{"":0}` |
| 键数组为 `[]` | 输出空字典 `{}`；与空字符串键不同 |
| 值为 `""`、`[]`、`{}`、false、0 或 null | 完整保留，不当作缺失值 |
| 键包含点号、方括号、空格、引号或换行 | 按原文作为一个键，不去空格、不解释为访问路径 |
| 键数组中同一个字符串出现两次 | 报错，不静默覆盖或去重 |
| 两次独立执行使用相同键 | 各自产生新字典；节点没有跨执行的全局去重状态 |
| 键为数字、布尔值、对象或含非字符串的数组 | 报错；需要这些名称时先明确转换成字符串 |

字符串按原文比较，大小写不同或空格不同的键分别保留。键为 `a.b` 输出 `{"a.b":值}`，不是 `{"a":{"b":值}}`。

## 输入保护与适用边界

每次创建新的外层字典，不修改键数组或输入值。内部值保留引用，不深拷贝图片、模型、张量或嵌套容器；多个键使用同一对象时会指向同一份值。下游若需要修改值，应使用不原地修改输入的节点，或自行复制。

本节点不检查值是否能序列化为 JSON。保存文本前，应确认值只含目标格式支持的类型；图片或模型能够装入字典，并不意味着它们能直接转换为 JSON。

旧的“按引用展开字段赋值”已移除。旧工作流需要拆成读取和组装连接，原有的分组唯一性、路径覆盖等规则应留在工作流校验环节；本节点没有引用字段、提取字段或分组配置。
