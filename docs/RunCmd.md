# 运行cmd命令

在独立的控制台进程中执行一条或多条 cmd 命令，捕获并返回该命令从开始执行到结束期间的全部输出。

## 输入

| 字段 | 描述 | 数据类型 |
| --- | --- | --- |
| `command` | 要执行的命令，支持多行。 | `STRING`（多行） |
| `timeout` | 最长等待秒数。`0` 表示无限等待，直到命令自行结束。范围 0–3600。 | `INT` |
| `kill_on_timeout` | 仅在超时生效时起作用。为真时强制结束整个进程树（含子进程）；为假时立即返回已有输出，命令在后台继续运行。 | `BOOLEAN` |

## 输出

| 字段 | 描述 | 数据类型 |
| --- | --- | --- |
| `输出` | 命令执行期间产生的全部标准输出与标准错误，合并为一段文本。 | `STRING` |

## 执行方式

- 节点实际执行时启动独立控制台进程，不会复用之前的终端；输入不变时可能命中 ComfyUI 缓存，不保证每次点击运行都再次执行命令。
- 无论单行还是多行，命令都会先写入一个临时 `.bat` 文件再执行。临时文件以 UTF-8 无 BOM 写入，开头自动加 `@echo off` 和 `chcp 65001 >nul`，执行完自动删除。
- 因此多行命令中的变量、`if`、`for` 等控制流正常工作，等价于在 cmd 里逐行输入。
- 输出按 UTF-8 解码，中文不会乱码；`@echo off` 保证输出里不带命令回显。

## 超时行为

| 情况 | 结果 |
| --- | --- |
| 命令在 `timeout` 秒内结束 | 返回完整输出 |
| 超时，`kill_on_timeout = true` | 执行 `taskkill /F /T` 结束整个进程树，返回超时前已产生的输出，并尽量追加终止前最后一段输出 |
| 超时，`kill_on_timeout = false` | 立即返回超时前已产生的输出，命令继续在后台运行；后台线程会继续读取管道，避免管道写满导致子进程卡死 |
| `timeout = 0` | 不设超时，一直等到命令自己结束 |

## 使用示例

- 单行：`echo Hello`，timeout 10 → 返回 `Hello`。
- 多行：`set FOO=测试` 换行 `echo %FOO%` → 返回 `测试`。
- 长任务加超时：`ping 127.0.0.1 -n 60`，timeout 5，kill 开 → 约 5 秒后返回已产生的输出，进程被结束。
- 后台继续跑：同样的命令，kill 关 → 5 秒后立即返回已有输出，ping 继续跑到结束。

## 注意事项

- **输出不是流式的**。节点要等命令结束（或超时）才一次性返回，执行期间看不到中间输出。长任务请用进度条或日志文件判断状态。
- **会弹出独立控制台窗口**。每次运行都会新开一个 cmd 窗口，这是有意设计，方便直接观察命令执行过程；命令结束后窗口随之关闭。
- **子进程工作目录继承启动 ComfyUI 时的工作目录**，不保证是节点目录或 ComfyUI 源码目录。需要指定目录时，命令里显式使用 `cd /d "D:\目标目录"`，再在下一行写命令。可先执行 `cd` 查看当前目录。
- **`kill_on_timeout = false` 时进程不会被清理**。如果命令是无限循环，它会一直在后台运行，需要手动结束。
- 返回内容包含标准错误，失败时也能看到错误信息；节点本身不因命令返回非零退出码而报错。
