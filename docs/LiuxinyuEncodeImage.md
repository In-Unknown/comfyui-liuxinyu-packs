# 图像张量编码为图像字节

把普通 ComfyUI 图像或图像批次编码为文件字节。适合在远程图片输入前控制 JPEG 质量、使用无损格式或保留透明度；不保存到磁盘，也不缩小图片。

## 输入

| 参数 | 描述 | 数据类型 | 必需 |
| --- | --- | --- | --- |
| `图像` | 非空 `[B,H,W,C]` 张量，C为1、3或4；批次逐张编码，执行列表逐项处理 | IMAGE | 是 |
| `透明遮罩` | 可选 `[H,W]` 或 `[B,H,W]`；1透明、0不透明，尺寸与图像一致；数量1广播，或与图像批次相等；覆盖原Alpha | MASK | 否 |

格式与所属参数如下。界面按图像、图像格式及其参数、透明遮罩排列。

| 参数 | 描述 | 数据类型 | 必需 |
| --- | --- | --- | --- |
| `图像格式` | 默认 PNG；PNG、JPEG、WEBP、BMP、TIFF、GIF，以及 Pillow 支持时出现的 AVIF | COMFY_DYNAMICCOMBO_V3 | 是 |
| `压缩等级`（PNG） | 0～9，默认6；只影响体积和编码时间，不改变像素 | INT | 选择PNG时 |
| `交错扫描`（PNG） | 默认关闭；开启写入 Adam7 交错 PNG，影响逐步显示，不控制透明 | BOOLEAN | 选择PNG时 |
| `质量`（JPEG / WEBP / AVIF） | 1～100，默认95；JPEG/有损WEBP/AVIF一般越高越精细且越大；WEBP无损时影响压缩努力程度 | INT | 选择对应格式时 |
| `色度采样`（JPEG） | 4:4:4、4:2:2、4:2:0；默认4:4:4保留更多彩色边缘细节 | COMBO | 选择JPEG时 |
| `渐进式`（JPEG） | 默认关闭；开启后逐步显示整图，不恢复有损丢失的细节 | BOOLEAN | 选择JPEG时 |
| `优化编码`（JPEG） | 默认开启；优化编码表，可能增加编码耗时 | BOOLEAN | 选择JPEG时 |
| `无损`（WEBP） | 默认关闭；开启使用无损像素压缩，保留透明像素的RGB | BOOLEAN | 选择WEBP时 |
| `压缩力度`（WEBP） | 0～6，默认4；越高通常压缩更慢、更充分 | INT | 选择WEBP时 |
| `压缩方式`（TIFF） | 无压缩、LZW、Deflate，默认Deflate；均为无损编码 | COMBO | 选择TIFF时 |
| `颜色数`（GIF） | 2～256，默认256；保留Alpha时留一个调色板索引用于透明 | INT | 选择GIF时 |
| `抖动`（GIF） | 默认开启；用误差扩散改善有限颜色的渐变，可能呈现颗粒感 | BOOLEAN | 选择GIF时 |
| `编码速度`（AVIF） | 0～10，默认6；越大通常编码越快、压缩效率越低 | INT | 选择AVIF时 |
| `保留透明度`（PNG / WEBP / TIFF / GIF / AVIF） | 默认开启；有Alpha时保留。GIF只能全透明或不透明，Alpha小于128的像素转为全透明 | BOOLEAN | 选择对应格式时 |
| `去透明背景`（全部格式） | 白色、黑色，默认白色；仅在目标不支持透明或关闭保留透明度时合成背景 | COMBO | 是 |

## 输出

| 输出名称 | 描述 | 数据类型 |
| --- | --- | --- |
| `图像字节` | 每张图一个完整编码文件，按批次顺序输出执行列表；单图也输出一项 | IMAGE_BYTES |

## 怎么用

1. 添加“从路径加载图片”，选择 `C:\images\product.png`。
2. 将它的“图片”接到本节点“图像”，图像格式选 JPEG，质量95，色度采样4:4:4。
3. “图像字节”接“保存图像到绝对路径”的“图片”，文件夹填 `C:\images\encoded`，文件名填 `product.jpg`。
4. 执行后得到 JPEG 文件，尺寸与输入一致。也可把字节口直接接 Harness 的 LLM 远程回复或 API图片编辑。

需要多张图一起请求时，使用 Harness 的“列表合并图片”口；普通图片口接执行列表可能产生多次请求。

## 透明度与精度

PNG交错与Alpha独立。透明区域变白使用“保留透明度=关闭、去透明背景=白色”；JPEG/BMP不支持本节点的透明输出，因此总会合成背景。上游将透明度单独输出为MASK时，记得连接“透明遮罩”；仅RGB不会自动恢复透明。

张量限幅0～1并按最近整数转为8位；NaN、无穷大、空图及不合法遮罩报错。PNG压缩等级不降低像素质量，JPEG质量100也不是无损。更完整的[格式差异和透明示例](ImageBytes.md)适用于本节点。

## 批次与缓存

两张输入得到两个字节项，不拼文件、不合并成ARRAY。转换结果使用ComfyUI缓存，参数或输入变化后重新编码；文件不会自动持久化，须另接保存节点。

## 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 透明区变白 | 检查Alpha开关、目标格式及MASK连线；交错不会改变透明度 |
| 选不了AVIF | 当前Pillow需要具备AVIF支持；不可用时不显示选项 |
| 下游不接受字节 | 使用支持IMAGE_BYTES的口；普通图像处理需先解码 |
| 文件大小没有达到预期 | 质量不等于目标字节数，尺寸和内容也影响体积；节点不自动缩放 |
