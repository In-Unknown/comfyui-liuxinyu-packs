# JSON Schema填写模版

输入 JSON Schema Draft 2020-12 字符串，运行时在节点画布中生成可填写的字段。用户确认、后端校验通过后输出完整 JSON 值。已确认值在字段结构不变且仍满足当前规则时自动复用，不再等待。

节点 ID：`LiuxinyuTemplateForm`；分类：`liuxinyu/结构化数据`。适合结构化参数、配置、记录及列表的人工填写，不硬编码业务字段。

**节点本身不显示 Schema 源码编辑框。** 表单是 `node.widgets` 中的画布复合控件，内部按属性树统一测量、排列、绘制和命中；不是盖在节点表面的独立 HTML 页面。采用 Inspector 式左标签、右值布局，输入框只包住值，列表是可折叠的共同容器。编辑某个值时临时出现原位输入框；菜单、日期和颜色选择器只在主动打开时出现。

## 输入

| 参数 | 描述 | 数据类型 | 必需 |
| --- | --- | --- | --- |
| `JSON Schema` | 普通字符串连线输入口。连接上游提供的完整 Schema JSON 文本；没有内置默认 Schema，没有多行源码控件。省略 `$schema` 时按 Draft 2020-12 | STRING | 是 |

输入是描述字段的 Schema，不是填写结果。解析后的对象先通过上游序列化为 JSON 字符串；不自动从围栏、解释文字或模型思考内容中提取 JSON。需要提取时显式组合相应节点。

`form_state` 是隐藏的 STRING 保存字段，默认 `{}`，不绘制、不占高度、不提供连接端口。它保存 Schema、填写值、确认状态、模板快照与最近一次复位前备份，随工作流保存；不手工编辑。普通草稿不能替代人工确认。

## 输出

| 输出名称 | 描述 | 数据类型 |
| --- | --- | --- |
| `填写结果` | 确认并通过校验后的完整 JSON 值；自动复用时仍经当前规则校验。保留对象、数组、嵌套结构及 null，不混入 Schema 或界面配置；数组整体输出，不展开执行列表 | DICT / ARRAY / STRING / INT / FLOAT / BOOLEAN / NULL |

输出口声明允许的 JSON 类型集合，实际结果由 Schema 与填写内容决定。需要字符串时显式序列化；需要逐项执行时接“将任意数组转为执行列表”。JSON Schema 的整数采用数学定义，`3.0` 也可通过 integer 校验。

## 第一次使用

1. 使用 ComfyUI 的 Python 安装包内 `requirements.txt`，表单依赖 `jsonschema[format]==4.26.0`。不需要模型或远程 API。
2. 重启后端、刷新页面，搜索“JSON Schema填写模版”。
3. 在上游文本节点提供下面的 Schema 字符串，将输出连接到本节点的 `JSON Schema` 端口。
4. 运行工作流。执行到本节点时，字段出现在节点画布内，任务等待填写。
5. 修改值；可点击“校验”查看错误。点击“确认”后再次校验，通过才执行下游。点击“取消执行”中断当前任务。
6. 保存工作流，保留已确认结果。下次结构不变且校验通过时通知并直接复用。

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "type": "object",
  "properties": {
    "标题": {"type": "string", "minLength": 1},
    "数量": {"type": "integer", "minimum": 1, "maximum": 20, "default": 3},
    "启用": {"type": "boolean", "default": true},
    "发布日期": {"type": "string", "format": "date"},
    "渠道": {"type": "string", "enum": ["淘宝", "京东", "其他"]},
    "卖点": {
      "type": "array", "minItems": 1,
      "items": {
        "type": "object",
        "properties": {
          "文案": {"type": "string", "minLength": 1},
          "重点": {"type": "boolean", "default": false}
        },
        "required": ["文案", "重点"],
        "additionalProperties": false
      }
    }
  },
  "required": ["标题", "数量", "启用", "发布日期", "渠道", "卖点"],
  "additionalProperties": false
}
```

例如填写后，把 `填写结果` 连接到“预览JS对象或数组”，可得到：

```json
{
  "标题": "健身凳",
  "数量": 3,
  "启用": true,
  "发布日期": "2026-11-16",
  "渠道": "淘宝",
  "卖点": [{"文案": "方便收纳", "重点": false}]
}
```

连线本身不会提前执行上游。已有草稿可在打开工作流时恢复，但运行时仍以实际输入的 Schema 为准。没有上游 Schema 连接时应先补上连接，不能依靠旧示例替代输入。

## 字段类型与画布控件

| Schema 特征 | 控件与行为 |
| --- | --- |
| `type: string` | 左标签、右值框；点击原位编辑。已有多行内容使用临时多行编辑器，保存完整字符串 |
| `integer` / `number` | 数字框；有可用上下界时滑动条与数字框在同一行，实时同步；也可横向拖动数字调整 |
| `minimum` / `maximum` | 限定数值范围；确认时后端仍完整校验 |
| `multipleOf` | 数字步长；滑动时按步长取值，后端采用十进制倍数校验，避免 0.3/0.1 的二进制误差 |
| `exclusiveMinimum` / `exclusiveMaximum` | 有整数或明确步长可推导合法端点时显示滑动条，否则保留数字输入 |
| `boolean` | 右值列起点的小复选框，不占满整行 |
| `enum` | 临时下拉菜单，与值框宽度对应；当前选项带勾选标记。保留字符串、数字、布尔、对象、数组的真实类型，不把选择结果统一转字符串 |
| `const` | 只读固定值；旧值不符时可明确选择“使用固定值” |
| `date` / `time` / `date-time` | 值框可直接编辑，右侧图标打开统一深色日历／时间选择器；不另占一行操作按钮 |
| 严格六位／八位 HEX 模式 | 值框附颜色预览；右侧打开色板、色相、通道及透明度选择器，见“颜色” |
| `object` / `properties` | 顶层直接列字段，嵌套对象按组折叠；字段 title 用作标签，description 用作提示 |
| `array` / `items` | 简单成员直接编辑，对象成员可独立折叠；标题右侧数量，左侧拖柄排序，右下角加减，长列表局部滚动 |
| 类型数组，如 `["null","string"]` | 使用带向下箭头的普通下拉框，直接显示当前类型；`null` 显示“无值”，其余显示“整数”“浮点数”“字符串”“布尔值”“对象”“数组”。切换后按新类型及其范围初始化，重复选择当前类型保留原值 |
| 未声明 `type` / 布尔 Schema `true` | 提供通用对象、数组、字符串、数字、布尔和 null 编辑及类型选择；不会把 `properties` 等关键字误当成类型断言 |
| `oneOf` / `anyOf` | 结构菜单；可选分支，或保留当前值逐字段编辑。对象分支补充初始字段时保留已有字段，最终校验全部分支及同级规则 |
| `allOf` / `if` / `then` / `else` / `dependentSchemas` | 后端根据当前值生成字段视图，应用编辑后更新条件字段；原始 Schema 不被合并改写 |

普通数字、文本与布尔字段不各自套一层折叠面板。字段修改直接更新对应路径，不能为了 UI 展示把数字或布尔转成字符串。

展开的嵌套对象及结构分支显示低对比度灰色层级引导线：从标题下方沿缩进区域延伸，以短横线连接直接子项，末端停在最后一个直接子项的标题／字段行。子层级有各自的线，收起后隐藏对应引导线；数组本身保留容器边界，其内部对象仍显示层级线。线条避开文字与折叠三角，不增加可点击区域，不改变字段位置、数据或节点高度；随画布缩放，并受所属列表的滚动裁剪限制。深层缩进已达到窄布局的上限时，不在没有空隙的位置强行画线。

普通字段的标签与值列之间使用半透明灰色虚线对应连接，位于这一行的垂直中心。从实际显示的标签末端留出间距后开始，到值控件前结束；标签过长、剩余空间不足时不绘制，不穿过文字、值框或按钮。虚线随所属条目一起缩放、滚动和拖动，不新增可点击区域；组标题仍使用上述层级引导线，不与普通字段的对应线混淆。

列表成员选中后，其选中背景覆盖范围内的键值虚线和缩进引导线统一使用 `#353535`；嵌套内容也遵守这一规则。失去列表焦点、选中底色转灰后，线条仍保持该颜色；未选中的成员保留普通引导线颜色。

普通字段行高 24 个画布单位，值框高 20 并在行内上下各留 2；相邻普通行间隔 4，因此两个值框之间实际保留 8 的空隙。组标题到第一个字段行间隔 4，内部内容段之间为 6，顶层内容段之间为 10；前一个组收起时，与后一个组标题之间保留 4。标题上方间距不取决于它自身的展开状态，因此切换当前组不会使其标题上下跳动。矢量分量换行采用 28 的行距；数字、枚举、日期、颜色等值控件与临时原位编辑框都遵守同一行内边界。

列表内容区上下各留 4，每个成员的实际内容上下各留 6，间距属于该成员的布局与拖动占位，不靠空字符串或增大控件凑高度。对象中的“新增字段”按钮高 20，所在行之前留 8、之后留 6，并保留行内留白；它不会贴住下一项或父容器底边。多层列表会在值列空间不足时停止继续缩进右边界，确保窄节点中的值框仍留在父容器内；滚动裁剪继续限制实际可见和可点击范围。

列表标题位于内容框外，不额外绘制标题底条；内容框与右下角增删页脚共用连续轮廓，加减不各自绘制独立按钮框。输入框、列表内容框与页脚外角统一采用 3 个画布单位的圆角。非空列表的内容上下各留 3 个单位，空列表内容区高 28；增删按钮在 24 高的页脚中垂直居中。成员内普通字段仍用 2 的间距，对象成员之间按内容段使用 4，不因嵌套反复累加额外组间空白。

字段共用值列起点；嵌套列表的左右边界受父容器约束，内层值框、数量框和增删页脚都随所属容器收进，不能延伸回节点的最右边。列表右侧预留滚动条空间，出现或消失时不挤动子字段。可选字段移除、多类型菜单各有独立操作区。数量框高 20、宽 44，在标题行中居中，编辑时仍保持同样字号、位置和宽度。宽度不足时标签省略，悬浮标签可查看完整名称；值框不会反复弹出同名原生提示遮挡内容。数字框和滑动条属于同一属性行。折叠、展开和列表增删重新计算真实高度。

结构参照 Unity 官方 [Custom Inspector 默认属性示例](https://docs.unity3d.com/6000.0/Manual/UIE-HowTo-CreateCustomInspector.html) 的统一值列，以及 [ListView](https://docs.unity3d.com/6000.0/Manual/UIE-uxml-element-ListView.html) 的折叠标题、数量、拖柄、条目选择与增删页脚。Schema 的可选属性另提供明确的添加／移除操作，不把属性存在性混成布尔值。

临时编辑器与选择器按画布实际变换矩阵定位，考虑平移、缩放、画布元素位置及设备像素比例，并按当前字段的命中区域持续更新锚点；编辑中调整节点宽度也会跟随，不回退到屏幕左上角。原位编辑器保持字段原来的位置与宽度，超出画布或所属列表可视区的部分裁剪，不因靠近屏幕边缘而整体挪动。浮动选择器空间不足时向上打开并限制在浏览器视窗内。没有全屏遮罩；弹层关闭后，列表快捷键只在对应列表持有焦点时生效。切换图、折叠所属区域或移除节点会关闭对应编辑器。

按钮标题居中，字段标签和值保持左对齐并共享行中心；文字按实际字形的上、下边界计算垂直中心，不用字体 em 框的 middle 基线代替视觉中心。加减、折叠、日期和时间图标按控件几何位置绘制。矢量末尾与其他值框右边缘对齐，下拉框为箭头保留空间，滑块拖动范围与轨道端点一致。

普通文字和原位输入框共用 14 画布单位的字号及字体（Windows 优先 Microsoft YaHei，其他平台使用 sans-serif 后备），值文字起点统一为框内左侧 6 个画布单位。编辑器测量浏览器输入控件的真实基线，并按当前值的字形度量定位；字符串、数字、矢量分量与列表数量都使用这一规则。画布缩放时，输入框以不取整的屏幕字号、尺寸和内边距重新绘制，避免把已经栅格化的输入框整体缩放而造成大小、位置跳变。只保留一层焦点边界，不叠加外发光描边。字形抗锯齿在浏览器画布与输入控件间仍可能有细微差别。

### 悬浮、按下与编辑

交互参照本机 Unity 6.3 LTS 的默认 Inspector，使用同款字符串、数值、对象与嵌套列表的 C# 示例实测，并参考安装包 `CoreEditorUtils.cs` 的标题／独立操作区域处理。实现适配 ComfyUI 画布，不引入 Unity 运行时；字段焦点、条目选择和列表焦点分别维护。

| 区域 | 命中范围 | 悬浮／按下／选中反馈 |
| --- | --- | --- |
| 对象／数组标题 | 当前标题横条，包括左右空白；不包括子字段。标题内数量、类型、移除按钮优先处理自己的点击 | 悬浮／按下只加强折叠箭头，不给整个组内容染色；展开状态由箭头方向表达 |
| 普通标签 | 标签文字范围 | 普通字段标签不成为大按钮；必要时显示完整名称／说明 |
| 文本／数值输入 | 对应值框 | 悬浮轻微加强边界，编辑使用单层焦点边界；不高亮父组或相邻字段 |
| 布尔值 | 复选框本身 | 框边反馈、勾选表示真实值；不会用整行底色冒充布尔值 |
| 下拉／操作按钮 | 按钮自身 | 按钮底色与文本输入区分；悬浮略亮，按下加深，移出松手不执行 |
| 滑动条 | 当前轨道 | 悬浮加强滑块，按下／拖动强调当前滑块，不改变邻近字段状态 |
| 数组成员 | 成员空白、拖柄或对象成员标题；内部值框各自处理编辑 | 悬浮不会改变选择。当前操作的列表使用蓝灰色选中底色，失去焦点后保留灰色选择记忆；编辑字段不会新选中整个条目 |
| 数组拖柄 | 当前成员左侧拖柄 | 只强调拖柄线条；移动超过阈值才排序，不把普通值框当成排序拖柄 |
| 不可用操作 | 按钮自身 | 弱化、不显示可操作悬浮效果；点击被该区域吸收，不穿透到父列表或折叠标题 |

复杂嵌套采用最内层实际命中的控件和列表：内层列表的成员下标、拖柄和选择独立于外层；点击内层不会重写外层的成员下标或同时高亮内层多项。展开／收起内层列表只将列表焦点交给内层，不把外层对象染成活动选中色；编辑字段或数量不新建条目选择。只有当前操作的列表显示活动选择，其他列表保留灰色选择；点击表单外或切换到其他字段后失去活动焦点。鼠标离开画布控件时清除旧悬浮与光标，不把之前的悬浮留在页面上。活动侧栏预览不继承可交互的焦点状态。

- 值框悬浮时边界轻微变化，按下加深；正在编辑的字段使用细焦点线。不会缩放按钮、挤动相邻行或让整组发亮。
- 枚举菜单使用紧凑行，通常与字段等宽（最小 120 屏幕像素），长选项换行；当前值显示勾选标记，焦点初始落在当前项。上下箭头、Home、End 移动菜单焦点，点击或 Enter 选择；Esc 关闭且不改值。菜单项用行底色标记焦点，不继承应用的大外发光描边。
- 按钮、折叠标题和复选框在原命中区域松手时响应；按住期间不超过 6 个屏幕像素的轻微位移仍视为点击，明显拖离取消。数字输入框的轻微抖动不会误改数值。原生尺寸测量不会清空当前已绘制控件的命中区域。
- 运行时“活动”侧栏使用独立的只读布局绘制节点预览，不修改主画布表单的坐标、命中区域、滚动位置或编辑焦点。侧栏反复重绘不应影响原节点的下拉、展开、增删或确认操作。
- 单行 Enter 应用当前字段；字符串输入中 Shift+Enter 展开多行编辑，多行输入用 Ctrl/Cmd+Enter 或“应用”；Esc 取消本次未应用编辑。Tab/Shift+Tab 在可编辑值框间移动。字段 Enter 不提交整个表单。
- 数字拖动实时预览，松手才固着本次手势；Esc 或指针操作被取消时恢复。一次数值拖动只产生一次值提交。
- 普通文本框使用文本光标，按钮使用点击光标，数值拖动与列表拖柄分别使用横向调整与抓取光标。类型切换、列表条数、增删操作提供对应提示。
- 正在提交时禁用重复操作。后端校验失败保留填写结果，错误按字段路径显示，同时在状态区域说明。
- 原位数字格式错误保留当前草稿，字段下方增加独立错误行并重新计算节点高度，不把临时编辑器的第二份错误文字覆盖在下一字段上；Esc 可取消本次输入。

数值控件的展示精度不是后端规则；后端按原始 Schema 检查。无 multipleOf 的连续数值允许输入任意合法精度；上下界相同不生成滑动条。

### 矢量分量

标准 JSON Schema 没有 Vector3 类型。本节点仅把**明确的固定轴对象**组合成一行画布分量控件：对象的键为 x/y、x/y/z 或 x/y/z/w（大小写不敏感），全部为必填数字字段、`additionalProperties: false`，且当前值完整。

```json
{
  "type": "object",
  "properties": {
    "x": {"type": "number", "default": 0},
    "y": {"type": "number", "default": 0},
    "z": {"type": "number", "default": 0}
  },
  "required": ["x", "y", "z"],
  "additionalProperties": false
}
```

点击某个分量原位编辑；输出仍是 `{"x":1,"y":2,"z":3}` 这样的对象，不变成新类型或数组。值列较窄、无法为每个分量保留合理宽度时，分量按两列换行，真实节点高度同步增加，后续字段不会覆盖它。width/height 等普通数字字段、允许增删轴的对象仍按普通对象编辑，不擅自认定为矢量。

### 日期时间

使用统一深色的自定义临时选择器，不再依赖浏览器白色 showPicker。日期展示星期表头、日历网格、年／月输入和翻月按钮，今天与当前选择分别标记；点击日期可直接应用。时间提供时、分、秒滚动列及精确输入，日期时间在同一弹层提供日历和时分秒输入；点击“应用”才写回。取消／Esc 不改变原值。

`time` 和 `date-time` 显示并保留原来的 Z 或 ±HH:MM 时区和秒的小数部分，编辑不会暗中换算成 UTC。新建空值使用当前本地日期和本地偏移作为选择器起点；仍需用户应用。可直接输入 `2026-11-16T12:30:00+08:00` 或 `12:30:00Z`；日期为 `2026-11-16`。普通时间选择器支持时 0–23、分 0–59、秒小于 60；直接字符串输入不受选择器的表达范围限制。此默认方言的 format 是注解，不据此拒绝输入；需要强制形状约束时可显式提供 pattern，但正则形状检查不等同于完整日期有效性检查。标准的数值 minimum/maximum 不能被当作日期字符串范围。

### 颜色

Draft 2020-12 没有标准 `color` 类型。本节点只将下列严格 HEX 模式映射为颜色编辑器，不按字段名称或任意字符串猜测。字符类可写为 `[0-9A-Fa-f]`、`[0-9a-fA-F]` 或 `[a-fA-F0-9]`，长度必须明确为 6 或 8：

```json
{"type":"string","pattern":"^#[0-9A-Fa-f]{8}$","default":"#4D99CCCC"}
```

六位为 `#RRGGBB`，八位为 `#RRGGBBAA`；输出仍为该字符串。例如 `#4D99CCCC` 对应 R=77、G=153、B=204、A=204（约 80% 不透明）。`format: color` 可以作为未知格式注解保留，不因此拒绝整个 Schema，但它不是标准颜色格式，也不会单独触发颜色选择器。其他合法颜色表示仍可通过普通字符串／对象字段编辑。

选择器提供饱和度／明度色板、色相、HEX 和 RGB(A) 数字；八位模式另有透明度。旧色和新色用棋盘底展示透明度，选择器内实时预览；应用才写入表单，取消恢复。最近 8 个已应用颜色保留在当前页面内存中；吸管仅浏览器支持 EyeDropper 时提供，必须由用户点击启动。六位颜色不输出透明度。RGB(A) 字典不自动识别为颜色，仍按普通对象编辑。

## 对象、可选字段与默认值

- 尚未创建的可选字段在值列显示 `＋ 添加`；已有结果缺少的新必填键会自动初始化并直接显示输入控件，不要求先点击添加。已填写可选字段在行末显示 `−` 用于移除，必填字段没有移除入口。它们不占用标签前的折叠位置。省略与 null 不相同，不使用布尔复选框混淆“是否填写”和布尔值。

“新增字段”是对象的操作，不能因为对象位于列表元素内就自动允许。通过 `$ref` 或 `allOf` 引用的对象若设置 `additionalProperties: false` 且没有名称模式扩展，仍隐藏任意新增字段入口；引用处的 title 等注解不会解除该限制。“＋ 添加”已有可选字段不受此限制，因为该字段已经在 properties 中声明。
- 默认值只用来初始化，不能跳过校验；依次参考 default、const、enum 和类型初始值。
- 新规则下同名且类型兼容的值保留；类型冲突的键按新类型重新初始化并更换对应控件。旧值只在新规则允许时生成同级编号备份键，详见“模板更新与已有结果”。无法确定分支或尚未解析的规则保留通用编辑，待规则解析或分支明确后再处理，不猜测一个互斥分支覆盖其他分支。
- `additionalProperties` 允许时可“新增字段”；同名键不覆盖，包含 `__proto__` 的普通字符串键按数据处理。
- 对象组可折叠，折叠不修改结果。仅展示部分字段不代表只输出可见字段。

初始构造最多展开 12 层，minItems 最多预建 100 项；需要更多时继续通过对象和列表控件新增。引用与条件视图限制一次预展开的深度和字段数量，未展开部分仍可使用通用字段编辑；修改值后重新解析，不无限构造递归定义。

## 数组、列表和执行列表

### 展开与收起状态的保存

对象、数组及嵌套条目的展开／收起状态保存在该节点的工作流属性中，随 ComfyUI 的工作流保存及页面恢复机制保留。刷新页面或重新打开已保存的工作流后，已经展开的部分仍展开，手动收起的部分仍收起；被收起的父组内部，也保留各子组此前的选择。

鼠标点击、键盘展开／收起以及校验定位自动展开都会记录。数组条目排序或删除后，展开状态沿用既有条目重排逻辑，跟随对应条目移动。不同节点各自保存，不会互相覆盖。未曾设置过的层级继续使用默认展开规则；输入模板实际变化时按现有规则重置旧模板的展开状态。

这些仅是界面状态，不修改填写值、不撤销已确认标记，不提交表单，也不会因单纯展开／收起而重新校验。它不替代工作流文件保存：导出或跨设备打开时，应保存包含这些节点属性的最新版工作流。

### 列表高度与可用空间

列表的自然高度由全部已展开内容决定，不再按屏幕高度比例或固定 240–600 数值限制高度。节点空间足够时，列表完整展开，不保留多余滚动条；节点被缩小时，扣除字段、提示、列表标题和底部操作区所需空间后，再给列表分配剩余高度，确实放不下的内容才滚动。

多个列表与嵌套列表共同参与整份表单的高度计算，短列表只占自身内容高度。拉高节点后，剩余空间重新用于展开列表，直到全部内容完整显示；多出的空间保留在底部操作区上方。缩放画布或改变浏览器窗口高度不会单独改变列表容量，布局以节点容器实际分配的画布高度为准。

最小布局仍保留列表标题、可交互的内容区域和增删操作区；这只是最低可用尺寸，不是最大高度。计算自然高度与重新布局不会清空现有滚动位置；只有内容已经全部展开或变短时，滚动位置才收敛到有效范围。


数组新增成员的类型由 items 或当前位置的 prefixItems 决定。空数组也能新增正确类型的初始值，不复制上一个条目的业务内容。

列表结构参考 Unity 6.3 的 [ReorderableList 实现](https://github.com/Unity-Technologies/UnityCsReference/blob/6000.3/Editor/Mono/GUI/ReorderableList.cs)：共享页脚内设置加减命中区。Unity Camera Stack 的加号菜单用于选择已有 Camera；本节点依据成员 Schema 直接初始化，所以不附加无实际选项的下拉箭头。排序或删除条目后，其内部折叠、嵌套列表选择、滚动与分支状态跟随对应成员重新编号，不套用原位置上其他成员的状态。

| 控件／规则 | 行为 |
| --- | --- |
| 数组组标题 | 显示字段名与条数，可折叠 |
| 点击条目 | 成员空白、拖柄或对象成员标题可选择所属列表的条目，整项连续底色包含展开的子字段和间距；嵌套列表独立选择。输入值框只进入字段编辑，不自动新选中整个条目或触发排序 |
| `＋` | 在末尾按成员 Schema 新增一项，选中该项并将焦点交给所属列表，滚动到新增项；仍受 maxItems/items 限制 |
| `−` | 删除当前选中项，随后选择前一项并保留列表焦点；没有选择、数组为空或达到 minItems 时禁用。删空后清除选择 |
| 列表数量 | 显示与原位编辑都使用相同左侧文字位置；修改数量按成员 Schema 补齐或从末尾移除 |
| 上／下方向键 | 当前列表有焦点且没有正在编辑字段或打开弹层时，循环选择上一项／下一项，并滚动至可见 |

| 左侧拖柄 | 超过小位移阈值开始排序；整条内容（含展开子字段和嵌套列表）在所属列表轨道内上下移动，横向位置固定。跨过相邻项中线时，其他条目以 160 毫秒缓出动画连续让出占位；途中改变方向，从当前显示位置继续移动，不瞬移。松手才提交数组顺序，并平滑落入最终位置；Esc／操作取消则恢复。边缘可自动滚动，不跨数组拖放 |
| 长列表 | 根据全部内容的自然高度与节点实际可用空间布局。空间足够时完整展开，仅在放不下时使用滚轮和右侧滚动条；节点加高后继续展开，不采用固定最大高度或屏幕比例。多个嵌套列表共同分配空间，裁剪外的字段不响应点击；Ctrl/Cmd+滚轮仍缩放画布。 |
| 标题右侧条数 | 原位编辑数量；新增按成员规则初始化，缩短从末尾移除。一次最多新增 1000 项，避免误输入冻结界面 |
| `minItems` / `maxItems` | 限制删除／新增 |
| `prefixItems` / `items: false` | 逐位置采用不同规则；不允许的额外项不能新增 |

列表交互参照 Unity 6 中 Cube 的 A 脚本事件列表：条目选中采用整项连续蓝色背景，失去列表焦点后转为灰色；列表内容采用统一灰底，加减按钮共同附着在右下角。拖动时不再显示鼠标旁的小标题，也不只画插入线；预览保留完整控件外观，但不允许在拖动过程中编辑这些虚拟控件。父项拖动会携带其嵌套内容，内层拖动只影响内层列表；滚动裁剪仍按各自容器处理。

新增值继续依据 JSON Schema 的 items/default 初始化，不复制 UnityEvent 的对象引用或调用函数，也不会无条件复制上一条业务数据。加减、重排与取消都保留现有确认／草稿机制。

列表是共同容器，对象成员独立折叠，不逐项套卡片。对象成员有非空普通字符串字段时，按字段显示顺序使用第一个这样的值作为标题，例如“高强度框架”；修改该字段后标题同步。索引始终保留在悬浮提示中，重复名称不影响实际下标。没有合适名称时，显示从 0 开始的 `元素 0`、`元素 1` 等下标，成员 Schema 的 title 接在下标之后。简单成员仍保持左标签、右值列。拖动靠近列表可视区边缘时随拖动移动滚动位置；输出保留所有未显示的条目。排序不改变值的真实类型；prefixItems 重排后仍按新位置校验。uniqueItems、contains 等规则在确认时后端检查。

JSON 数组可以直接嵌套数组，本节点不要求使用 Unity 序列化所需的额外包装对象。Unity 默认列表新增可能复制尾项，本节点仍按成员 Schema 和 default 初始化，避免复制上一项的业务内容；视觉和交互参考不会改变数据语义。

嵌套列表的增删页脚需要完整进入父列表可视区才显示操作按钮，避免滚动边缘露出半截加减号，与外层固定页脚混淆。继续滚动到该页脚即可操作；被裁剪的按钮没有可点击区域。

数组整体输出，例如 `[1,2,3]` 是一个 ARRAY，不自动执行下游三次。上游提供 Schema 执行列表时，ComfyUI 原生逐项调用；需要填写的每次调用有独立请求编号，可通过“待填写项”选择，不能把一次提交误用于另一个已等待的请求。

## 标准支持与复杂结构

后端按 Draft 2020-12 校验原始 Schema，包括类型、范围、组合／条件、对象／数组约束、未求值属性与条目。控件映射和数据校验是两个层面，界面不能精确表达的约束仍然校验。

- `$ref`、`$dynamicRef`、`$anchor`、`$dynamicAnchor` 与 `$id` 由 referencing 解析资源作用域；同级约束继续参与，不用简单字符串拼接代替引用语义。
- allOf、if/then/else、dependentSchemas 和 dependentRequired 根据当前值产生字段与必填提示；patternProperties 为当前已命名字段提供规则，新增键名后重新计算。oneOf/anyOf 仍可明确选择分支。
- 条件字段暂时不适用时不删除旧填写值；如果原始规则不再允许该字段，确认时提示错误，由用户明确移除。复杂值使用通用对象、列表与标量控件，不再因为存在组合规则而强制填写整段 JSON。
- HTTP(S) 外部引用由后端读取；相对引用须有可解析的 $id 基址，嵌入资源优先从文档内解析。不可达、内容无效或无法解析时提示错误，不视为校验通过。后台解析在工作线程中进行，不占住服务器事件循环。
- 同一份 Schema 的解析上下文最多缓存 16 份；每份最多 20 个远端资源，单资源最多 8 MiB、读取超时 10 秒。缓存保留该资源内容供后续校验复用，后端重启清空。远端同 URL 内容变化需要重启后端或使用新版本 URL；这些是运行限制，不是标准语法要求。
- 上游可传入字符串 `true` 或 `false` 作为布尔 Schema；true 允许 JSON 值，false 不可能有合法结果，执行时报错。
- 只接受题定的 2020-12 默认方言或省略版本，不混用旧版或自定义元 Schema；普通输入 Schema 上的 $vocabulary 不会自行定义新方言。
- 默认方言使用 format-annotation：已知 format 可提示界面组件，未知 format 保留普通字段，不拒绝 Schema；format 本身不作为失败条件。format-assertion 或自定义 vocabulary 的其他方言不在此节点的默认方言支持范围内。
- contentEncoding、contentMediaType、readOnly 等注解不触发自动解码、文件读取或上传。
- JSON 值嵌套最多 64 层，数字有限且绝对值不超过 `2^53-1`；大编号用字符串，不接受张量、元组或非字符串键。

### 条件字段示例

将以下字符串连接到本节点并运行：选择 `企业` 后会出现 `税号` 字段；切回 `个人` 不会擅自删除已经填写的税号。最终校验始终使用以下原始规则。

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "type": "object",
  "properties": {"类型": {"enum": ["个人", "企业"], "default": "个人"}},
  "required": ["类型"],
  "if": {"properties": {"类型": {"const": "企业"}}, "required": ["类型"]},
  "then": {"properties": {"税号": {"type": "string", "minLength": 1}}, "required": ["税号"]}
}
```

企业分支的有效结果例如 `{"类型":"企业","税号":"91310000EXAMPLE"}`。值修改后约 150 毫秒发起本地规则解析；仍在原位输入或拖动时延后刷新，过期响应不会覆盖新值或其他待填写项。字段视图只提供编辑提示，不保证草稿始终有效，也不求解任意 Schema 是否存在解；`false` 直接报告无法填写，其他相互矛盾的规则由校验指出。

## 等待、确认与固着复用

### 模板更新与已有结果

上游新 Schema 执行到本节点后，旧填写内容作为草稿按当前规则整理，按如下顺序处理：

1. **补齐缺失的必填键。** 对象及数组成员内的必填字段逐层初始化，直接出现对应输入控件；没有在 `properties` 中声明、只出现在 `required` 中的键也会创建。可选且尚未创建的字段不因补齐操作自动加入。
2. **保留同名、类型兼容的值。** 不因默认值或范围改变覆盖已经填写的值。整数可以用于允许 number 的字段；小数不能直接作为 integer，布尔值也不当作数字。
3. **重建类型冲突的键。** 例如旧值 `"库存": "未知"` 遇到新的 integer 规则，原 `库存` 键按新类型生成初始值，控件改为数字输入。类型正确但超过范围、长度不足或不符合枚举等情况不自动替换，交给当前规则校验。
4. **按新规则决定是否留下旧值。** 尝试创建 `库存_备份1`、`库存_备份2` 等同级键，避开已有键和模板中已声明的键名。允许时它紧邻原字段显示，并作为真实键进入填写结果；不允许时丢弃此次冲突的旧值，不创建另一个隐藏备份区。
5. **重新确认。** 自动补齐或重建都会将结果标为未确认，即使初始化后的值碰巧合法，也不会自动放行执行。

示例：已有结果为 `{"商品名称":"保温杯","库存":"未知"}`，新模板要求商品名称和整数库存，允许额外键。整理后可以得到 `{"商品名称":"保温杯","库存":0,"库存_备份1":"未知"}`；若新模板设置 `additionalProperties: false`，结果则为 `{"商品名称":"保温杯","库存":0}`。初始化采用新模板的 default、const、枚举或类型初始值；与显式类型冲突的默认值不会让控件反复在两个类型间切换。

**是否允许备份，依据原始 JSON Schema 校验，不只检查一个开关。** `additionalProperties` 默认允许额外键，也可设为 false 或约束额外值类型的 Schema；`patternProperties` 可按名称模式规定类型；`unevaluatedProperties` 可约束组合／引用后未覆盖的键。`propertyNames`、属性数量上限和依赖规则等也参与判断。备份键若引入新的校验失败，就不会保留；其他未填写字段已有的错误不会单独阻止一个合法备份。

对象键的冲突备份放在同级。数组内部对象仍按其对象键处理；数组标量成员类型改变时，尝试在该数组所属对象旁备份整份旧数组，不在数组中混入虚构的键。顶层值没有同级对象可放备份，类型重建时直接替换。仅删除或新增规则不等于任意清理草稿；当前值中的其他额外键仍由原始 Schema 校验。

条件、组合和引用规则先通过后端解析，再补齐对应分支；点击校验或确认会在补齐完成后重新校验，避免显示补齐前过期的“缺少键”错误。多个分支尚不明确时只补齐各候选分支共同要求的键，互斥部分等待分支明确。递归和资源限制仍适用，不能自动构造本来就不可能存在的有限合法值。

`required` 只要求键存在，并不要求字符串非空。新建字符串通常为 `""`；要求用户实际填写时，模板应同时设置 `minLength: 1`，需要排除纯空白时还应有相应 pattern。错误会指向这个已存在字段，而不是要求先添加它。

类型备份等待后端规则判断期间，待判定内容临时随草稿保存，以免刷新页面丢失判断进度；判定完成即清除该临时内容，允许的备份成为结果中的普通键，被拒绝的旧值不会另存隐藏备份。该功能需要前后端版本同步；后端未更新时会明确提示，不能在未判定的情况下直接提交。

### 底部操作区与节点尺寸

底部按钮从左到右为 `计算链以更新模版缓存`、`复位到模板`、`校验`，等待期间再显示 `取消执行`、`确认`，其中 `确认` 位于最右侧。尚未接收模板时也显示计算链按钮。操作区位于节点右下角，距右边和底边各 12 个画布单位。节点拉高后，表单内容留在上方，操作区随节点底边移动；手动设置的高度不会因普通编辑或复位被自动缩回。内容增多时仍会满足最小显示高度。

宽度不足时，按钮按顺序右对齐换行，按钮间横向间距 6、两行间距 6，不挤出边界或互相覆盖。按钮绘制和可点击区域使用同一份布局。表单仍是节点内部原生画布控件，节点整体平移、缩放时一起移动，不固定到浏览器窗口。

### 计算链以更新模版缓存

上游文件或计算规则改变后，点击最左侧的 `计算链以更新模版缓存`，按当前连线将产生 JSON Schema 的上游依赖链提交到 ComfyUI 队列，计算到本节点的 Schema 输入为止。成功后更新本节点的模板缓存和初始值快照，并按新规则重新生成表单；同名、同类型的已填值保留，新增必填字段及类型冲突沿用下文迁移规则。此操作不提交填写结果，不进入本表单的人工等待，也不继续执行下游。

例如将 `读取文本文件` 的输出连接到 `JSON Schema`，修改并保存该文件中的 `required` 或 `default` 后：

1. 点击 `计算链以更新模版缓存`，等待“模版缓存已更新”提示，表单按新规则显示并保留兼容的填写值。
2. 如需把已填内容也全部恢复为新模板的初始状态，再点击 `复位到模板`。
3. 正常运行工作流时，再检查并确认结果。

计算链是一次真实的上游执行，沿用 ComfyUI 的缓存和节点变更检测；本包读取文本文件节点会检测文件变化并重新读取。未变化且缓存有效的计算可以复用，不强制清空缓存。若上游包含 LLM 或其他收费节点，缓存未命中时会按普通运行调用它们；若上游有交互节点，仍需完成其交互。这不是绕过上游计算直接读取某个固定文件的快捷方式。

| 情况 | 行为 |
| --- | --- |
| 尚未连接 Schema，或者表单被静音／绕过 | 提示修正连接或启用节点，不覆盖原缓存 |
| 本表单正在等待人工确认 | 提示先确认或取消该次执行，避免更新任务排在自身等待后面 |
| 更新进行中再次点击 | 不重复提交；显示排队或计算状态 |
| 临时断网、无法读取任务状态 | 保留任务编号；再次点击查询同一任务，不重复计算 |
| 输入链失败、取消、返回非法 Schema 或多个 Schema | 显示原因；保留原模板和填写内容，需要修正后重试 |
| 刷新页面或重新打开工作流 | 保存的更新任务编号用于从运行历史恢复结果，不重复提交；后端重启丢失任务时明确报错 |
| 计算期间另一执行为该表单送入新请求 | 不覆盖另一执行的输入，提示结束它之后再更新 |

更新任务信息保存在隐藏的 `form_state.refresh_job`，随工作流草稿／保存机制保留；未保存的页面状态不等同于已写入文件。子图通过完整执行路径定位，不能唯一定位的共享实例会明确提示，不猜测目标。

### 复位到模板、快照与撤销

`复位到模板` 将字段、数组成员及可选属性恢复到**当前输入 JSON Schema 定义的初始状态**。初始值沿用首次生成表单的规则：优先采用 `default`，其次为 `const`、枚举初始项与类型初始值；数组未提供 default 时按 minItems 初始化，可选且没有默认值的属性不会凭空保留。组合规则和引用通过已有规则解析接口处理。Schema 的默认值不保证满足所有校验条件，复位后仍可继续填写和校验。

例如输入字段 `{"type":"integer","default":3}`，把值改为 9 后点击复位，恢复为 3；数组字段 `{"type":"array","items":{"type":"integer"},"default":[1,2]}` 即使增删、重排过，复位后也恢复为 `[1,2]`。未在 Schema 中声明的演示填写值或历史草稿，不会被当成输入模板的默认值。

复位依据节点最近一次实际收到或工作流中保存的 Schema，不自行计算上游。上游字符串或文件修改后，先点击 `计算链以更新模版缓存`，或正常执行到本节点，再复位才能使用新模板。再次执行直接复用确认值时，也会同步本次 Schema，让新默认值用于后续复位；延迟到达的旧执行消息不会覆盖较新的未确认草稿。

| 保存内容 | 生命周期与作用 |
| --- | --- |
| 当前 Schema 与草稿 | 记录当前已应用的字段值；修改或复位后取消确认状态 |
| 模板快照 `template` | 独立缓存输入 Schema 和初始值，字段编辑不改写它；输入 Schema 变化时重新建立，包含默认值变化 |
| 复位前备份 `reset_backup` | 保存最近一次成功复位之前的 Schema、已应用填写值和确认状态；下一次复位替换该份备份，不无限累积历史 |

这些数据随工作流保存，保存后重新打开仍可复用模板快照。未保存到文件的更改受 ComfyUI 自身草稿与恢复机制管理，不把内存缓存等同于已经写入工作流文件。

复位可以使用 ComfyUI 原生撤销操作恢复；等待人工填写期间撤销，也会同步恢复该待确认请求的填写内容。复位本身不会调用提交接口、取消执行或结束等待，用户仍须点击 `确认`。解析失败会保留原填写内容并提示原因。复位前已有字段输入错误时也可使用复位重新开始；尚未应用为合法字段值的临时输入文本不作为 JSON 结果备份。

### 等待与确认

确认、取消或收到后端完成通知，只结束本次等待，不丢弃已解析的字段显示规则。相同 Schema 和填写值在等待前后使用相同的标题、枚举、类型及字段增删限制；合法的条件分支变化仍按实际填写值更新。执行结束时正在进行的规则解析可以继续完成，不会因切换状态被丢弃。

组合、条件和引用需要后端解析时，相应位置短暂显示“正在解析字段规则…”，解析完成后显示实际控件。此时不把尚未确定的约束当作任意类型，不凭空提供类型切换、自由新增或移除字段。只有 Schema 本身允许通用类型／额外字段时才显示对应操作；解析失败会保留填写内容并报告原因。

首次执行或没有可复用结果时，节点等待用户填写，下游依赖它而等待；不会输出占位结果。独立并行任务仍遵循 ComfyUI 正常调度。API 执行无人填写时也等待，不自动采用默认值。

“校验”只检查，不放行；“确认”提交到后端重新校验，通过后该请求只接受一次。页面使用“完整字段路径＋中文原因＋修改建议”，数组位置显示为“第1项”等便于阅读的编号；修正后继续确认，无需重跑上游。

### 修改后的持续校验

点击“校验”，或等待执行时点击“确认”，发现错误后会进入持续校验状态。此后每次提交字段修改（包括更改类型、增删或排序列表项）都会重新校验整个填写结果，不需要反复点击校验按钮。复位、当前待填写请求的撤销恢复也会重新检查。

- 修改时保留已有的字段错误标记和底部错误列表，状态显示“正在重新校验…”。新结果返回后，修好的错误消失，尚未修好的错误继续显示，新产生的错误一并加入。
- 沿用规则解析请求的 150 毫秒合并窗口；连续修改合并为对最新值的一次检查。正在输入、弹出编辑器或拖动时，等待该次编辑结束再更新表单，避免打断操作。尚未能解析成合法数值的输入保留本地输入错误，修正并提交值后再检查完整规则。
- 条件变化需要补齐或重建必填字段时，先完成字段更新，再校验更新后的值，避免显示过期的缺键错误。
- 只接受对应当前值的最新检查结果；较慢的旧响应不会覆盖新结果。请求失败时保留已有错误并显示失败原因，下一次修改会再次检查。
- 所有错误消除后显示“校验通过”，结束本轮持续校验。自动校验只检查，不提交、不固着填写结果，也不解除工作流等待；仍须点击“确认”才能继续执行。确认会再次检查当前值。
- 尚未主动校验过的草稿不会因普通修改自动展示整份规则的错误；持续校验状态属于本次页面里的当前填写过程，不写入工作流作为永久设置。

例如有“名称不能为空”和“数量至少为 1”两个错误：填好名称后，只移除名称错误，数量错误继续显示；再将数量改为 1 后显示“校验通过”。两次修改之间不需要重新点击校验。

### 中文校验提示

顶部只显示问题总数，不重复第一条报错。字段处保留错误提示，表单下方使用独立的日志式错误区域：每条左侧是八角错误图标，按右侧两行文字的整体高度确定比例，并在条目内垂直居中（长段落换行时保持两行文字的图标尺度），右侧上方显示完整字段路径，下方显示中文原因和修改建议。条目采用交替底色和细分隔线；完整路径与说明均按节点宽度自动换行，条目高度随文字增长，不覆盖下一条或底部按钮。

校验失败会展开全部错误路径涉及的对象、数组及分支层级，避免错误字段藏在折叠区域中。列表依据当前节点实际分配的空间展开；空间不足时才滚动，不采用固定数值高度上限。点击底部任意错误条目，会重新展开对应路径，从内向外滚动相关列表，再平移画布将目标字段放到实际可见画布区域中央（扣除左右分栏、顶部及底部面板等遮挡，侧栏已挤出画布时不重复扣除）；不改变画布缩放、字段值、确认状态或工作流执行状态。错误条目悬浮时有轻微底色反馈和手形指针，不增加永久选中状态。定位使用原始 JSON Pointer，不从点分隔的显示文字反推，因此字段名中的点、斜杠及波浪号不会导致定位到别处。

字段旁的红色提示与对应内容使用同一个低饱和红色圆角边框，内部细线分开内容与说明：普通字段框住自身；对象或数组的整体规则错误框住该组标题及当前展开的内容，折叠时框住标题与提示。嵌套列表中的边框、提示遵循列表裁剪和滚动，不覆盖父容器；错误消除后边框一同移除。

红色提示中的字段路径使用已解析规则的显示名（title），保持点分隔的完整层级；未设置显示名时使用原键名。比如内部的“出图要求.主图.制作”可显示为“本次制作范围与规格.主图.本次是否制作”。只改变这处自动生成的提示，不改变真实 JSON 键、值、校验规则和错误定位路径；作者通过 x-error-message 提供的文字原样保留。后端为字段旁提示单独返回 display_message，下方卡片继续使用原 message。

整体规则错误定位到表单起始位置；路径指向尚未生成的字段或向量的内部成员时，定位到最近的可编辑父字段。修正后重新校验即可获得当前值对应的错误结果。

路径用点分隔，例如 `出图要求.主图.配置.第1项.配置名称`，不再在括号内重复位置，也不使用箭头或斜杠作为分隔符。数组编号从 1 开始；对象字段名按原名保留（原名自身的点或斜杠也保留）。同一字段的不同规则会一起保留，完全相同的规则提示不重复列出。下方错误卡片的路径、内容及样式保持原样。字段旁的红色提示按所在容器宽度自动换行，完整显示，不用省略号截断；高度随内容增长，为后续字段和底部按钮留出空间。

| 情况 | 提示示例 |
| --- | --- |
| 必填文字为空 | `配置名称：不能为空，请填写内容。` |
| 要求非空白字符但只填了空格 | `配置名称：不能为空或只包含空白字符，请至少填写一个非空白字符。` |
| 至少需要一个字段的对象为空 | `数量：对象至少需要 1 个字段，当前有 0 个字段。请添加字段。` |
| 数值低于下限 | `数量：数值必须大于或等于 1，当前为 0。` |
| 缺少字段 | `缺少必填字段：名称、数量。请添加并填写这些字段。` |
| 类型不符 | `需要填写整数，当前是文字，请修改值或切换类型。` |
| 数组有重复项 | `列表中存在重复项，请删除重复项或修改内容，使各项互不重复。` |

长度、数值边界、步长、成员数量、必填、额外字段、依赖字段、枚举、固定值、组合方案和禁止条件均按实际校验规则生成中文说明，不调用翻译或模型 API。实现位于可独立导入的 [schema_chinese 包](SchemaChinese.md)：先将规则转换为明确区分逻辑关系的要求树，再生成中文。复杂组合按层级列出完整条件，不再只截取前三个分支。任意正则表达式不被猜测成业务要求：无法识别为常见非空白约束时，保留精确匹配模式。

#### 模板作者自定义报错：x-error-message

`x-error-message` 是本节点支持的 Schema 扩展注解，不是 Draft 2020-12 内置的报错关键字。它只替换报错文案，不改变校验通过与否、字段路径、原始诊断或错误定位。未提供有效文案时，继续使用自动生成的中文说明。

**它写在 Schema 的规则位置，与 `type`、`properties`、`additionalProperties` 等同级，不能写进 `properties` 当成数据字段。** `additionalProperties: false` 限制的是填写结果中的额外键，不会禁止 Schema 自身的报错注解。该注解不生成控件、不生成初始值、不出现在填写结果中；默认值和用户数据也不会被当成报错规则解析。

下面是可直接连接到 JSON Schema 输入的完整例子：

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "type": "object",
  "properties": {
    "项目名称": {
      "type": "string",
      "default": "",
      "minLength": 1,
      "x-error-message": {
        "minLength": "请填写一个项目名称，便于辨认本次任务。"
      }
    }
  },
  "required": ["项目名称"],
  "additionalProperties": false,
  "x-error-message": {
    "required": "请添加并填写项目名称。",
    "additionalProperties": "这里只允许填写项目名称，请移除额外字段。"
  }
}
```

初始化只有 `{"项目名称":""}`，页面只生成项目名称的输入控件；校验空字符串时显示作者写的 minLength 文案。填写完成的输出如 `{"项目名称":"夏季主图"}`，不含任何 `x-error-message` 字段。

| 写法 | 作用 |
| --- | --- |
| `"x-error-message": "这里的内容不符合要求，请检查。"` | 替换当前 Schema 位置产生的所有校验错误文案 |
| `"x-error-message": {"not": "主图、详情页、SKU图中至少选择一项制作。"}` | 只替换同级 `not` 失败的文案，其他规则继续自动解释 |
| `"x-error-message": {"minLength": "请填写名称。", "default": "请检查此字段。"}` | 优先使用对应规则的文案，没有有效对应文案时使用 default |

匹配优先级为“当前 Schema 位置的对应规则文案 → 当前位置的 default 文案／字符串文案 → 自动中文解释”。空白字符串、非字符串文案等无效内容不隐藏错误，回退至下一项。按规则写法中的 `default` 是此扩展的报错后备文案，不是 Schema 的字段默认值。

给 `not`、`anyOf`、`oneOf` 写总报错时，要放在这些关键字同级，而不是放在其内部某个分支。父对象的文案不会自动覆盖所有子字段错误；引用中的错误文案应写在实际定义失败规则的 `$defs` 或被引用 Schema 内。页面继续显示完整路径；文案按普通文字展示，不执行 HTML、脚本或变量插值。仅修改报错注解不改变结构判断，不会让原本合法的已确认值失去复用资格。

标准允许自定义扩展关键字，但其报错语义并不跨校验器通用。不支持它的普通校验器仍按标准规则校验，通常忽略这条注解；开启未知关键字严格检查的工具可能要求注册扩展或预先移除。若向这类工具提供 Schema，应仅删除 Schema 规则位置的 `x-error-message`，不能按同名字符串递归删除用户数据、`default` 或 `const` 内容。本节点的实际校验器已验证该扩展不影响 `additionalProperties: false` 等标准规则。

#### 多字段组合与禁止条件的提示

`not` 校验失败时，提示具体被禁止的条件及当前值，不只写“符合禁止条件”。对于必填对象字段的枚举／固定值组合，若能从字段的可选值中准确求出替代值，会直接说明至少要改哪一个字段、改成哪些值，使用完整点分隔路径。

例如字段 `出图要求.主图.制作`、`出图要求.详情页.制作`、`出图要求.SKU图.制作` 均允许 `待确认 / 制作 / 不制作`，且规则禁止三者全部属于 `待确认 / 不制作`。三个字段都是待确认时，会提示：

> 至少将以下字段中的一个设为 "制作"：出图要求.主图.制作、出图要求.详情页.制作、出图要求.SKU图.制作。当前：这 3 个字段均为 "待确认"。修改后仍需满足其他字段规则。

这条提示只针对该组合规则；选择制作后，仍要满足该类别的配置等其他要求。字段名称和值从输入 Schema 读取，不在节点中固定业务内容。可选字段、引用或额外组合约束不能安全推导为这种修改建议时，改为列出完整的中文条件；保留必要的精确模式、引用和作用范围，不提供错误的“修改后必通过”承诺。`anyOf / oneOf` 显示至少／恰好一项的完整要求及点分隔字段路径，`contains` 同时说明数量和匹配条件。

接口仍保留 `path`（JSON Pointer）、`rule`、`schema_path` 和原始 `technical_message`，便于定位；页面不直接展示英文校验器报错。中文位置中的“第1项”对应机器路径的下标 `0`，不会修改实际数组下标或结果。

| 再次执行的情况 | 行为 |
| --- | --- |
| 从未确认，或修改了固着值 | 等待人工确认 |
| 已确认、结构相同、当前校验通过 | 通知并直接复用，不等待、不移动画布 |
| 标题、说明或默认值变化 | 不覆盖确认值，不因此要求重填；执行后更新当前模板，供主动复位使用 |
| 范围、必填、枚举或格式变化 | 按新规则校验，原值不合法才等待修正 |
| 增删字段、类型／成员结构／引用／组合分支变化 | 重新等待确认，尽量保留旧值供编辑 |

对象键的排列顺序不算结构变化，prefixItems 的位置变化算结构变化。复杂组合保守比较，不声称识别所有逻辑等价的 Schema。

修改已固着值立即变成未确认草稿；确认后保存工作流才能跨重开／重启保留。已排队任务使用提交时的快照。同一任务的循环展开有最多 128 条临时确认记录，限定任务、工作流、节点与原草稿快照，仍比较结构并校验，不跨任务覆盖新草稿，不作为隐藏跨节点传值渠道。

## 通知、恢复和旧版兼容

页面可见且浏览器有焦点时，待填写事件定位到对应节点，必要时逐层打开子图。重复事件不抢回视图，不覆盖填写内容；自动复用只通知。

系统通知由 Python 后端通过 Windows 原生 Toast 接口发送，不使用浏览器 Notification API，不申请站点通知权限，也不再显示“系统通知”按钮。页面会报告当前工作流与前台状态：前台正在查看该工作流时直接定位；后台时发送系统通知。后端发出事件后约 1 秒仍未收到前台报告，也会尝试通知，因此关闭浏览器不影响等待提醒。自动复用仍会通知，但不会暂停任务。

点击通知优先匹配已连接且打开目标工作流的页面，通过完整节点路径逐层进入子图并定位。先尝试激活该页面；必要时仅在此次主动点击通知后请求 Windows 激活其浏览器窗口，已最小化才恢复窗口。找不到匹配页面、页面没有响应或浏览器／Windows 拒绝激活时，才在默认浏览器新开标签页，从执行时的工作流快照恢复并定位，不覆盖另一个已有工作流页面。不要把这个恢复快照误认为已经保存到文件。

首次发送时自动注册当前 Windows 用户下的 ComfyUI 通知标识及 `comfyui-liuxinyu-form` 点击协议，由本机 Python 处理，不要求管理员权限。依赖系统自带 Windows PowerShell／WinRT；不新增 pip 依赖。Windows 已关闭应用通知、请勿打扰、无交互桌面或系统策略仍可能阻止显示；明确的接口失败会记录到后端日志并反馈到 ComfyUI 消息。系统接受通知不保证一定显示横幅。

通知在运行后端的 Windows 电脑上出现；远程浏览器连接不会把它转发到另一台电脑。等待请求完成后会清理通知；后端重启后旧请求标识失效。最近最多保留 128 个通知定位记录，仅在进程内保存；旧通知无法定位时页面会明确提示，不会把旧确认提交到新的任务。

等待时刷新或切回工作流，会按工作流 ID 和完整节点路径恢复待填写请求。后端重启会终止等待任务；已保存的确认结果仍可在新运行时校验复用，未保存草稿是否恢复依赖 ComfyUI 的草稿保存。

旧版节点的 Schema 明文框及 `form_state` 错误端口会被清理；旧控件值按原位置迁移，已有 Schema 连线保留。曾仅在节点内填写 Schema 的旧工作流需要补上上游字符串连接。无需重建节点，不能继续把原内置示例当成真实输入。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 上方仍有 Schema 明文框或输出口被挡住 | 后端需加载新的 STRING 输入定义，刷新前端；新版不会创建 Schema 编辑控件或整块 DOM 表单 |
| 只有状态，没有字段 | 先连接 Schema 字符串并运行到节点；普通连线尚未执行上游 |
| 校验通过仍等待 | 点击“确认”；手动校验和修改后的自动校验都不代表提交 |
| 运行后所有控件看得到但点击无效 | 更新并刷新前端；旧实现的活动预览会覆盖主画布命中坐标。新版隔离预览布局，刷新后恢复尚未结束的填写请求，无需重新运行上游 |
| 确认返回 422 | 按字段路径和规则修正，当前执行继续等待 |
| 确认返回 409 | 请求已提交、取消或因重启失效，不会误作用于下一轮 |
| 值看着正确仍被拒绝 | 检查完整范围、倍数、分支及依赖规则，控件显示不是唯一校验依据 |
| 部分列表项不见了 | 检查折叠状态并在列表内滚动；全部项仍保存在结果中 |
| 日期选择器打不开 | 点击值框右侧图标；刷新前端加载新选择器，也可直接编辑标准时间字符串 |
| 颜色仍是普通文本 | 核对 type 和上述精确 HEX pattern；不是任意正则都自动推断颜色 |
| 引用解析失败 | 检查 $id 基址、锚点、资源地址与后端网络可达性；外部资源不可用时不能保证渲染与校验 |
| 日期文本未被 format 拒绝 | 默认 Draft 2020-12 方言的 format 是注解；组件提示不等于强制格式断言 |
| 后台没有 Windows 通知 | 检查 Windows 的 ComfyUI 通知开关／请勿打扰，以及后端日志；不需要浏览器站点通知权限 |

## 开发与验证

输入链更新参照同包 `ratio_paint.js` 的 `graphToPrompt` 与 `partialExecutionTargets` 机制。`template_form_refresh.js` 仅把执行快照中的目标替换为内部输出节点 `LiuxinyuTemplateSchemaCache`，只保留 Schema 输入依赖，不修改画布连线或用户节点类型；内部节点使用现有 V3 自动扫描加载，不列入用户节点目录。执行结果从 history 读取，兼容输出缓存；通过完成事件立即检查，并用低频队列检查补偿消息丢失。`tests/test_template_form_refresh.cjs` 覆盖目标路径、执行快照、缓存结果、失败与取消；表单测试覆盖按钮顺序、重复点击、模板更新、复位及恢复。

Python 使用同包 V3 define_schema/execute 和根目录自动扫描加载，输入为 `io.String.Input(force_input=True)`。前端入口 `template_form.js` 负责事件、定位及通知；`template_form_controller.js` 管理请求、确认和旧数据迁移；`template_form_native.js` 通过 addCustomWidget 注册一个 Inspector 复合画布控件，管理字段树的布局、裁剪、命中、拖动和滚动；`template_form_model.js` 负责默认值、引用和控件推导；`template_form_popups.js` 负责临时原位编辑、菜单及日期／颜色选择器。

持久 UI 不使用 addDOMWidget 或独立 HTML 背景容器。复合控件在加入节点前声明不单独序列化，填写值与快照写入隐藏 form_state；真实端口由原生布局先安排，表单随后通过 computeLayoutSize 声明最小高度并获得剩余可用高度，使底部按钮的绘制和原生命中区域同时延伸到节点底部。临时编辑器使用单独限定的样式，不污染其他节点；移除时清理事件监听、临时编辑器及控件登记。参照同包动态节点的控件生命周期和 node_find 的定位方式。

设计参考 Unity 官方 [PropertyField](https://docs.unity3d.com/6000.0/Documentation/Manual/UIE-uxml-element-PropertyField.html) 的类型派发与标签一致性、[ListView](https://docs.unity3d.com/6000.0/Documentation/Manual/UIE-uxml-element-ListView.html) 的集合管理、[Vector3Field](https://docs.unity3d.com/6000.0/Documentation/Manual/UIE-uxml-element-Vector3Field.html) 的分量输入；实现基于 ComfyUI，并非照搬截图或引入 Unity 运行时。

本地 inspect/pending/submit 接口负责校验、恢复和确认，presence/activate/activated/notification 接口负责前台状态、通知点击和定位恢复；`template_form_notifications.py` 负责 Windows 通知与点击协议，不调用模型 API。验证使用 ComfyUI Python 执行 `tests/test_template_form.py`，Node.js 执行 `tests/test_template_form.cjs`；覆盖控件类型、原生布局、端口不重叠、数组操作、矢量、数据保持、确认复用和旧节点迁移。事件回归直接加载本机前端的 CanvasPointer、getWidgetOnPos 和 processWidgetClick，检查尺寸测量与点击交错、轻微位移经过拖动结束回调时的按钮／折叠响应。真实浏览器画布交互与 Windows 通知仍需页面验收。

### 下拉菜单的开关与外观

类型选择与普通枚举使用同一种带箭头下拉框，不使用 `⋮` 按钮替代。当前为 `null` 时，值列直接显示“无值”下拉框；选为其他基本类型后，显示类型下拉框和对应的值控件。空间充足时值控件在左、类型在右，宽度不足时类型在上、值控件在下一行，行高同步增加，避免挤压或覆盖后续字段。对象和数组的类型下拉框位于标题行，与折叠、条数和移除各自独立。展开菜单与其下拉框等宽，选项均显示中文并勾选当前项。

“无值”只是 JSON `null` 的界面名称，输出仍为 `null`，不等于空字符串或删除字段。“浮点数”对应 Schema 的 `number`，仍按标准允许整数值；它不会把 `number` 改成只能接受小数的规则。类型切换使用该字段的范围限制初始化，例如 `minimum: 1` 的可空整数切换后初始为 `1`，不会继续使用原 `default: null`。

枚举与类型等下拉菜单以 Unity 6 的 **Box Collider → Layer Overrides → Include Layers／Exclude Layers** 为视觉参照：平直外框、深浅交替的灰色单行条目、左侧独立勾选栏和蓝色悬浮／键盘焦点提示。初次展开只标记当前值，不把当前项自动染成悬浮色；触发框右侧使用紧凑的向下三角。

按用户要求，以下两点覆盖 Unity 原版的内容宽度与桌面尺寸行为：

- **菜单与触发框等宽，文字同字号。** 长选项不另撑宽菜单，也不改成多行；超出部分省略，悬浮可查看完整选项文字。
- **菜单尺寸固定在画布坐标系内。** 打开后继续缩放或平移画布，菜单跟随触发框；字体、行高、边框、勾选和整个菜单同步缩放，不能菜单保持屏幕大小而画布缩小。屏幕边缘会调整弹出方向／位置；高度超出窗口时允许内部滚动，不通过压小字号容纳。

鼠标按下起始控件时展开，再次按下同一控件收起，松开不会重新打开。可以点击条目选择，也可以按住起始控件后拖到目标条目再松开选择。点击外部或按 Escape 关闭；方向键及 Home／End 只移动菜单焦点，选择后才修改值并关闭。枚举仍按 Schema 选择一个实际值，不因为视觉参考来自图层掩码而变成多选或位运算。

菜单完成首次定位后才显示，避免短暂出现在页面左上角。触发框和菜单共用本包提供的 Inter 字体，中文使用系统后备字体。字体采用 SIL Open Font License，随包保存 [许可文本](../fonts/Inter-LICENSE.txt)，不依赖用户安装 Unity，也不从远端下载字体。
