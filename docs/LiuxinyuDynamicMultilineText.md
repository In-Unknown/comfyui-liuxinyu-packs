# 动态多块多行字符串

默认提供一块多行文本框；点击添加按钮可以增加更多文本块，每块自带一个输入口和对应的输出口，最多 100 块。

## 输入

| 参数 | 描述 | 数据类型 | 必需 |
| --- | --- | --- | --- |
| `文本1`、`文本2`…… | 各文本块的上游输入；连接时输出上游字符串，未连接时输出框内文字；仅点击添加按钮增加文本块，最多 100 个 | STRING | 否 |
| `blocks_json` | 内部状态，保存各文本块内容，随工作流保存 | STRING（默认 `[""]`） | 是 |

## 输出

| 输出名称 | 描述 | 数据类型 |
| --- | --- | --- |
| `文本1`～`文本100` | 与各文本块一一对应，输出该块的字符串；普通输出，上游接执行列表时逐项各得一个字符串 | STRING |

## 怎么用

1. 添加节点后，节点上有一块多行文本框和“文本1”输出口。
2. 点击添加按钮新增“文本2”，需要更多就继续点。
3. 每块二选一：直接在框里填写文字，或连接上游字符串。
4. 对应的“文本1”“文本2”……输出口分别输出各块内容。

每路互相独立：连接了输入时输出上游字符串，没连接时输出框内文字。例如只在“文本1”框里填 `产品A`、把上游字符串 `红色` 接到“文本2”，两个输出依次为 `产品A` 和 `红色`。

文本内容随工作流一起保存，重新打开不用重填。

输入接到上游后，该块多行编辑区域收起，原来的标题／端口行保留，节点自动收紧高度；不会再为该块增加第二行空白。断开后恢复原文字。各块独立判断，新添加的文本块同样适用，详见[多行输入连接后收起](MultilineCollapse.md)。

## 输出口

节点内部固定保留 100 个输出口位置，界面只显示当前块数对应的输出口；增加块后新输出口出现，已有连线不受影响。

## 调整显示顺序

选中节点，把鼠标悬浮在输入端口或标题文字上，按 `↑` / `↓` 与相邻输入交换。标题、圆点和编辑框作为完整文本块一起移动，添加按钮仍在所有文本块下面。例如输入显示从 `文本1、文本2、文本3` 改成 `文本2、文本1、文本3`，各块内容和已有连线不变。

未单独排序输出时，输出默认对齐自己的文本块。悬浮右侧输出并按方向键，可独立交换输出位置；会保留各块原有的行间距，不把其他输出都挤到顶部。屏幕上下顺序不会重新编号：`字符串2` 始终输出原来的文本2。

已连接文本块只移动标题／端口行，断开后在当前位置恢复编辑框。新增文本块和保存重开后仍保持排序，隐藏的内部存储控件不额外占一行。详见[端口显示排序](PortOrder.md)。

交换端口不会缩窄正文编辑框。输出标签占用标题行，与相邻编辑框仅边缘相接时不作遮挡处理；每块仍保留原有编辑宽度和固定编辑高度。自动整理也按各块实际高度计算输出行，包含已连接后收起的文本块，不把这些输出按普通短端口的间距挤到一起。

## 常见问题

- 最多 100 块。
- 各块是相互独立的字符串。要把多块收成一个字符串数组，接[组装字符串为字符串数组](LiuxinyuStringArrayBuild.md)；要拼成一段文字，接[字符串拼接](LiuxinyuStringConcatenate.md)。
- 保存的文本块数据损坏时，节点报错“文本块必须为包含 1 至 100 个字符串的数组。”，此时检查工作流文件或删除重建本节点。
