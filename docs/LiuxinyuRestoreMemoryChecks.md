# 恢复内存检查和回收

等待全部已连接输入完成后，恢复**当前运行任务**正常的逐步 RAM 检查和回收。恢复节点本次执行结束即进入原有检查路径，不强制清空缓存。

- 无配置项，至少连接一项输入；输入输出按编号对应，原样传递。
- 各对端口类型跟随对应输入，按连接自动增长，没有固定数量上限。
- 可作为终点：输出不再连接任何节点，也会执行恢复。
- 多分支需要全部完成后再恢复时，将各分支的结果接入本节点。只接一条分支不会等待其他独立分支。
- 不需要和“当前忽略内存检查和回收”逐口配对，端口数量可以不同。
- 没执行过忽略节点时，本节点保持检查开启；非 RAM 压力缓存模式下不切换缓存模式。
- 恢复之后尚未结束的循环子图结果收尾，同样会正常检查内存。

需要本地核心配套的动态端口及任务内存控制接口。节点 ID：`LiuxinyuRestoreMemoryChecks`。范围说明见[当前忽略内存检查和回收](LiuxinyuIgnoreMemoryChecks.md)。
