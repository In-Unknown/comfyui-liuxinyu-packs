# 右键菜单顺序与来源标签

在经典画布的右键菜单中，统一按配置排列本包选项，并以小号灰蓝色 `liuxinyu` 标明来源。沿用原生底色、选项文字、悬浮和禁用效果，无需添加节点或设置开关。各功能的加载先后不影响本包选项之间的显示顺序。

## 入口与操作

更新前端脚本后按 `Ctrl+F5` 刷新页面，不需要重启后端。

| 菜单选项 | 出现位置与条件 | 对应说明 |
| --- | --- | --- |
| `画布背景…` | 经典画布空白处右键；正在恢复或读取图片时暂时禁用 | [画布图片背景](CanvasBackground.md) |
| `整理节点` | 选择至少两个节点后，右键节点或画布空白处；实际整理支持 2～40 个节点 | [整理节点](GraphLayout.md) |
| `视窗回归原点` | 画布空白处或节点上右键，无需选择节点 | [视窗回归原点](ViewportOrigin.md) |
| `检查/同步后端工作流文件` | 画布空白处右键，文件同步机制初始化完成后出现 | [工作流文件变动提示](WorkflowFileSync.md) |
| `查看未保存差异` | 画布空白处右键 | [工作流文件变动提示](WorkflowFileSync.md) |

## 输入与输出

这是自动生效的前端功能，没有节点输入口、输出口或画布控件参数。读取包内 `menu_order.js` 的顺序配置，打开菜单时收集当前符合显示条件的选项，统一排序并标记来源；不产生执行数据，不往工作流或浏览器缓存保存顺序。

## 显示示例

选中多个节点，在画布空白处右键，初始化完成后的本包选项按以下顺序显示：

```text
原生菜单选项
────────────────────────────────
画布背景…                 liuxinyu
整理节点                   liuxinyu
视窗回归原点               liuxinyu
检查/同步后端工作流文件     liuxinyu
查看未保存差异             liuxinyu
```

条件不满足的选项跳过，其余选项保持相对顺序。例如没有选中多个节点时不显示“整理节点”；节点右键中只显示符合该入口的“整理节点”和“视窗回归原点”。“计算中”“读取中”等动态文字与禁用状态不会改变位置。直接点击原选项文字或同一行的标签区域，即执行原来的操作。

## 统一修改菜单顺序

编辑包根目录的 [`menu_order.js`](../menu_order.js)，在 `MENU_ORDER` 中上下调整稳定 ID：

```javascript
export const MENU_ORDER = Object.freeze([
  "canvas-background", // 画布背景
  "graph-layout", // 整理节点
  "viewport-origin", // 视窗回归原点
  "workflow-sync", // 检查/同步后端工作流文件
  "workflow-differences", // 查看未保存差异
]);
```

例如想把“视窗回归原点”放到最前面，就把 `"viewport-origin"` 移到数组首行，保存文件并刷新页面。空白处和节点右键使用同一顺序表，再按各自的显示条件筛选。仅改顺序不需要修改各功能文件或重启后端；与包一起复制或更新到另一台电脑后也使用同一配置。

ID 不随显示文字、翻译或忙碌状态变化。顺序表中尚未注册的 ID 会跳过；新增功能若忘记列入表，则按 ID 的固定字符顺序追加在已配置项后面，不采用加载先后顺序。移除配置中的 ID 不表示禁用该功能。

## 分组与主题

- 每一条本包选项右侧都显示来源，包括连续排列的选项，逐项明确归属。
- 本包选项与其他选项的边界使用细分隔线；已有原生分隔线的地方不再叠加一条。
- 标签颜色混合当前文字色与灰蓝色，以适应明暗主题；不用醒目的整行底色。禁用时继承原生禁用效果。
- 仅标记本包明确创建的上述菜单项，不通过名称猜测其他插件或原生选项的来源。节点内部按钮、文件列表菜单等其他入口不在本次范围内。
- 本包选项由一个公共入口一次性提供，内部顺序固定；原生与其他插件选项仍按 ComfyUI 自己的机制排列，不修改它们之间的顺序。

## 常见问题

| 现象 | 说明或处理 |
| --- | --- |
| 没有“整理节点” | 先选择至少两个节点，再打开节点或画布菜单；端口自己的菜单不是普通节点菜单 |
| 刷新后仍没有标签 | 使用 `Ctrl+F5` 重新加载前端资源；本功能适用于原生经典画布菜单，其他扩展替换菜单渲染时需另行适配 |
| 改了菜单文字后顺序是否改变 | 不会；排序依据稳定 ID，不依赖显示文字 |
| 新增选项出现在本包选项末尾 | 将它的 ID 加入 `menu_order.js` 中需要的位置，再刷新页面 |

## 开发与验证

`menu_source.js` 沿用现有扩展加载方式，统一提供 `getCanvasMenuItems` / `getNodeMenuItems`，并安装来源样式。各功能使用 `registerMenuItem` 注册菜单工厂；打开菜单时才计算选择状态、可用性及文字，再按照独立的 `menu_order.js` 输出。使用原生 `className` 和 CSS 相邻选择器，不替换原生菜单构造器，也不靠页面扫描移动已绘制的菜单。

### 新增菜单项

1. 在 `menu_order.js` 的目标位置加入唯一稳定 ID，例如 `"example-action"`。
2. 在功能脚本中导入并注册工厂：

```javascript
import { registerMenuItem } from "./menu_source.js";

registerMenuItem("example-action", {
  canvas: () => ({ content: "示例操作", callback: () => runExample() }),
  node: (node) => node ? { content: "示例操作", callback: () => runExample(node) } : null,
});
```

示例中的 `runExample` 由该功能自己实现。只支持某一个入口时，省略另一个工厂；当前不应显示时返回 `null`。菜单工厂必须同步返回单个原生菜单项，异步操作放入点击回调中。公共入口转交 ComfyUI 原来的参数，保留回调、禁用状态和已有类名，统一加来源标签。

同一个 ID 重复注册会明确报错，避免后加载的功能覆盖先加载的功能。功能自己的其他生命周期仍可用 `app.registerExtension` 注册，但本包菜单项不再通过各功能的 `getCanvasMenuItems` / `getNodeMenuItems` 分散提供。

命令行验证：

```powershell
node tests/test_menu_order.cjs
node tests/test_graph_layout.cjs
node tests/test_workflow_file_sync.cjs
node tests/test_canvas_background.cjs <当前前端 settingStore-*.js 的完整路径>
```

顺序测试覆盖五个 ID 的全部 120 种注册顺序、两个入口、配置改序、延后注册、隐藏项、忙碌文字、未配置 ID、重复注册和实际视窗回归回调；其他回归覆盖样式只安装一次、原整理、文件同步和背景功能。最终标签颜色、分隔线和点击观感由页面验收。
