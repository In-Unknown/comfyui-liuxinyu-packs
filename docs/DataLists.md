# 数组、执行列表与图片批次

这三种形式都能装多个东西，但会影响下游执行几次、何时合并内容。插口都写着 IMAGE，也不能据此判断它传递单张、批次还是执行列表。

| 形式 | 怎样理解 | 常见来源 |
| --- | --- | --- |
| 数组 ARRAY | 一个盒子，里面是 `[0.1,0.2]` 等元素；整个盒子作为一个值传递 | 多个数值组成数组；“完整字面量”输出 |
| 执行列表 | ComfyUI 给下游安排的多项输入；普通节点通常每次收到一项 | 匹配路径、切分结果、分包回归输出 |
| 图片批次 IMAGE | 一个张量内部包含多张相同宽高和通道数的图片 | 一次生成多张图、从路径加载图像批次 |

执行列表中也可以放多个图片批次，各批次尺寸可以不同。“执行列表有 2 项，每项含 4 张图”总计 8 张图，但对分包起点来说是 **2 包**。

## 下游决定是否收取整个列表

### 为什么执行列表的端口可能写 ANY

`ANY` 表示每个执行项允许的值类型，不表示是否为执行列表。例如“将任意数组转为执行列表”的输出类型是 ANY，但它明确声明输出执行列表；每项可以是字符串、字典、图片，也可以是完整数组。STRING、DICT、ARRAY、IMAGE 同样可以具有执行列表语义，不能只看类型名判断。

分包口会在运行时检查列表来源：声明输出执行列表的节点，以及普通节点逐项处理该列表得到的结果可以接入。收集节点将列表合成完整数组后，要再次逐项分包就必须显式转换。当前前端没有阻止所有普通数组连线；画布能连上不等于满足分包条件，运行时会给出转换提示，不会自动添加转换节点。

### 普通处理与整体收集

普通节点通常逐项运行；一些节点专门接收完整列表，例如“从批次列表拼接图片”会收集收到的图片批次进行拼接。不能把“上游输出列表”理解为“所有下游都会分别处理并保留分组”。

多个目录的图片混在一起通常发生在这里：目录逐个加载，但拼接把产生的列表整体收集。要保持目录范围，可将“匹配 → 加载 → 拼接”放进 [分包子流](packet_tasks.md)。

## 两个输出的区别

在“字符串转为字面量”填 `[0.1,0.2]`：

- 第一个“字面量”输出：普通下游依次得到 `0.1`、`0.2`。
- 第二个“完整字面量”输出：下游一次得到完整数组 `[0.1,0.2]`。

最终切分需要全部切点，所以应接第二个输出。

## 分包、重复与多输入

- 分包起点只接受执行列表，每项为一包，不拆执行项内部的数组或 IMAGE 批次。普通数组先接“将任意数组转为执行列表”；普通单值先接“批量任意为执行列表”（次数 1）。
- 重复节点把输入整体重复 N 次：4 张图片的批次重复 3 次，得到 3 项，每项仍有 4 张图。
- 回归将每包的执行列表依次追加；需要保留分组时，先在包内合并或打包成一个完整值。
- 多个普通输入都是执行列表时，ComfyUI 通常按位置配对，短列表复用最后一项，不自动求所有组合。主动收取完整列表的节点可能有自己的规则，以节点说明为准。
