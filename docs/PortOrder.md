# 节点端口显示排序

需要同时整理一组节点的位置与端口时，可使用[整理节点](GraphLayout.md)：框选后右键操作，与本页手动排序共用保存属性。

在单个节点上分别调整输入口和输出口的上下位置，让相邻节点的连接顺序更接近，减少交叉线。排序记录随工作流保存，刷新页面、重新打开文件或换电脑后可以恢复。

这是节点包提供的前端功能，不需要新增节点，也不需要运行工作流。适用于当前经典画布中使用标准端口布局的节点，包括其他包的普通节点、子图节点及子图内普通节点。

## 入口与操作

**选中节点，将鼠标悬浮在端口圆点或文字上，等端口按原生效果高亮、变大后，按键盘 ↑ 或 ↓。** 无需右键菜单或排序窗口。

子图内部的“图输入 / 图输出”边界面板无需选中：直接悬浮端口后按 ↑ / ↓。边界与外部子图节点的对应端口双向同步，详见下方“子图内外双向同步”。

| 操作 | 结果 |
| --- | --- |
| 选中节点并悬浮在端口圆点或文字上 | 显示“↑ / ↓ 与相邻端口交换”的提示；同侧至少有两个端口时可用 |
| 按 `↑` | 与画布上同侧紧邻的上一个端口交换；已在最上方则不变 |
| 按 `↓` | 与画布上同侧紧邻的下一个端口交换；已在最下方则不变 |
| 交换后移动鼠标到需要继续调整的端口 | 下一次按键调整此时悬浮的端口 |
| 保存工作流 | 将当前节点的显示顺序写入工作流文件 |
| 使用 ComfyUI 原生撤销、重做 | 恢复相应编辑步骤中的顺序 |

提示和快捷键直接跟随 ComfyUI 原生端口高亮；鼠标位于端口文字区域而使圆点高亮时同样有效。松开鼠标完成选中后会刷新提示，无需再移动一次鼠标。

每次按下只交换一次，按住箭头键不连续交换，避免鼠标不动时两个端口反复换位。交换后高亮更新为鼠标当前位置下的端口；若要继续移动刚才的端口，把鼠标移到它的新位置再按键。

上下相邻关系依据端口的实际显示位置，包括原生位于参数控件旁的端口，不直接使用内部编号判断。输入只与输入交换，输出只与输出交换。多选节点时，只调整鼠标悬浮的那个节点。

在文本框、下拉框或可编辑区域中输入时，方向键保持原用途。按着 Ctrl、Alt、Shift 或系统修饰键、拖动连线或按着鼠标按钮时不触发排序。普通节点未选中、鼠标在未高亮的节点正文上、节点折叠或画布只读时，也不触发；子图边界面板免选中。

## 输入与输出

本功能没有执行输入、执行输出或后端计算，不改变节点输入输出的数据类型、数组结构、执行列表语义或返回值。

| 对象 | 排序后的行为 |
| --- | --- |
| 输入口 | 圆点、标签、点击区域和连线落点一起移动；仍连接原输入参数 |
| 输出口 | 圆点、标签、点击区域和连线落点一起移动；仍代表原返回项 |
| 节点连线 | 保留原连接关系，不断线重接，不替换连线编号 |
| 普通节点实例 | 只修改所操作的节点，其他同类型普通节点不受影响 |
| 子图接口 | 内部边界与外部对应端口双向同步；同一子图定义的多个实例共用接口显示顺序 |
| 工作流文件 | 保存当前节点的显示顺序设置；实际端口数组与执行索引保持不变 |

## 使用示例：让两侧连线对齐

假设节点 A 从上到下输出“报错信息”“校验通过”，节点 B 从上到下输入“校验通过”“报错信息”。当前两条连线发生交叉。

1. 单击节点 A，将它选中。
2. 把鼠标移到“校验通过”的输出圆点上，等它高亮。
3. 按一次 `↑`。A 的输出立即显示为“校验通过”“报错信息”，与 B 对齐。
4. 保存工作流。重新打开后，A 保持这个显示顺序。

假设 A 原本返回：

```python
("第 1 项的 'count' 必须是 integer。", False)
```

排序后其返回值仍完全相同。顶部的“校验通过”仍对应原输出索引 `1`，底部的“报错信息”仍对应原输出索引 `0`。向顶部端口新建连线时，也会连接索引 `1`，不会把错误文字接到布尔输入。

## 带参数控件的输入口

**输入口与关联的输入框作为一整行一起交换位置。** 普通端口按端口行占位；字符串、数值、下拉框等输入口连同对应控件一起移动，多行文本框按实际高度占位。不会把圆点移到上方、却将输入框留在下方，也不会额外重复显示一份控件名称。

“动态多块多行字符串”的一块包含独立标题行和多行编辑框，两者作为完整一组移动。例如将“文本2”上移到“文本1”之前，显示顺序变成 2、1、3、4；每块的标题、圆点和编辑框保持配对，不会把所有标题移到节点底部。已连接的块只保留标题／端口行，断开后编辑框在该块当前的位置恢复。

默认情况下，这类文本块的输出跟随对应标题行；如果单独调整输出顺序，则使用各块原有的输出行位置交换，输入块不动，其他输出不会全部挤成顶部的连续小行。输入和输出的显示顺序可以独立保存，文本编号和真实配对关系不变。

例如原先从上到下为“绝对路径”端口、“相对路径”文本框：悬浮“相对路径”并按 `↑` 后，整个“相对路径”文本框连同左侧端口成为第一行，“绝对路径”端口成为第二行。框内内容、上游连线、控件与参数的对应关系均保持不变。

配套控件随所属输入一起移动。例如“保存图像到绝对路径”的“文件夹”输入与“选择文件夹”按钮组成一组：将“图片”下移到“文件夹”之后，顺序是“文件夹 → 选择文件夹 → 图片 → 文件名 → 覆盖已有文件”。文件、目录选择按钮以及声明了关联关系的原生辅助控件同样按组处理；动态文本的“添加下一个输入框”等整节点操作按钮继续留在底部。

没有所属输入的独立控件继续按原顺序放在输入行之后。只有输入框与右侧输出标签的区域确实重叠，才给标签留出宽度；上下两块仅边缘相接不算遮挡，不会缩窄动态文本的编辑框。输入、输出独立排序均重新核对标签宽度，恢复原布局时恢复原控件宽度。只调整输出顺序时，输入侧位置保持原生布局。

某一侧只有一个端口时，该侧没有可交换的相邻端口，不启用自定义重排。旧整理版本可能给“整数”等节点保存了单输入、单输出的排序记录；这些记录现在自动忽略，保持原生控件位置和宽度。刷新页面即可恢复，不需要删除节点或手动编辑工作流。另一侧有多个端口时仍可正常排序；动态节点中随输入行移动的输出锚点仍遵循节点自身的联动规则。

原本把控件放在最上方的节点，例如“组装键值对”，交换时从原有最上方的输入行开始排列；不会因为节点给普通端口预留了偏移，而把所有输入向下推并留出空白。

排序不改变控件数组的原始顺序，因此保存时各参数值仍对应原参数。端口、输入框及点击区域一起更新；重新打开工作流后恢复整行布局。节点高度不足时会增高，撤销后可能保留已扩大的高度，可手动缩小。

此功能排序已有端口，不会凭空增加输入，也不将没有端口的控件自动转换为输入口。

适用节点的多行文本输入已连接时，[多行输入收起](MultilineCollapse.md)会把编辑框缩为一行带名称的端口，按这一行的高度参与排序；断开后恢复编辑框，仍跟随该端口的位置。适用于 liuxinyu、harness 节点及子图提升的多行输入。

没有输入端口的节点保持原生控件布局，例如 Note 的文本框仍由 ComfyUI 按节点尺寸分配高度。旧工作流中的空输入排序记录不会启动控件重排；反复布局不会因此累积高度。自动整理也不再给没有端口的 Note 写入空排序记录。

## 动态端口与类型变化

- 排序记录使用稳定端口 ID；无 ID 时使用内部名称及同名端口的出现序号，不以中文显示标签或数据类型作为身份。
- 新增动态端口追加到当前侧的显示末尾，其他已存在端口保持顺序。
- 端口暂时消失时跳过该项；如果同一身份的端口重新出现，可恢复原有位置。
- 类型或显示标签改变，不会使端口因为“改名”而丢失排序。若节点实际改了内部名称且没有稳定 ID，则作为新端口处理。
- 虚拟连接删除已全部断开的通道时，会将已有显示顺序按保留的端口迁移到新编号。传入端和各个传出端分别保留自己的排序，不会因为重新编号把灰色备用口错认成原数据口。
- 多个端口内部名称完全相同时，依靠它们在原始数组中的同名出现次序区分；删除其中一项后，无法保证识别剩余同名端口原先的独立身份。
- 再次交换某一侧端口时，重新记录该侧当前存在的端口顺序，不继续保留已不存在的旧项；另一侧的排序设置不变。

分包、虚拟连接等节点仍按原来的通道编号和输入输出索引配对。移动“输出 2”的显示位置不会把它变成“输出 1”；排序不会更改这些节点原有的动态增删、类型同步或执行逻辑。

## 保存、复制与撤销

普通节点顺序保存在工作流节点的 `properties.liuxinyu_port_order` 中，包含版本号以及自定义的输入、输出顺序。子图的共享接口顺序保存在子图定义的 `extra.liuxinyu_port_order` 中，使用边界端口的稳定 ID 与外部端口对应；共享设置优先于旧的实例显示偏好。未调整的另一侧保留原布局，内部字段 `null` 表示该侧恢复原生布局。

保存的是显示偏好，普通节点的临时绘制坐标不会替代原有端口坐标写入文件。子图边界沿用原生接口保存当前位置，重新布局时依据共享顺序恢复。撤销到排序前时，普通节点原先指定的自定义端口坐标继续使用。

应用排序使用工作流变更事件，纳入正常编辑记录；复制普通节点时随节点属性复制，复制之后两份普通节点可独立排序。子图实例若仍引用同一子图定义，则继续共用接口顺序；独立的子图定义各自保存。撤销、重做或重新载入工作流后按恢复的属性重新布局。

文件必须正常保存，才能带到其他电脑。另一台电脑需要安装含此扩展的节点包并启用扩展；没有扩展时仍按原有逻辑执行，画布使用默认顺序。

## 子图内外双向同步

支持主画布上的子图节点，以及嵌套子图里的普通节点、子图节点和输入输出边界面板。

| 操作位置 | 操作方法 | 同步到哪里 |
| --- | --- | --- |
| 子图内部左侧“图输入”面板 | 不必选中，悬浮圆点或文字后按 ↑ / ↓ | 外部子图节点的输入侧 |
| 子图内部右侧“图输出”面板 | 不必选中，悬浮圆点或文字后按 ↑ / ↓ | 外部子图节点的输出侧 |
| 外部子图节点 | 选中节点，悬浮端口后按 ↑ / ↓ | 内部对应边界面板，以及同一定义的其他外部实例 |
| 边界末尾灰色新增口 | 不参与交换，不显示排序提示 | 始终保留在已有端口之后 |

例如图输出从上到下是“用户提示词”“系统提示词”“结构校验表达式”：

1. 进入子图，直接悬浮“结构校验表达式”，按一次 `↑`。
2. 内部边界和外部子图节点都变成“用户提示词”“结构校验表达式”“系统提示词”。
3. 返回外部，选中子图节点，悬浮“用户提示词”并按 `↓`。
4. 内外同步变成“结构校验表达式”“用户提示词”“系统提示词”；每条线仍传递原来对应的表达式或提示词。
5. 保存工作流。刷新或换电脑打开后，两侧仍采用同一显示顺序。

交换的是整个端口行：圆点、文字、悬浮区域和连线落点一起移动。边界输入输出数组、外部端口数组、端口 ID 与连线索引都不重排；从新位置拖出连线仍连接原来的端口。重命名端口保留稳定 ID 时，排序位置不变；新增端口放在已有显示顺序之后、灰色新增口之前，删除端口时跳过已不存在的项。

同一子图定义的多个外部实例同步接口顺序，即使实例位于不同嵌套层。不同定义的子图互不影响，子图内部普通业务节点的位置与端口顺序也不受接口排序影响。使用“整理节点”调整外部子图端口时同样同步，候选试排后会还原共享顺序与受影响实例，确认应用时才保留结果。

## 支持范围

当前适配经典 LiteGraph 画布的端口布局与绘制接口。启用 **Vue Nodes / Nodes 2.0** 时，快捷键与悬浮提示不启用，已有排序设置保留但暂停显示。返回经典画布后恢复应用。

自行接管绘制、命中测试或布局的第三方特殊节点，需要另外核对其接口；不能把某个特殊节点的自绘区域等同于标准端口。

## 常见问题

| 现象 | 说明或处理方法 |
| --- | --- |
| 悬浮后没有提示或按键不生效 | 先刷新前端，选中节点，再悬浮在端口圆点或文字上；确认同侧至少有两个端口，且使用经典画布和标准端口布局。 |
| 子图边界无法选中 | 无需选中，直接悬浮已有端口并按 ↑ / ↓；灰色新增口不参与排序。 |
| 正在编辑文字，方向键没有调整端口 | 正常行为；结束文本编辑、点击画布选中节点后再操作。 |
| 应用后节点变高 | 完整控件行需要按实际高度占位，尤其是多行文本框；仅保存、刷新不应重复增加高度。 |
| 旧版保存刷新后节点长一截 | 更新并刷新前端。加载时先同步原生端口布局缓存，再安排弹性文本框，避免端口空间重复计入高度。已经保存的较大尺寸可手动缩回后保存，不猜测原来的高度。 |
| 旧版整理后 Note 持续变长 | 更新并刷新前端后停止增长，已有空排序记录无需手动删除。已经增大的尺寸不会自动还原，可拖动边缘缩回合适高度后保存；Note 文字不受影响。 |
| 顶部端口不再是索引 0 | 这是显示排序的预期结果。数据仍按端口名称和原索引对应，不按屏幕上的上下位置重新编号。 |
| 换电脑后顺序未显示 | 确认保存了工作流文件，并在另一台电脑安装和启用新版扩展。 |
| 动态新增端口出现在底部 | 新端口默认追加，可悬浮该端口并按 ↑ 调整。 |
| 撤销排序后节点仍较高 | 顺序已恢复，可手动调整节点高度。 |
| 排序后仍有交叉线 | 本功能提供端口排序，不自动移动节点或添加转接点；复杂布局仍需结合节点位置调整。 |

## 开发与验证

实现位于 [`port_order.js`](../port_order.js)，通过包现有 `WEB_DIRECTORY` 自动加载；不新增 Python 节点、不改后端执行规则，也不改工作流文件中的业务配置。

命令行验证：

```powershell
node tests/test_port_order.cjs
```

还可向测试传入当前前端的 `settingStore-*.js` bundle 路径，直接验证安装版本中的坐标计算和点击边界函数。测试覆盖端口身份与连线不变、临时坐标不落盘、保存重载、动态端口、控件与端口整行移动、多行控件高度及点击区域、节点移动与缩放尺寸、折叠、子图安装、键盘交换、悬浮提示，以及编辑文字和拖动时不触发排序的检查。

Note 回归使用原生控件布局和弹性空间分配函数，验证带旧空排序记录的弹性文本框连续布局 100 次高度不变，以及手动缩小后尺寸稳定；同时覆盖没有端口和只有输出端口的节点。

加载时序回归刻意清空原生具体端口缓存，模拟工作流配置阶段先触发布局的情况；使用安装版原生布局与两种扩展安装顺序，连续加载四次，验证保存高度、弹性文本框内容和控件边界保持稳定。另以“快速设计主图”的 9、19、61 在独立无界面页面重复加载核对实际尺寸；不修改用户正在编辑的画布。

子图回归直接使用安装版本的边界布局、输入输出锚点和文字命中函数，覆盖免选中操作、内外双向同步、同一定义的嵌套实例、新实例、保存恢复与撤销状态、重命名、动态增删、灰色新增口、原连线身份保留，以及连续布局 100 次尺寸稳定。自动整理回归还检查候选试排后共享顺序与其他实例的尺寸、位置和属性完整恢复。

模拟测试不替代页面视觉验收。更新后先保存页面中的编辑，再刷新浏览器；本功能只改前端，不需要为它重启后端。

动态文本块回归同时加载实际动态文本、输入收起和排序扩展，覆盖六种注册顺序、标题／编辑框整体交换、保留非等距输出锚点、部分连接、断开恢复、混合排序、新增块、保存恢复及重复布局尺寸稳定。虚拟连接回归覆盖一个传入端与多个分别排序的传出端，删除中间、末尾、首个剩余通道时保留显示身份和真实连线。

尺寸与控件归属回归检查各编辑框的实际 `width`，不能只检查端口纵坐标；使用真实文件选择扩展验证目录／文件按钮与参数成组移动、两种注册顺序、连续交换、节点缩放尺寸和恢复布局，另覆盖原生关联辅助控件及键值对顶部行。自动整理快照与后端使用同一输入起点、控件组高度和输出行位置，动态文本的输出行随输入块高度计算。
