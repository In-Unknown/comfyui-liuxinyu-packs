# 回归分包子流条件

与“分包执行子流回归”成对使用。这是每个包的处理终点：等本包所有接入的结果准备好，再通知起点发送下一包；全部包完成后输出汇总结果。

## 输入

| 参数 | 描述 | 数据类型 | 必需 |
|---|---|---|---|
| `分包回归条件` | 直接连接配对“分包执行子流回归”节点的同名输出，不能经过其他处理节点 | LIUXINYU_PACKET_CONDITION | 是 |
| `输入 1`…`输入 100` | 当前包的处理结果，可以是图片、文字、数值等；本节点等待全部已连接输入完成后再通知起点发下一包。端口随连接增加，最多 100 个，类型跟随接入的处理结果 | ANY | 否 |

## 输出

| 输出名称 | 描述 | 数据类型 |
|---|---|---|
| `输出 1`…`输出 100` | 与同编号输入对应（输入 1 对应输出 1），全部包完成后按包顺序汇总的结果。执行列表，下游逐项处理 | ANY |

输入与对应输出的类型跟随当前接入的处理结果，同时显示如「输入 1 · IMAGE」「输出 1 · IMAGE」。实际端口也会限制类型，不只是改标签；类型会继续传递给后面的跳回点和条件回归。要改接不同类型，可先断开原输入再连接。执行列表仍保留元素类型，例如图片执行列表输出为 IMAGE；上游本身是任意类型时仍保留任意。

与起点输入的类型可以不同。两条分支分别接入输入1、输入2时，本节点会等待两条分支都完成。

## 最简单的接法

```text
目录列表 → 分包执行子流回归 → 匹配图片 → 加载图片 → 拼接图片 → 本节点 → 预览
              分包回归条件 ─────────────────────────→ 本节点的分包回归条件
```

以两个目录为例，第一个目录先完成图片拼接，再处理第二个目录；最终本节点输出两张长图。拼接要放在本节点之前，否则回归之后再统一拼接仍可能合并成一张。

## 汇总会不会保留组别

- 每包输入一张图片：最终是多张图片的执行列表。
- 每包输入多个执行项：最终依次追加，例如第一包 A1、A2，第二包 B1、B2，得到 A1、A2、B1、B2。
- 每包输入一个完整数组或字典：保留这个完整值，结果仍可以按包区分。

如果希望每包只有一个结果，应在包内先合并。普通下游通常逐项处理回归输出；“从批次列表拼接图片”等收取整个列表的节点会再次合并。

## 轮次、嵌套与常见错误

起点的“当前轮次”可接本节点一个空输入，全部完成后相应输出为 1、2、3……。空输入数组产生零包，汇总为空列表。

嵌套顺序应为 `A起点 → B起点 → B回归 → A回归`。A/B 条件各自直接配对，不支持交叉闭合。

每条需要等待的分支都应接回本节点，不能绕过回归形成外部输出；没有数据输出口的保存或预览节点通常放在本节点之后。某包报错或取消时，后面的包停止，已经产生的永久保存文件不会自动撤销。

完整的多目录接线、数据配对和使用场景见 [分包执行子流回归](LiuxinyuPacketStart.md)。
