# 分包跳回

把执行列表中的每个执行项作为一个包，依次执行同一段子流；每次进入子流时，同时提供本包内容和上一轮返回的完整数据。它与[携包条件回归](LiuxinyuPacketReturnEnd.md)配对，用于需要一边遍历、一边更新结果的流程。

节点 ID：`LiuxinyuPacketReturnStart`；分类：`liuxinyu/流程控制`。

## 什么时候使用

| 需要完成的事 | 选择方式 |
| --- | --- |
| 每包处理后，要把新的总结果交给下一包继续使用 | 使用本节点和携包条件回归 |
| 每包独立处理，最后收集各包的输出 | 使用[分包执行子流回归](LiuxinyuPacketStart.md)及其配对回归节点 |
| 没有待遍历的包，只根据条件反复更新同一份数据 | 使用[跳回点](LiuxinyuReturnPoint.md)及条件回归 |

分包数据必须是执行列表，其执行项可以是文件任务、数值、对象、路径、图片或其他值。携带数据可以是数组、字典、文本、数字或图片批次。节点只负责迭代和传递，实际如何修改数据，由循环中的节点决定。

## 输入

| 参数 | 描述 | 数据类型 | 必需 |
| --- | --- | --- | --- |
| `被处理数据1、2…` | 一个完整值；第一轮原样提供，后续轮次使用回归节点同编号返回的新值，不拆数组 | ANY | 至少一路 |
| `分包数据1、2…` | 只接受执行列表，每个执行项为一包。普通数组先经“将任意数组转为执行列表”；普通单值先经“批量任意为执行列表”（次数 1） | ANY（执行列表） | 至少一路 |

两类端口独立增长，使用 ComfyUI 原生 Autogrow；各类最多 100 项，这是当前原生端口模板的限制，不是循环次数限制。新增输入后，输出按编号出现。多路待分包输入不要求与携带数据数量相同。

**数组必须显式转换才能分包：** `[1,2,3]` → “将任意数组转为执行列表” → 分包数据，会产生三包；普通数组直连分包口会报错，不会自动拆开或自动插入节点。同一个数组接被处理数据时，始终是一整个数组。`[[1,2],[3]]` 经数组转换节点后得到两包，分别为 `[1,2]` 和 `[3]`，不会递归拆分。

执行列表中只有一个数组执行项时，该数组就是一个包。若要拆它的内部成员，先把它转为需要的执行列表。携带数据每轮必须只有一个执行项；多个执行项先通过[执行列表收集为数组](LiuxinyuCollectExecutionList.md)合为完整数组。

## 输出

| 输出名称 | 描述 | 数据类型 |
| --- | --- | --- |
| `分包回归条件` | 直接接对应携包条件回归的同名输入，用于配对；它不是布尔值 | LIUXINYU_PACKET_RETURN |
| `当前被处理数据1、2…` | 第一轮为初始值，之后为上一轮返回的新值；只为实际已连接的被处理数据提供输出 | ANY（跟随对应输入类型） |
| `当前分包数据1、2…` | 各分包数据输入本轮取到的一个完整执行项；只为实际已连接的分包数据提供输出 | ANY |
| `当前轮次数` | 始终位于最后，从1开始，每次循环加1，包括耗尽后的重复轮次 | INT |

输入排列为全部“被处理数据”在前、全部“分包数据”在后，两组各自保留供继续接线的空闲输入。**空闲输入不产生数据输出。** 两组的输出数量分别计算，不因为接了第二路被处理数据就额外生成第二路分包输出。

例如，接入2路被处理数据、1路分包数据时，输出依次是：

```text
分包回归条件
当前被处理数据1
当前被处理数据2
当前分包数据1
当前轮次数
```

未连接任何数据时，只显示分包回归条件和当前轮次数。增加、断开输入时，对应数据输出同步变化；保留下来的端口连线跟随该端口移动。没有对应输入的数据输出会被移除，其连线也会断开。前端保存和后端执行使用同一套紧凑顺序，无需另外转换轮次数端口编号。

包序号和“还有下一包”不再作为单独输出；回归节点仍在内部利用分包进度计算继续条件。

## 多路分包、空包与耗尽

- 多路待分包输入按最长一路确定新包总数；较短的非空输入重复最后一项。例如两个数组分别转为执行列表后，`[1,2,3]` 与 `["A","B"]` 得到 `(1,A)`、`(2,B)`、`(3,B)`。
- 所有待分包输入都是空执行列表时，跳过整个循环体，由回归节点直接输出被处理数据。即使所选运算会得到 true，也不进入循环，因为根本没有最后一包可取。
- 一路为空、另一路非空时会报错：空列没有可复用的最后一项。请补充这一路或断开它。
- 非空输入先执行第一轮，之后才判断是否继续。
- 包耗尽而回归运算仍为 true 时，重复最后一包。携带数据继续更新，轮次继续增加，使用的仍是最后一包。

## 完整例子：逐包追加到结果数组

将 `["A","B","C"]` 接“将任意数组转为执行列表”的“数组”，把“执行列表”输出接分包数据1；被处理数据1 直接接完整数组 `[]`。

1. 分包回归条件直接连接“携包条件回归”。
2. 当前被处理数据1 接“插入字段到字典或者js对象”的“对象或数组”；挂载访问语句留空，表示根数组。
3. 当前分包数据1 接插入节点的“新增值”。根为数组，因此每轮追加一个完整成员。
4. 插入节点的“完整对象或数组”接回归节点的“处理完成数据1”。
5. 回归节点选“与”，输入布尔设为 true；处理完成数据1 接下游。

| 当前轮次数 | 当前分包数据1 | 当前被处理数据1 | 本轮插入后的数据 | 内部还有下一包 |
| --- | --- | --- | --- | --- |
| 1 | `"A"` | `[]` | `["A"]` | true |
| 2 | `"B"` | `["A"]` | `["A","B"]` | true |
| 3 | `"C"` | `["A","B"]` | `["A","B","C"]` | false |

最终只输出一个完整数组 `["A","B","C"]`。若只把初始 `[]` 直接接插入节点，每轮都会从空数组重新开始；应连接本节点的“当前被处理数据”输出，才能接续上一轮结果。

## 给多个位置逐次增加字段

待分包数组也可以是：

```json
[
  {"path":"[0]","fields":{"owner":"Alice"}},
  {"path":"[1]","fields":{"owner":"Bob"}}
]
```

将上述方案数组先接“将任意数组转为执行列表”，再接分包数据1。将 `[{"id":"A"},{"id":"B"}]` 接入被处理数据1。从当前分包数据1分别读取 `path` 和 `fields`，接单次插入节点的挂载访问语句和新增值；当前被处理数据1接插入节点的“对象或数组”。每次插入后的完整结果再回归。最终得到 `[{"id":"A","owner":"Alice"},{"id":"B","owner":"Bob"}]`。

若要求所有目标恰好处理一次，应在进入循环前检查方案是否重复、是否遗漏。这是工作流的数据规则，不由循环节点推断。不要在循环中重排原数组后继续使用旧路径。


## 执行列表的识别与旧工作流迁移

分包口只消费执行列表。直接声明输出执行列表的节点，以及普通节点逐项处理该列表后得到的结果，都可接入；只有一项时仍是执行列表。收集节点把列表合成完整数组后，必须重新转换才能分包。不能仅凭 `ARRAY` / `STRING` / `IMAGE` 类型名或方括号外观判断。

| 原先的接法或目标 | 现在的接法 |
| --- | --- |
| 普通数组直接接分包口 | 数组 → 将任意数组转为执行列表 → 分包口 |
| 普通单值直接作为一包或固定配对值 | 单值 → 批量任意为执行列表（次数 1）→ 分包口 |
| 将整个数组保留为一包 | 数组 → 批量任意为执行列表（次数 1）→ 分包口 |
| 执行列表中每项本来就是数组 | 直接接分包口，每项数组保持完整 |

例如数组 `[10,20]` 经“将任意数组转为执行列表”后执行两包：`10`、`20`；经“批量任意为执行列表”（次数 1）后执行一包：`[10,20]`。普通数组直接连入时错误信息会指出分包输入，并提示这两种转换方法；不会运行循环体。更新代码后需重启后端并刷新前端，旧工作流须按此补齐转换节点。

## 配对、类型与错误

被处理数据和回归的数据必须同编号对应，数量与实际类型保持一致；数组可以增长、字典可以增加字段，但数组不能在某轮变成字符串。图片等张量要求张量维数一致，尺寸可变化。未连接输入却使用其输出、回归缺项、多项执行列表、错误配对都会报错。

循环体内的结果必须经过配对回归节点后才能进入外部下游。支持正确闭合的嵌套循环；每层管理自己的包、轮次和携带数据。外层的一包若是数组，内层要拆其成员时必须再接“将任意数组转为执行列表”。不设置隐藏的循环次数上限，持续满足回归条件会一直运行，可用 ComfyUI 的中断操作停止。节点不会保存跨任务的携带数据，也不主动复制或修改传入对象；循环体应使用返回新结果而不原地修改输入的节点。
