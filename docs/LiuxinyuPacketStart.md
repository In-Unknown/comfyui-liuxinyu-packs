# 分包执行子流回归 / 回归分包子流条件

这两个节点成对使用：把输入拆成一个个包，让每个包单独经过同一套处理步骤；前一包处理完成并回归后，再发送下一包。

“子流”就是起点和回归节点之间的一段工作流。最典型的用途是：**一个对象会拆成多个子项，之后又要合并这些子项，而你希望不同对象的子项各自合并。**

## 输入（分包执行子流回归）

| 参数 | 描述 | 数据类型 | 必需 |
|---|---|---|---|
| `输入 1`…`输入 100` | 待分包数据，如目录、图片、数字等。本节点整批收取后拆包：完整数组拆第一层逐项分包，执行列表逐项分包，IMAGE 批次、字典、标量整体为一包；数组元素本身还是数组时不继续递归拆开。包数取最长输入，短的非空数组重复最后一项，单值每包复用。端口随连接增加，最多 100 个 | ANY | 否 |

## 输出（分包执行子流回归）

| 输出名称 | 描述 | 数据类型 |
|---|---|---|
| `分包回归条件` | 直接连接配对“回归分包子流条件”节点的同名输入，不能经过其他节点 | LIUXINYU_PACKET_CONDITION |
| `输出 1`…`输出 100` | 当前包中与同编号输入对应的数据（输出 1 对应输入 1），每包输出一项 | ANY |
| `当前轮次` | 从 1 开始的整数，表示当前是第几包；嵌套时各自计数。数据输出，不会自动在节点上显示进度文字 | INT |

回归节点「回归分包子流条件」的端口见 [回归分包子流条件](LiuxinyuPacketEnd.md)，两节点的配对关系见下表。

## 什么时候需要它

假设有 15 个详情页目录，每个目录有若干张图片，你希望得到 15 张详情页长图。直接把所有目录交给“匹配图片 → 加载图片 → 拼接图片”，可能把各目录的图片都送进同一个拼接列表，最终变成一张大长图。即使节点顺序执行，只要合并前丢失了分组，仍然会发生这个问题。

可以把它理解为做 15 道菜：每道菜的原材料是一包，拆包后只把这一包的材料放进锅里，做好、盛出，再处理下一包。分包节点固定了“这一道菜的处理范围”，让普通处理节点无需理解分组标识。

| 任务 | 建议 |
| --- | --- |
| 多个目录，每个目录内的图片各自拼接 | 适合，每个目录作为一包 |
| 多张长图，各自切块、处理、再拼回一张 | 适合，每张长图作为一包 |
| 多份文档，各自拆段并汇总成一份摘要 | 适合，每份文档作为一包；需要相应文本处理节点 |
| 每张图只独立缩放，没有跨图合并 | 通常直接使用执行列表即可 |
| 希望把所有输入合成同一个结果 | 直接合并即可 |
| 反复修改一个对象，直到结果满足条件才停止 | 不属于本节点的功能；包数由输入决定，没有条件终止和状态迭代 |

如果下游始终携带分组标识，并支持按标识分别合并，也可以不用这对节点。本节点用执行范围来保留归属，便于复用已有普通节点。

## 先分清三种“多个值”

| 输入形式 | 分包行为 |
| --- | --- |
| 完整数组 `["目录A", "目录B"]` | 拆第一层，得到两包 |
| ComfyUI 执行列表中的目录A、目录B | 得到两包 |
| 一个 IMAGE 张量内部含 4 张图片 | **整体是一包，不拆成 4 包** |
| 字典、模型、Latent 或普通数值 | 作为完整值处理 |

数组的元素本身还是数组时，不继续递归拆开。详见 [数组、执行列表与图片批次](DataLists.md)。

## 端口怎么接

| 节点 | 端口 | 用途 |
| --- | --- | --- |
| 起点 | 输入1、输入2…… | 待分包数据，如目录、图片、数字等 |
| 起点 | 输出1、输出2…… | 当前包的对应数据，输出1对应输入1 |
| 起点 | 分包回归条件 | **直接**连接配对回归节点的同名输入 |
| 起点 | 当前轮次 | 从 1 开始的整数，表示当前是第几包 |
| 回归 | 输入1、输入2…… | 本包处理结果；等待全部已连接输入完成后再发下一包 |
| 回归 | 输出1、输出2…… | 所有包完成后，按包顺序汇总的执行列表 |

连接末尾数据端口后会增加下一对空端口，最多 100 对。回归的输出1对应它自己收到的输入1，不要求回归输入与起点输入保持相同类型。

两节点的数据端口会显示具体类型，例如「输入 1 · IMAGE」「输出 1 · STRING」，并同步实际连接类型；不兼容类型不能连接。起点类型跟随它的上游，回归类型跟随回归自身收到的处理结果。类型变化也会传递到已连接的「跳回点」和「条件回归」。要改接其他类型，可先断开原输入再连接。

完整 `ARRAY` 接入起点时，输出的是数组元素，元素可能是数字、图片或混合类型，因此输出标为「任意（数组元素）」；不会把元素误当成 ARRAY。回归接入完整 ARRAY 时不拆开它，对应输出仍为 ARRAY。上游本身声明为任意类型时，静态端口也保留任意，不根据名称猜测类型。

**不要画反向连线。** “回归”由内部调度完成，画布上的线全部从起点向下游流动。

## 跟着接：多个详情页目录，各自拼接

假设 `D:\详情页素材` 下有 `产品A`、`产品B` 两个目录，分别放 3 张和 2 张图片。

1. 在“字符串转为字面量”里输入 `["产品A", "产品B"]`，将第一个“字面量”输出接到“在绝对路径中的相对路径”的“相对路径”。给“绝对路径”输入连接 `D:\详情页素材` 字符串。这样得到两个完整目录路径的执行列表。
2. 路径输出接“分包执行子流回归”的输入1。
3. 起点输出1接“从目录中匹配路径或目录”的目录路径。匹配模式选正则表达式，内容填 `(?i)\.(png|jpe?g|webp)$`，匹配对象选文件，只找当前目录时关闭递归。
4. 匹配结果接“从路径加载图像批次”。例如目标宽度 `790`、目标高度 `0`，按宽度等比缩放。
5. 加载结果接“从批次列表拼接图片”，方向选从上到下。
6. 拼接输出接“回归分包子流条件”的输入1。
7. 起点的分包回归条件直接接回归节点的同名输入。
8. 回归输出1接“预览超长图片”。

```text
目录列表 → [起点：输入1]
             输出1 → 匹配 → 加载 → 拼接 → [回归：输入1]
             条件 ────────────────────→ [回归：条件]
                                            输出1 → 预览
```

执行过程：A 的 3 张图拼成 A 长图并回归，再处理 B 的 2 张图。最终预览收到两张长图。

**拼接必须位于起点与回归之间。** 回归后再把两张长图送给同一个收集全部列表的拼接节点，仍可能合成一张；回归输出不会自动附带永久分组标签。图片先后顺序由上游加载与匹配规则决定，分包节点不会重新排序图片。

空目录或加载错误遵循中间节点自身规则；分包节点不会自动跳过报错的包。

## 另一个场景：每张长图切块、处理、拼回

```text
长图执行列表 → 起点 → 切分 → 逐块处理 → 本包拼接 → 回归 → 多张长图
                └──────────── 条件 ──────────────┘
```

A 的切片在包内完成合并后才处理 B。需要无标尺切片时用“最终切分（按边界）”；“切分预览（自动切块）”会添加标尺，用于观察位置。带重叠的预览块直接拼接会重复重叠区域，不能视为原图还原。详见 [长图切分](SplitPreview.md)。

输入必须是逐张长图的执行列表或数组。如果输入是一个包含多张图的 IMAGE 批次，起点仍视为一包；需要先用能拆图片批次的节点转换。“批量任意为执行列表”用于重复整个输入，不负责拆图片批次。

## 多个输入如何配对

包数取最长输入的长度。数组按位置配对，短的非空数组重复最后一项，单值每包复用。

| 轮次 | 输入1：`[A,B,C]` | 输入2：`[10,20]` | 输入3：`固定值` |
| --- | --- | --- | --- |
| 1 | A | 10 | 固定值 |
| 2 | B | 20 | 固定值 |
| 3 | C | 20 | 固定值 |

不会自动求所有可能组合。`[[A1,A2],[B1,B2]]` 是两包，每包仍为数组；`{"items":[A,B]}` 是一个完整字典。

全部输入都是空数组时执行零包，输出空列表。空数组与非空输入混用报错，因为空数组没有可复用的最后一项。

## 回归后拿到什么

| 各包送入回归的内容 | 最终内容 |
| --- | --- |
| 第1包一张 A 图，第2包一张 B 图 | A、B 两项 |
| 第1包执行列表 A1、A2，第2包执行列表 B1、B2 | A1、A2、B1、B2 四项，包界线不再保留 |
| 第1包完整数组 `[A1,A2]`，第2包完整数组 `[B1,B2]` | 两项，每项仍为完整数组 |

普通下游通常逐项处理，接收完整列表的节点可以一次合并它们。要保留组别，应在包内完成合并，或把本包结果装成一个完整数组/字典再回归。

## 当前轮次、多分支与嵌套

轮次从 1 开始，可接数字转字符串来构建编号；也可接回归的额外输入，结束后得到 `1、2、3……` 的执行列表。它是数据输出，不会自动在起点显示进度文字。

一包可以分两路，如图片处理与名称生成。两路分别接同一个回归节点，等待全部完成再发下一包。所有需要等待的分支都要回到对应回归，不能绕过回归直接接外部输出。没有数据输出口的保存、预览节点通常应放在回归之后。

嵌套适合“产品 → 产品下的目录 → 目录内图片”这类层级处理。必须先完整结束内层，再结束外层：

```text
A起点 → B起点 → 内层处理 → B回归 → 外层处理 → A回归
```

A/B 条件分别直接连接自己的回归。内层每次进入从第 1 轮开始，外层继续自己的计数。`A起点 → B起点 → A回归 → B回归` 这种交叉结构不受支持。将条件当普通数据传过其他节点，也不会转移控制权。

## 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 图片仍混在一起 | 拼接是否位于回归后？起点是否收到一个包含全部图片的批次？ |
| 只执行一包 | 单个 IMAGE 批次、字典或标量都不会自动拆开 |
| 输出已连接但输入未连接 | 起点的数据输出缺少同编号输入；补齐输入或断开输出 |
| 条件需要直接连接 | 起点条件应直接连自己的回归条件输入 |
| 循环未闭合 | 检查漏接回归、分支绕过回归、交叉闭合 |
| 某包报错后停止 | 不会自动跳过失败包，也不会撤销已保存到磁盘的结果 |
| 重复同一包没有重新生成随机内容 | 普通节点仍遵循 ComfyUI 缓存；需改变种子等实际输入，重复数据不保证随机结果变化 |

## 开发与验证

ID 为 `LiuxinyuPacketStart` / `LiuxinyuPacketEnd`。原有数据端口 API 编号保持不变，起点轮次输出固定为 101，前端提交时转换画布端口编号，更新后需刷新浏览器。

`tests/test_packet_tasks.py` 检查配对、等待、空数组、重复运行、动态子图、嵌套、轮次、失败停止及目录拼接；`tests/test_packet_sockets.cjs` 检查端口增减、恢复连线及轮次编号。
