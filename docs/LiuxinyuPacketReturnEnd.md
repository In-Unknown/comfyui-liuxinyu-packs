# 携包条件回归

等待本轮数据与布尔条件计算完成，决定是否携带新数据返回[分包跳回](LiuxinyuPacketReturnStart.md)。继续时不向外部下游输出；退出时只输出最后一轮的完整数据。

节点 ID：`LiuxinyuPacketReturnEnd`；分类：`liuxinyu/流程控制`。

## 输入与输出

| 端口或设置 | 方向 | 类型 | 说明 |
| --- | --- | --- | --- |
| 分包回归条件 | 输入 | 专用连接类型 | 必须直接来自配对“分包跳回”的同名输出；不是 true/false |
| 输入布尔 | 配置，可接入输入 | BOOLEAN | 可设常量或连接循环体计算结果；默认 true，每轮只接受一个布尔值 |
| 逻辑运算 | 配置 | 枚举 | 与、或、与非、或非、异或、同或；默认与，在本节点选择 |
| 处理完成数据1、2… | 输入 | 与对应初始值一致 | 配对后自动生成；接本轮处理后的新数据，对应被处理数据的同编号输入 |
| 处理完成数据1、2… | 输出 | 与对应初始值一致 | 退出时的完整值；空包情况下为初始值；不是执行历史列表 |

节点新建且未连接分包回归条件时，只有一个“分包回归条件”输入，没有数据输入、没有输出，布尔与运算配置暂不显示。

连接到分包跳回后，按它**实际已连接的被处理数据**生成处理完成数据输入和输出，数量、编号及类型逐一对应；分包数据数量不参与计算。例如起点接入2路被处理数据、5路分包数据，回归节点只生成2路处理完成数据，不生成5路数据口，也不增加空闲数据输入。

配对后显示输入布尔和逻辑运算配置；输入布尔仍可连接本轮计算结果。断开配对后，自动移除生成的数据口及其连线，恢复只有配对输入的状态，保留配置值供下次配对使用。

需要保留某项数据不变时，将“分包跳回”的对应当前被处理数据输出接入处理完成数据输入。不要接原来的初始来源，否则每轮会回到初始内容。最多支持100路被处理数据。

## 两个运算量是什么

`A` 是本轮处理完后**还有下一包**，由分包跳回计算；`B` 是本节点的**输入布尔**。对 A、B 执行所选运算，结果 true 就继续循环，false 就退出并把处理完成数据传给后续节点。

这里 A=true 表示仍有新包，A=false 表示已经处理到最后一包。分包回归条件已经关联了本轮分包状态，A由节点内部计算，不需要额外接线。

## 六种运算的完整结果

| A：还有下一包 | B：输入布尔 | 与 | 或 | 与非 | 或非 | 异或 | 同或 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| false | false | false | false | true | true | false | true |
| false | true | false | true | true | false | true | false |
| true | false | false | true | true | false | true | false |
| true | true | true | true | false | false | false | true |

与非为 `NOT(A AND B)`，或非为 `NOT(A OR B)`；异或为 A、B 不同，同或为 A、B 相同。不会因为包耗尽而强行覆盖计算结果。

## 常用接法

| 需要的行为 | 设置 |
| --- | --- |
| 按顺序处理全部包，最后自动退出 | 与，B=true |
| 还有新包并且外部条件允许才继续 | 与，B 接允许继续的条件 |
| 至少遍历全部包，之后仍未满足完成条件就继续最后一包 | 或，B 接“仍需继续处理” |

非空输入无论 B 的初始值如何，都会先执行一轮，再计算回归条件。“与、B=false”因此是处理第一包后退出，不是完全不执行。

与非在包耗尽时恒为 true；如果进入这个阶段，会一直重复最后一包，直到手动中断。其他运算也可能持续返回 true，请根据上表选择。没有隐藏的最大轮次截断。

## 例子：耗尽后继续处理最后一包

将 `["A","B"]` 经“将任意数组转为执行列表”接入分包口，被处理数据直接接完整数组 `[]`。循环体每次把本包追加到携带数组，并计算 `当前轮次数 < 4` 作为 B；逻辑运算选“或”。

| 轮次 | 包序号 | 本包 | 本轮新数据 | A | B | 是否回归 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 1 | A | `["A"]` | true | true | true |
| 2 | 2 | B | `["A","B"]` | false | true | true |
| 3 | 2 | B | `["A","B","B"]` | false | true | true |
| 4 | 2 | B | `["A","B","B","B"]` | false | false | false |

下游只收到最后的 `["A","B","B","B"]`。如果需要每轮日志或历史，应在携带数据中自行累积，而不是把最终输出理解为自动收集。

## 空包、嵌套及类型要求

所有待分包输入为空时，不执行循环体，也不读取其中计算的 B，直接输出被处理数据。没有处理过任何包，因此不会凭空构造一个“最后一包”。多路分包输入一部分为空而另一部分非空会报错。

支持嵌套；每个回归节点只闭合自己的分包跳回，不能交叉连接。需要等待的分支要连接到本轮数据或输入布尔。数据每轮必须只有一个完整值，类型与初始值一致；把多个执行项作为一份数据携带时，先收集为数组。类型不一致、缺失回归项或错误配对会给出错误，不会静默丢弃数据。

回归节点退出后会继续执行下游；false 不代表停止整个工作流。输入数据是否含重复记录、是否覆盖全部路径、是否允许覆盖字段，由循环体及循环前的数据检查决定。
