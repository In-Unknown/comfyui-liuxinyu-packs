# 对数组中字典元素重排序

将完整数组中的字典按某个字段升序、降序排列，或随机打乱。适合对评分、价格、编号等记录排序，保留每条记录的全部字段和重复项。

节点 ID：`LiuxinyuSortDictionaryArray`；分类：`liuxinyu/结构化数据`。参照同包字典数组节点，输入输出均为完整数组。

## 输入

| 参数 | 描述 | 数据类型 | 必需 |
| --- | --- | --- | --- |
| `数组` | 一个原生数组，每项必须是字典，例如 `[{"分数":2},{"分数":1}]`；不是 JSON 文本、元组或单个字典 | ARRAY | 是 |
| `要依据的键` | 默认空字符串；精确读取字典第一层键名，不解析点号路径。升降序时每项必须有该键；随机方式不读取，可留空 | STRING | 是 |
| `方式` | `随机`、`升序`、`降序`，默认 `随机` | COMBO | 是 |

## 输出

| 输出名称 | 描述 | 数据类型 |
| --- | --- | --- |
| `输出` | 重排后的一个完整数组，保留全部字典及其字段，不展开为执行列表 | ARRAY |

## 示例：按分数降序排列

1. 将下面的 JSON 文本交给“字符串转为JS对象”。
2. 将解析结果接本节点的 `数组`，`要依据的键` 填 `分数`，`方式` 选 `降序`。
3. 将 `输出` 接“预览JS对象或数组”。

```json
[{"名称":"甲","分数":2},{"名称":"乙","分数":9},{"名称":"丙","分数":2}]
```

预期输出：

```json
[{"名称":"乙","分数":9},{"名称":"甲","分数":2},{"名称":"丙","分数":2}]
```

选择升序时顺序为甲、丙、乙。甲与丙同分，两种排序均保持它们原来的先后顺序。

## 字段值与排序规则

- 数字按数值比较，整数和浮点数可混合；布尔值按 `false=0`、`true=1` 比较。
- 字符串按 Unicode 字符编码比较，区分大小写；这是普通字符串排序，不是拼音或自然排序。例如 `"10"` 排在 `"2"` 前，数值 `2` 则排在数值 `10` 前。
- 数字和字符串不能混合比较，不自动把 `"2"` 转成 `2`。空值、字典、数组及 NaN 不能作为升降序的排序值。
- 键名精确匹配，包含空格或点号的键也按原名读取。`a.b` 表示名为 `a.b` 的第一层键，不表示嵌套字段。空字符串也可作为真实键名。
- 所有字典必须包含指定键，缺失会报告第几项及键名。其他字段可以包含嵌套对象、数组等，不参与比较。

## 随机方式与缓存

随机方式打乱所有记录的位置，不按键分组、不抽样、不删除重复项。此时不要求字典包含指定键，但每项仍必须是字典。

随机方式在每次工作流运行到本节点时重新执行，不复用本节点上次的随机结果。没有种子控件；随机结果可能恰好与原顺序或上次顺序相同。升序和降序遵循 ComfyUI 正常缓存规则。空数组输出 `[]`，单项数组仍是一项。

## 完整数组与执行列表

节点每次调用接收一个数组，按 ComfyUI 原生规则处理执行列表：

| 上游内容 | 行为 |
| --- | --- |
| 一个完整字典数组 | 排序一次，输出一个完整数组 |
| 执行列表的每项都是字典数组 | 每个数组分别排序，输出对应的数组执行项，不跨项合并 |
| 执行列表的每项是单个字典 | 类型不符；需要先用“执行列表收集为数组”收集，再连接本节点 |
| 空执行列表 | 交由原生执行器处理；本节点不将其收集或转换为完整空数组 `[]` |

例如上游两项分别是 `[{"n":3},{"n":1}]` 和 `[{"n":4},{"n":2}]`，按 `n` 升序后得到两项 `[{"n":1},{"n":3}]`、`[{"n":2},{"n":4}]`，不会合成四项数组。

## 原数据保留与常见问题

输出创建新的外层数组，原数组顺序不变；记录字典及其嵌套值保持原对象，不深拷贝、不修改内容。

| 现象 | 检查方法 |
| --- | --- |
| 提示输入不是数组 | 检查是否传入 JSON 文本、单个字典或元组；文本先解析 |
| 提示某项不是字典 | 数组内不能混入数字、字符串或其他数组 |
| 提示缺少键 | 检查字段名称、大小写及空格；嵌套路径应先通过结构化数据节点提取为第一层字段 |
| 提示值无法比较 | 将排序字段统一为数字或字符串，并处理 null 等不可排序值 |
| 每次随机顺序不同 | 属于预期行为；重新运行会重新随机，不保证复现上一次顺序 |
