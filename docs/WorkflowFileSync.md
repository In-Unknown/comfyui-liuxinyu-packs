# 工作流文件变动提示

节点包自带的前端机制，无需在画布添加节点。刷新页面后加载。

ComfyUI 按原有方式恢复工作流，本机制沿用原生恢复流程，并在配置完成后、原生保存基准记录前等待端口初始化。恢复完成后，检查当前工作流的实际文件：**文件最后修改时间晚于上次前端成功保存时间，就认为这段时间内发生过后端变动**。即使文件改过又改回相同内容，也符合条件。

提示提供两个选择：

- **同步到实际文件**：点击后重新读取实际文件，替换当前页面内容，并清除该工作流的旧草稿；加载完成后的画布作为已保存基准，之后实际编辑才显示未保存。不会写入后端文件。
- **什么都不做**：保留当前页面和草稿，继续正常编辑。同一版文件不重复提示，文件再次修改后可以再次提示。关闭提示或按 Esc 等同于什么都不做。

前端保存包括正常编辑时成功写入浏览器草稿，以及成功保存工作流文件。恢复流程自身产生的草稿重写不会推进本机制已经记录的保存时间，刷新后也沿用该时间窗口。

弹窗等待选择期间，浏览器仍可正常保存草稿，但草稿保存不会关闭弹窗或推进此次检查的时间边界。尚未选择就刷新页面，仍会提示这版文件。若实际工作流文件已被成功保存，则取消原来的提示并重新检查，避免再同步过时的内容。

切换工作流、后端重新连接、窗口重新获得焦点时会检查。页面可见时每 5 秒检查一次文件修改时间；隐藏页面、加载中或弹窗尚未处理时暂停定时检查。

取消后想重新检查，右键画布空白处，点击 **检查/同步后端工作流文件**。这个手动入口不受此前“什么都不做”的记录或自动检查时间窗口限制，会重新读取后端文件，与此刻的实际画布比较：

- **内容一致**：提示“无需更新：当前工作流与后端文件内容一致。”，不弹同步确认框，不重新加载画布，不清除草稿或改变未保存基准。
- **内容不同**：显示同步确认框，明确说明当前画布与后端文件不同；只有点击“同步到实际文件”才替换页面。确认时再次读取文件，包含检查后在后端发生的最新修改。
- **读取或解析失败**：提示同步未完成，不会当作内容一致。

例如，保存工作流后立即手动检查，内容相同就提示无需更新；只修改当前画布的节点参数而未保存，再检查则需要选择是否同步。比较使用实时画布，不使用可能滞后的草稿状态；覆盖节点参数、位置、尺寸、端口、连线、分组和嵌套子图。忽略根画布的缩放和平移、JSON 对象键顺序及根节点数组的序列化顺序，节点通过 ID 对应；子图内部字段仍逐项比较。这与“查看未保存差异”使用同一套字段比较规则，不是原始文件字节比较。

“检查/同步后端工作流文件”和“查看未保存差异”各自带有小号灰蓝色 `liuxinyu` [来源标签](MenuSource.md)。每一项都显示标签，本包选项区域用细线与其他选项区分；顺序由 `menu_order.js` 集中规定，两个选项分别拥有稳定 ID；来源标签与排序不改变同步确认或差异查看行为。

## 加载时的端口初始化与未保存标记

官方 MatchType 节点（例如切换节点 Switch）在加载时可能暂时把端口设为 `*`，随后在动画帧中依据连线恢复为 `STRING`、`ARRAY` 等类型。即使文件已经保存了正确类型，也会经过这一过程。如果在中间状态记录已保存基准，打开或刷新后就会出现并未编辑却显示未保存的情况。

本包在原生 `afterConfigureGraph` 加载钩子中等待两帧，让端口初始化及其触发的下游 JSONata 类型更新完成，再由 ComfyUI 原生流程记录基准。普通打开、页面刷新恢复和手动同步均适用，包含嵌套子图中的切换节点。因此保存后重新打开，不会再因这类 `* → STRING` 初始化变化产生未保存标记。

这个等待不改写工作流文件，不清除已有草稿，不主动重置保存基准，也不从差异比较中排除端口类型。正常编辑参数、连线或端口类型后，仍按原生规则显示未保存；其他真实字段差异仍会出现在报告中。

手动同步时会保持弹窗，隐藏两个操作按钮并显示“正在读取实际文件并完成节点初始化…”，在加载完成及后续初始化结束后记录已保存基准并关闭弹窗。等待期间画布不可操作，避免把新的用户编辑纳入此次同步的已保存基准。

若同步后没有编辑却再次出现未保存白点，可右键选择 **查看未保存差异**。报告分别显示“已保存基准 → 前端已记录状态”和“前端已记录状态 → 当前画布”的字段差异，便于定位其他加载后的变化。报告可选中复制，最多显示每组前 60 处差异；不会保存、清除白点或修改已保存基准。

首次启用时可以使用现有 V2 草稿的保存时间；没有历史保存记录的文件，从首次打开时开始记录。未保存的临时工作流没有对应实际文件，不检查。

使用 ComfyUI 已有用户文件 API，沿用当前用户权限。自动提示依赖文件修改时间；外部工具若刻意保留或回拨文件时间，无法据此自动检测修改，可通过手动入口比较实际内容。浏览器与后端系统时间应保持一致。当前适配 V2 草稿存储；升级前端后若其内部存储接口变化，需要重新核对适配。

验证：`node tests/test_workflow_file_sync.cjs`。覆盖普通打开及连续保存重载的嵌套 Switch 类型初始化、下游 JSONata 微任务、已有草稿与真实编辑保留，以及保存后内容一致、实时编辑和嵌套子图差异、根画布视口与节点顺序、读取失败、检查期间切换工作流、确认时重读最新文件和失败回退。页面弹窗的视觉效果和交互由用户最终验收。
