# 工作流文件变动提示

节点包自带的前端机制，无需在画布添加节点。刷新页面后加载。

ComfyUI 按原有方式恢复工作流，本机制不拦截、不替换恢复流程。恢复完成后，检查当前工作流的实际文件：**文件最后修改时间晚于上次前端成功保存时间，就认为这段时间内发生过后端变动**。即使文件改过又改回相同内容，也符合条件。

提示提供两个选择：

- **同步到实际文件**：点击后重新读取实际文件，替换当前页面内容，并清除该工作流的旧草稿；加载完成后的画布作为已保存基准，之后实际编辑才显示未保存。不会写入后端文件。
- **什么都不做**：保留当前页面和草稿，继续正常编辑。同一版文件不重复提示，文件再次修改后可以再次提示。关闭提示或按 Esc 等同于什么都不做。

前端保存包括正常编辑时成功写入浏览器草稿，以及成功保存工作流文件。恢复流程自身产生的草稿重写不会推进本机制已经记录的保存时间，刷新后也沿用该时间窗口。

弹窗等待选择期间，浏览器仍可正常保存草稿，但草稿保存不会关闭弹窗或推进此次检查的时间边界。尚未选择就刷新页面，仍会提示这版文件。若实际工作流文件已被成功保存，则取消原来的提示并重新检查，避免再同步过时的内容。

切换工作流、后端重新连接、窗口重新获得焦点时会检查。页面可见时每 5 秒检查一次文件修改时间；隐藏页面、加载中或弹窗尚未处理时暂停定时检查。

取消后想重新选择，右键画布空白处，点击 **检查/同步后端工作流文件**。这个手动入口不受此前“什么都不做”的记录或自动检查时间窗口限制，仍需点击“同步到实际文件”才会替换页面。

同步时会保持弹窗，隐藏两个操作按钮并显示“正在读取实际文件并完成节点初始化…”，等待原生 MatchType 节点（例如 Switch）的动画帧初始化及下游 JSONata 输入类型更新完成，再记录已保存基准并关闭弹窗。此前仅等待图加载返回，会把下一帧的 `* → ARRAY/STRING`、输入标签更新误认为编辑。等待期间画布不可操作，避免把新的用户编辑纳入已保存基准；不会因此改写实际文件或改变正常恢复流程。

若同步后没有编辑却再次出现未保存白点，可右键选择 **查看未保存差异**。报告分别显示“已保存基准 → 前端已记录状态”和“前端已记录状态 → 当前画布”的字段差异，便于定位其他加载后的变化。报告可选中复制，最多显示每组前 60 处差异；不会保存、清除白点或修改已保存基准。

首次启用时可以使用现有 V2 草稿的保存时间；没有历史保存记录的文件，从首次打开时开始记录。未保存的临时工作流没有对应实际文件，不检查。

使用 ComfyUI 已有用户文件 API，沿用当前用户权限。判断依赖文件修改时间；外部工具若刻意保留或回拨文件时间，无法据此检测修改。浏览器与后端系统时间应保持一致。当前适配 V2 草稿存储；升级前端后若其内部存储接口变化，需要重新核对适配。

验证：`node tests/test_workflow_file_sync.cjs`。页面弹窗的视觉效果和交互由用户最终验收。
