# 布尔运算符

通过下拉菜单选择 Python 的 `not`、`and`、`or`。`not` 输出布尔值；`and` 和 `or` 测试 A 的真值，按需读取 B，并返回其中一个原操作数。适合组合判断、选择备用值及保留原数据类型的条件传递。

节点 ID：`LiuxinyuBooleanOperator`；分类：`liuxinyu/逻辑运算`。

## 输入

| 参数 | 描述 | 数据类型 | 必需 |
| --- | --- | --- | --- |
| `运算符`（`operation`） | 默认 `not`；可选 `not`、`and`、`or`。在节点控件中固定选择，不能连线动态改变 | COMBO | 是 |
| `A`（`a`） | 按 Python 真值规则测试的第一个操作数 | ANY | 是 |
| `B`（`b`） | 仅在 `and`、`or` 时显示；两种二元运算都必须连接，运行时按需要读取 | ANY | 二元时是；`not` 时不使用 |

不是任意数量的连锁运算：`not` 一个操作数，`and` / `or` 两个。需要 `a and b and c` 时串联两个节点。

## 输出

| 输出名称 | 描述 | 数据类型 |
| --- | --- | --- |
| `结果` | `not` 的实际值一定为 BOOLEAN；`and` / `or` 返回 A 或 B 的原对象，保持值、类型与引用。完整数组不展开为执行列表 | ANY |

输出口使用 ANY，是因为同一个节点可以返回整数、字符串、数组、字典等；不会把操作数字符串化或强制变成 bool。选择 `not` 后，实际返回值仍确定是布尔值。

## 直接照做：空文本时使用备用文本

1. 选择 `or`，出现 A、B 两个数据口。
2. 把主要文本接 A，把备用文本 `暂无说明` 接 B。
3. 将 `结果` 接到后续文本处理节点。

| A | B | 输出 |
| --- | --- | --- |
| `""` | `"暂无说明"` | `"暂无说明"` |
| `"承重能力强"` | `"暂无说明"` | `"承重能力强"` |
| `" "` | `"暂无说明"` | `" "`，空格字符串非空，为真 |

如果还要把“只有空白字符”当作空值，先接去除首尾空白的字符串节点。本节点执行 Python 原有真值规则。

## 求值顺序与返回值

| 运算 | A 的真值 | 是否请求 B | 返回内容 |
| --- | --- | --- | --- |
| `not A` | 假 | 无 B | `true` |
| `not A` | 真 | 无 B | `false` |
| `A and B` | 假 | 否 | A 原对象 |
| `A and B` | 真 | 是 | B 原对象，不再强制测试 B |
| `A or B` | 真 | 否 | A 原对象 |
| `A or B` | 假 | 是 | B 原对象，不再强制测试 B |

```python
not 0          # True，bool
0 and "abc"    # 0，int
1 and "abc"    # "abc"，str
0 or "abc"     # "abc"，str
1 or "abc"     # 1，int
[] or [1, 2]   # [1, 2]，完整数组
1 and None     # None，不是缺少输入
```

## 真正的短路执行

A 是正常依赖，先读取；B 是按需依赖。`and` 在 A 为假时、`or` 在 A 为真时，不会为了本节点执行 B 的上游。运行测试使用“被执行就报错”的 B 分支确认这一点。

如果其他节点也需要 B 的来源，那些节点仍可请求它。短路控制的是本节点对 B 的依赖，不会取消其他消费者的执行。

ComfyUI 提交前仍检查已连线节点的结构和必需参数。短路用于跳过运行，不能用于隐藏结构不完整的工作流。因此即使当前 A 会短路，二元运算的 B 也需要正确连接。

## 真值规则与官方逻辑节点

`False`、`None`、数值零、空字符串、空列表、空字典和空集合为假。非空字符串 `"False"`、`"0"` 仍为真；不会按文字内容解析真假。

官方 `And` / `Or` 对多个输入汇总得到 bool；本节点的 `and` / `or` 则返回两个操作数之一。若两路来自比较节点，二者本身已经是 BOOLEAN，返回结果也就是 BOOLEAN，可继续接官方 `If/Else Switch`。

要把任意值明确转为布尔，可串联两个 `not`。要按布尔条件选两条独立分支，使用[比较运算符](LiuxinyuCompare.md)或本节点产生判断，再接官方切换节点即可。

## 动态端口与保存

选择 `not` 时只保留 A；选择 `and` 或 `or` 时显示 A、B。`and` 与 `or` 之间切换保留 B 的连线；切到 `not` 会删除 B 端口及其连线，再切回二元运算需要重新连接 B。A 和输出连线保持不变。

运算符和连线随工作流保存；重新加载时按保存的运算符恢复端口。更新节点包后需刷新前端，动态端口由 `operator_inputs.js` 管理。

## 数组与执行列表

数组作为完整对象测试真值，例如 `[]` 为假，`[0]` 为真。选中数组时整体返回，不递归展开。输入来自执行列表时，ComfyUI 按项调用，输出相应执行列表。

执行列表中只要有一项需要 B，框架就会请求 B 的上游，取得其执行列表，再逐项选择结果；不保证 B 的上游也逐项短路。需要每一项的处理过程独立短路时，将判断放进[分包子流](LiuxinyuPacketStart.md)。

## 常见问题与报错

| 现象 | 原因及处理 |
| --- | --- |
| `and` 输出了 0，不是 false | 这是 Python 原操作数返回语义；需要 bool 时使用 `not` 两次或先比较 |
| `or` 没有采用备用值 | 检查 A 是否实际为空；空格、`"0"`、`"False"` 都是真值 |
| 二元运算提示缺少 B | 连接 B；不要用断线表达 None，需要一个真正输出 None 的上游 |
| 多元素图片或数组对象报真值不明确 | Python 无法把某些张量整体当 bool；先用比较、统计或聚合节点得到明确判断 |
| 切换回来后 B 的线不见了 | 一元模式删除 B 连线是正常行为；重新连接即可 |
