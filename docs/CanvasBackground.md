# 画布图片背景

把一张或多张本地图片铺在经典画布的网格下方。每张图片完整保留，按原始宽高比等比缩放，不裁边、不旋转、不拉伸；大小错落的矩形连续铺满平面，已有图片会循环使用。默认开启空间随机与两层嵌套：不同区域选择不同剖分，大块内部继续分成小块，同一位置在平移或刷新后保持稳定。节点、连线、分组仍由 ComfyUI 绘制，不需要添加节点或运行工作流。

本功能实现的是“任意两个相邻图片块不能恰好拼成一个矩形”的密铺，包含区域和嵌套层级之间的接缝。空间随机不再把一张固定贴图简单重复；不过它使用有限模板、有限随机种子和规则区域索引，不宣称数学上严格非周期，也不保证任意两个位置的局部图案绝不相同，或任意三个及更多图片块都不能组成矩形。

## 入口与操作

1. 更新后使用 `Ctrl+F5` 刷新 ComfyUI 页面。仅新增前端文件，无需重启后端。
2. 在经典画布空白处右键，选择 **画布背景…**，菜单右侧带 `liuxinyu` 来源标签。
3. 展开 **图片 · N 张**，点击 **添加图片**，选择一张图片，或按住 `Ctrl` / `Shift` 选择一组。也可直接把图片拖到面板上追加；覆盖旧组时明确使用 **替换整组**。
4. 保持 **显示图片背景** 勾选。分别拖动 **图片缩放**、**图片不透明度**、**组内背景淡化**、**网格不透明度** 的滑条，或在滑条上滚轮微调。只有图片缩放带 `50% / 100% / 200%` 三个小圆点吸附位置。鼠标停在滑块圆点上 1 秒且未按下，显示可输入数值的小浮层。网格设为 `0%` 完全隐藏，不需要关闭图片；组内背景淡化默认 `65%`，可增大以看清分组。
5. **嵌套层数** 默认 `2`，可用滑条、滚轮或悬停浮层调整到 `0～10`；不显示刻度，不做吸附。始终使用空间变化，不再需要选择“随机／重复”。层数在松开滑块或提交数字后计算，期间显示状态，计算在后台 Worker 运行。
6. 在 **种子** 输入框填写整数，回车或失焦后应用；右侧 **生成** 按钮生成一个新随机种子。记下当前种子，以后填回即可恢复对应布局（图片集合、顺序、缩放、层数及算法版本须相同）。
7. 修改自动保存，短暂失败自动重试，不显示保存中、保存成功或重试成功提示，也没有手动重试按钮。连续 8 次失败才显示完整诊断。面板不会锁住画布，标题栏可拖动，右侧可收起或关闭；关闭面板不取消后台保存。

取消文件选择保持原图；一组中有无法解码的文件时，整组添加／替换失败，保留之前的背景并在面板显示错误。读取期间暂时禁用调整与图片更改，但仍可收起、移动或关闭面板。关闭不会取消正在读取的图片：成功后仍应用和保存，失败时显示通知。

这是全局前端功能，没有节点输入口。图片来自浏览器文件选择器，区别于本包调用 Windows 后端对话框的路径节点。

| --- | --- | --- | --- |

| `生成` | 生成与当前值不同的随机种子，显示在左侧输入框并应用。多图优先减少同图共边，其次拉开同图距离；不同种子仍可能得到局部相似图案 | 操作按钮 | 否 |

透明图片保留透明度，因此透明区域仍能看到底色。“无缝覆盖”指矩形图片边界连续，不保证透明素材本身处处不透明。

缩放 `100%` 对应基础铺块高度 `1800` 画布单位：`基础高度 = 1800 × 缩放百分比 / 100`。旧保存值直接换算显示，例如 `900` 为 `50%`，不会为了换界面重置图片或参数。最外层高度为 `基础高度 × 4^min(实际层数, 3)`；第 4～10 层增加内部细节，不再把最外层指数放大。实际单张图的大小随剖分变化。若希望更细地调整，可直接输入如 `125.5%`，不要把数值理解为原图片文件的像素尺寸。

### 滑条、吸附与浮层输入

各项滑条平时只显示标签与滑条，不常驻显示数字。仅图片缩放在轨道上显示三个与横条同色的小圆点，从左到右为 `50% / 100% / 200%`，没有额外按钮或数字标签。拖动接近这些点约 6 个屏幕像素时吸附，继续拖远即可离开；滚轮和精确输入不吸附，因此可以微调到 `99%`、`101%`。其他滑条没有圆点刻度或吸附。

滚轮在滑条上向上增加、向下减少；缩放与不透明度按 1 个百分点调整，层数按 1 层调整。触控板小幅滚动会累计到一个步长再改变值。到达范围端点后保持端点；滚轮事件不会传给画布缩放，也不会滚动面板。

按住滑条调整时立即显示数值浮层，拖动期间保持显示，松开立即隐藏。未按下时，鼠标停在滑块圆点附近满 1 秒也会显示；离开圆点或浮层区域立即隐藏，不延迟。可从圆点移入上方浮层编辑；即使正在输入，移出整个控件也会提交并隐藏。回车或 Escape 提交并收起。移动／收起／关闭面板、滚动面板、切换窗口或标签页也关闭浮层并取消待显示计时。

数字框允许暂时留空继续编辑，不会立即把背景设为零；输入有效范围内的数值即预览，失焦／提交时保存。越界数值在提交时收回到端点，空值或无效输入恢复当前有效值。键盘聚焦滑条后，方向键与 Home／End 沿用原生滑条行为，Enter／F2 打开输入浮层；键盘事件继续传播。浮层中的数字与单位 `%` 或 `层` 作为一组居中，内外宽度均随数字长度调整，不保留固定宽度空白。浮层内边距为上下 2 像素、左右 6 像素；数字输入无内框、聚焦描边或阴影，点击数字直接出现光标编辑，仅外层浮层保留细描边。读屏仍可读取滑条当前值。

## 可以直接照做的示例

准备四张图片：`A.jpg` 为 `1600×900`，`B.png` 为 `900×1200`，`C.webp` 为 `1000×1000`，`D.jpg` 为 `600×1200`。

1. 右键画布空白处 → **画布背景…** → 展开图片区 → **添加图片**，一次选中这四张图片。
2. 将缩放拖到第一个小圆点，吸附到 `50%`；图片不透明度保持默认 `35%`，网格不透明度保持 `100%`，层数保持 `2`。需要精确输入时，在对应滑块圆点上停留 1 秒再编辑浮层。若希望接近原来的基础高度 `600`，可输入缩放 `33.33%`。
3. 背景里出现大小不同的横向、竖向和正方形图片块。每次出现的 A 图宽高比仍为 `16:9`，B 为 `3:4`，C 为 `1:1`，D 为 `1:2`；图片四条边的内容全部保留。
4. 向左、右、上、下平移画布，各区域会继续复用这四张图片，但排列和嵌套组合有所变化，负坐标也适用。返回原位置应看到原来的图案；缩放跟随世界坐标，不是固定在屏幕上的壁纸。
5. 在 **种子** 输入 `123456` 后回车，记下这个值，再点击右侧 **生成** 查看新排列。保持其余配置和图片不变，填回 `123456` 后回车，即可恢复刚才的布局。
6. 在缩放浮层中输入 `125`，再用滚轮微调；拖到中间的小圆点可吸附回默认 `100%`。
7. 将 **网格不透明度** 设为 `0`，确认网格消失而图片仍在，再设为 `40`，得到较淡的网格。取消 **显示图片背景** 后只隐藏图片，网格设置继续生效；重新勾选恢复图片。展开图片区可移除单图或 **清空**。关闭后刷新页面，应恢复最后保存的图片和两种不透明度。

不需要连接任何节点。背景不会进入生成结果，也不会成为模型输入。

## 调整与种子恢复

面板优先显示缩放、图片不透明度、组内背景淡化、网格不透明度和嵌套层数，始终按位置变化，不再提供固定重复选择。已有图片时，图片区默认收起，摘要保留数量与前三张小缩略图，通过箭头和“展开／收起”文字提示操作，可点击整行展开。展开后可以追加、替换、逐张移除或清空。文件名只占一行，悬停可查看完整名称。面板不放置顶部操作说明、层数教程或底部“使用提示”，详细行为集中在本文；只保留必要的计算、最终错误及实际层数不足状态，正常保存不占据界面。

控件使用专用 CSS 和 ComfyUI 的背景、输入框、文字主题变量。只有整个面板和独立输入浮层保留细描边；面板使用普通浮动容器且不绘制阴影或辉光。内部依靠间距、低对比度底色、悬停／按下变化分组，按钮、开关、数字框和展开行不添加常驻方框。滑块轨道／圆形滑块自行绘制样式，不依赖浏览器默认蓝色。数字输入使用 Arial 非衬线字体、常规字重及等宽数字特性，缺少该字体时回退到 Helvetica 或系统非衬线字体。浮层数字聚焦只显示编辑光标，其他交互控件保留低调的键盘焦点提示。

背景面板不提供撤销／重做，不保存调整历史，也不接管画布快捷键。有效修改提交后直接自动保存；需要改变结果时调整数值、生成新种子或重新选择图片。

种子始终显示，可选择、复制和手动填写；输入区域没有内部框线、聚焦描边或阴影，点击数字直接显示编辑光标，与右侧生成按钮共用一块低对比度底色。生成按钮同时更新数字和布局，种子随配置持久保存；不再提供重新随机布局和按住对比按钮。无效输入恢复之前的种子并提示有效范围；后台计算失败时保留之前的种子和布局。种子仅控制排列，不记录图片、缩放、层数等完整快照；恢复旧布局时这些条件也必须一致。

面板没有遮罩，不阻止操作外面的画布。标题是普通标题元素，支持拖动移位，不作为按钮、不进入 Tab 焦点顺序，也没有按钮悬停底色或白色焦点框。打开时焦点落在面板容器，不自动选中标题或按钮；实际控件仍保留键盘操作和焦点提示。窗口变窄或面板内容展开时，位置会限制在可见区域内。收起只隐藏控件。位置在当前页面内记住，刷新后回到默认右侧位置。

面板没有统一键盘拦截器，所有键盘事件均正常传播，不只放行个别组合键。包括保存、撤销／重做及自定义快捷键在内，面板和内部控件的键盘处理均不调用 `preventDefault` 或 `stopPropagation`，由 ComfyUI、浏览器与原生输入控件按各自规则处理。Enter／F2 打开数值浮层、Enter／Escape 提交浮层、Enter 提交种子时也不截断事件。面板不为 Escape 注册关闭快捷键；关闭请使用标题栏 `×`。面板内指针与滚轮操作仍与画布隔离，避免调节时误缩放或点击画布。

面板是位于 `graph-canvas-container` 内的普通 `div`（`role="region"`），不是原生 `dialog`。当前 ComfyUI 只要检测到任意 `dialog[open]` 就会暂停快捷键，即使该窗口通过 `show()` 非模态打开，或声明 `aria-modal="false"`，也会被视为模态窗口。因此仅让键盘事件冒泡还不够；普通浮动容器避免触发这个全局阻断，放在画布容器内则让限定画布范围的快捷键也能识别面板内的事件。实际输入数字时，Delete、复制粘贴等仍遵循 ComfyUI 对输入控件的原生编辑规则；不会把删数字强制转成删节点，也不合成或重复派发快捷键。真正的模态对话框打开时，仍遵守 ComfyUI 的原有保护。

## 保留比例的电路网络混排

基础拓扑来自边长 `112`、由 `21` 个不同大小正方形组成的 Duijvestijn 完美正方形。这里复用的是其平面邻接关系，不强制所选图片变成正方形。

史密斯图把水平分界线看作网络顶点，把跨越两条水平分界线的图片块看作边。对宽高比为 `r = 原图宽 / 原图高` 的图片，设该边的电导为 `r`：

```text
图片块高度 h = |上下顶点的电势差|
图片块宽度 w = |电流| = r × h
因此 w / h = r
```

固定上、下外边界的电势，求解内部顶点的基尔霍夫方程，再由电流累加恢复横坐标。分界线处的电流守恒对应两侧宽度总和相等。电流可能相对初始方向反向，坐标按实际大小关系恢复；电势相同造成的零面积图片块不予采用。

每个基础混排区域包含 21 块。图片少于 21 张时循环分配，超过 21 张时生成足够多个区域，保证所有图片出现；最后不足一组的位置继续循环使用已有图片。基础区域按共同高度拼接，供空间变化和嵌套复用。

采用结果前检查：

- 每块宽高比等于对应图片的原始宽高比，尺寸为正且坐标有限。
- 所有图片块在外框内，无面积重叠，面积总和等于外框面积。
- 内部接缝、区域之间和周期边界均没有两块恰好合成矩形。

多图尝试最多 40 种分配，保留满足几何约束且同图分散评分较好的结果；单图只需一次基础求解。没有通过几何检查的结果不会显示，也不会通过裁剪图片强行适配。

分区等比保底结果同样经过运行时几何校验。数学构造成立不等于 JavaScript 浮点数可以处理无限精度：比例跨度大到无法可靠区分边界时，会报告“图片比例跨度超出数值精度”并保留原背景；不会把数值退化的块显示出来。

## 同一图片尽量远离

分散是覆盖、比例与接缝约束之后的优化目标，分三处处理：

1. **基础区域。** 保持各图片使用次数大致均衡，先按相邻关系安排图片，优先避免相邻块使用同一张，再倾向把相同图片放到较远位置。对通过电路求解和几何检查的候选，主要惩罚同图共边长度，次要惩罚同图中心接近；基础周期接缝也参与评分。
2. **嵌套内部。** 在安全的子区域方向和组合中比较同图接触长度，保留接触较少的一组变化。外边界固定的内部变化仍可按递归位置随机选择。
3. **相邻大区域。** 根据坐标奇偶划分四种优先级。区域只参考较低优先级邻居，选择同图接触较少的安全布局；因此不会互相循环依赖，也不依赖用户先浏览哪里。并列结果由保存的种子决定。释放缓存、返回原位置和刷新均保持一致。

这是有限候选与局部选择的优化，不声称达到全局最远距离，也不承诺任意图片集合都完全没有同图相邻。只有一张图片时，同图相邻必然存在；两三张图片、极端比例或保底分区也可能留下接触。重复导入同一文件会作为两个来源记录处理，建议每张只添加一次。图片内容不做语义识别，相似照片不会自动视为同一张。

## 为什么任意比例不必裁剪：保底构造与证明

**在允许图片循环出现、外框比例自由的条件下，任意有限组正宽高比图片都有一种满足上述两块条件的铺法。** 因此本功能无需声称任意矩形数学上不可能，也没有裁剪降级选项。

构造如下：对于宽高比为 `r` 的某张图片，把基础 21 块正方形剖分的所有横坐标、宽度乘以 `r`，纵坐标、高度保持不变。于是每个小块都变成宽高比为 `r` 的矩形，用该图片完整填入即可。每张图片建立一个这样的区域，所有区域高度相等，水平相接后循环重复。

证明分为三个部分：

1. **比例和覆盖。** 原来的小块为 `s×s`，变换后为 `(r·s)×s`，比例严格为 `r`。对整块做同一个可逆缩放不会产生空隙或重叠。这里变换的是排布坐标；图片从一开始就按自己的比例填入对应矩形，不是把原图拉成长方形。
2. **区域内部不能两块合并。** 两个轴对齐矩形的并集要成为矩形，必须沿一整条等长边相接。基础剖分的 21 个正方形边长全部不同，因此不存在这种配对；统一的可逆横向缩放保持此性质。
3. **循环边界不能两块合并。** 基础区域左边分段的高度为 `50、29、33`，右边为 `27、19、24、42`，没有相同的上下端点区间；相邻区域高度相同，所以水平拼接不会出现可合并的一对。顶边分段宽度为 `50、35、27`，底边为 `33、37、42`，同样没有相同的左右端点区间；上下重复按同一区域对齐，仍不能配对。最右与最左的循环接缝适用同样论证。

这就是 **分区等比密铺** 保底构造：图片会按区域集中出现，每张在自己的区域中出现 21 次，混合程度通常不如电路网络混排，但完整性、比例和密铺条件都有明确构造保证。它不是“搜索失败所以判定数学上不可能”。

“完美正方形”“简单剖分”和本功能的两块条件并不完全等价。这里不宣称任意图片输入都得到大小互异的正方形，也不宣称复合区域不可能由更多图片块组成矩形。

## 空间随机与分层剖分

### 大块也参与剖分

把基础密铺看作一块完整区域，在归一化方形坐标中，再用 21 块完美正方形剖分为它安排不同大小的位置。每个位置填入一份按相同比例缩放的基础密铺，而不是只放一张图片。第二层继续对这些子区域做相同处理，形成大块包含中块、中块包含小图的结构。

基础密铺外框通常是矩形：实际使用时把方形坐标整体映射到这个外框比例。每个子区域仍与父区域具有相同宽高比，因此里面的图片只需等比缩放，不会因为外层剖分而改变比例。一个基础 21 图布局经过两层嵌套，整块共有 `21×21×21 = 9261` 张图片实例，但只处理当前可见部分。

上限为 10 层。第 4 层开始，接触父区域外边界的子区域使用最多两层的边界模板，内部子区域继续递归加深。因此不同位置实际深度可以不同，10 层指允许达到的最深内部路径，不是把每个位置都展开成 `21^10` 个实例。边界模板保留准确接缝信息，深层定义共享子布局；绘制只递归访问可见区域，并在子像素处停止。布局生成放在模块 Worker，提交层数后等待计算完成再应用。

浏览器完全不支持 Worker 时沿用同一算法在主线程计算，此时计算期间可能短暂影响页面响应。浏览器支持 Worker 但脚本加载或执行失败时，会报告错误并保留旧背景，不自动转为主线程重复计算。

每层考虑剖分几何的 8 种旋转／镜像方向；基础图片块布局考虑水平／垂直反射。**变化只作用于块的位置，照片内容始终正向绘制**，不把照片本身旋转或镜像。

### 随机变化与接缝约束

不能让各块不加检查地独立随机，因为不同边界可能恰好出现可合并的两张图。本实现为每种布局记录四条边上图片片段的起止位置：

1. 构造每个父区域时，检查子区域所有相邻边，拒绝两侧完整片段完全对齐的组合。
2. 对一组可以互换的内部变化，固定接触父区域外边界的子区域；只改变内部子区域，并重新检查内部接缝。这样组内所有变化对外呈现相同的边界。
3. 为最外层选择一组在上下、左右所有配对方向都兼容的布局。任何相邻区域从这组里选取都能安全接合。
4. 内部每次出现同一组布局时，可以按自己的递归路径独立选择内部变化；不是整幅背景只从几张固定的大贴图中挑选。

所有变化保留完整覆盖和原图比例。候选不符合接缝约束就不使用；某一级没有安全候选时保留上一层，界面显示实际层数，不以裁剪或拉伸来凑满指定层数。层数设为 `0` 时仍在基础区域之间变化。

### 同一位置始终稳定

选择依据是“保存的种子 + 正负区域坐标 + 递归路径”，不依赖当前时刻、访问顺序或 `Math.random()`。先向左再向右、切换工作流、释放缓存后重新访问、刷新页面，都不会让同一位置重新抽签。

更换图片、改变层数或尺寸会改变布局／坐标尺度；填写新种子或点击种子右侧的“生成”会明确更换种子。层数和种子同图片一起保存；旧记录的固定重复开关不再使用，缺少层数时按默认的两层嵌套加载。算法升级可能改变旧种子对应的布局，升级后的同一版本保持位置稳定。

最外层仍使用规则坐标区域作为索引，内部具有多尺度变化。这里解决的是固定重复贴图的明显周期感，不把实现说成严格非周期平铺的数学证明。

## 矢量网格、不透明度与绘制顺序

从画布上层到下层依次是原生节点与连线等内容、矢量网格、图片和底色。扩展只读取一次当前主题网格图片中的横／纵线位置、宽度及线色，再用 Canvas 2D 的细矩形直接绘制线条；不把网格位图放大或循环贴上去。更换主题网格图片时重新读取。

标准深色主题保持每 `10` 个画布单位一条细线、每 `100` 个单位一条粗线。线的位置与间距跟随画布缩放和平移，线宽按屏幕宽度保持约 `1 / 2` 个 CSS 像素，并根据设备像素比取整、对齐物理像素边界，避免线条放大变成模糊粗带。高像素比或非整数系统缩放下，实际宽度取最接近的整物理像素；这里的矢量绘制仍最终由屏幕像素显示。主题的常规水平／垂直网格沿用各自间距和线色。

**网格不透明度** 是独立的强度系数，`0%` 完全跳过网格绘制，`100%` 使用主题线色和原生缩放渐隐，并不强制线条在任何缩放下都完全不透明。实际强度还乘以原生画布透明度；开启原生缩放渐隐时，再乘以 `1 − 0.5 / 画布缩放倍数`。缩放比例不大于 `0.5` 时沿用原生隐藏规则，图片仍继续铺满。没有图片、关闭“显示图片背景”或清空图片后，该网格控制都继续生效；不会改变节点、连线和图片本身的透明度。旧保存记录缺少此项时采用 `100%`。

只处理经典 LiteGraph 画布的背景绘制接口。读取主题网格失败时提示并使用标准深色矢量网格；自定义跨域图片可能受浏览器像素读取限制，建议使用内置主题。此读取方式针对常规横纵线网格，不负责把任意装饰图案转换为矢量。其他扩展主动绘制不透明全屏背景时可能挡住本功能；建议同时只开启一个图片背景功能。未对所有第三方画布替代实现做兼容承诺。

## 分组覆盖区域的图片淡化

原生分组的半透明底色容易被背景图片干扰。**组内背景淡化** 只作用于分组矩形覆盖的图片区域，不改变组框、标题、节点、连线或网格自身的不透明度，也不改变分组外的图片。默认淡化 `65%`；`0%` 恢复组内与组外相同的背景强度，`100%` 让组内只留下画布底色、网格及原生内容。

在不透明画布底色下，组内图片的有效不透明度为 `图片不透明度 × (1 − 组内背景淡化)`。例如图片不透明度为 `80%`、淡化为 `75%`，组内相当于 `20%`，组外仍为 `80%`。可以先把图片不透明度调到 `80%`，将一个原生分组放在背景图上，再把淡化滑条从 `0%` 拖到 `100%`，观察仅组内图片逐渐消失。

每次重绘都读取当前图中原生分组的边界，因此移动、缩放分组或平移、缩放画布时淡化区域随之更新；删除分组后恢复普通背景。所有可见分组以并集一次绘制，嵌套或重叠处不会多次淡化。自定义扩展绘制、但未注册为原生分组的装饰区域不参与此处理。

实现沿用原生背景绘制包装：在原生内容与网格之后、图片之前，用当前画布底色填充分组并集，按淡化值合成；不修改分组的颜色或工作流数据，不重新生成布局。关闭图片或没有图片时不额外绘制淡化层。该参数随背景配置保存，旧配置缺少此项时采用 `65%`。

## 图片副本与配置持久化

复用 ComfyUI 原有 `/userdata` 用户文件接口，图片副本和配置实际写入运行 ComfyUI 的电脑。当前默认用户位置为：

```text
C:\Apps\ComfyUI_windows_portable\ComfyUI\user\default\liuxinyu\canvas-background\
  background.json
  images\<随机标识>.webp
```

启用多用户或自定义用户目录时，位于对应用户目录的 `liuxinyu/canvas-background/` 下。原始文件名、原始比例和对应副本路径写入 `background.json`，不依赖文件选择器再次取得原文件路径。配置还保存图片显示开关、缩放、图片和网格不透明度、组内背景淡化、嵌套层数及布局种子。缩略副本通常为 WebP，浏览器不支持 WebP 编码时可为 PNG。它不是原图备份服务：副本最长边为 1024 像素，原图仍由用户保留。

### 保存、迁移与恢复

- 每次有效调整提交后自动保存。先完成全部图片副本写入，再写引用它们的配置；复用 ComfyUI 的临时文件加原子替换机制。滑块拖动中先预览，松开后提交；层数提交后先完成后台计算。
- 只调整参数时复用已保存的图片副本，不反复上传图片。这里的上传目标是当前 ComfyUI 服务，不是第三方网站；远程部署时文件位于远程服务器。
- 初次更新时，若磁盘尚无配置，会从当前浏览器原有 IndexedDB 读取旧图和设置，显示后自动迁移到磁盘。旧浏览器记录不删除；迁移写入失败仍显示旧图，并走同一自动重试流程。已有磁盘配置时，以磁盘为准，不用旧浏览器数据覆盖它。
- 保存成功后刷新、关闭浏览器或重启 ComfyUI 都可以恢复；同一服务器、同一 ComfyUI 用户不依赖原浏览器缓存或原始图片路径。保存与重试在当前页面后台执行，关闭设置面板不会取消，但刷新或关闭浏览器会终止尚未完成的请求与重试；没有错误提示不代表仍在重试的内容已经落盘。
- 写入失败保留磁盘上一份完整配置。当前页仍可预览，短暂故障自动恢复；耗尽重试后显示完整诊断，此时刷新只能恢复最后成功保存的内容。读取失败仍单独提示，不自动用空配置覆盖磁盘文件。旧浏览器记录若已被清除且尚未迁移，无法凭空恢复。
- 移除单图或清空只修改当前配置列表，不删除原图或磁盘副本。无引用副本不会自动清理；备份时可直接复制整个目录。需要恢复图片时重新添加；面板位置只保留在当前页面。
- 不同标签页不实时同步，同时修改时以后完成的配置写入为准。工作流 JSON 不携带这些副本或设置，切换工作流仍使用当前用户的背景。

### 自动重试与最终诊断

每次保存最多尝试 8 次（首次尝试加 7 次重试），失败后的等待依次为 `0.5、1、2、4、8、8、8` 秒。每个图片或配置写入请求有 15 秒超时，网络错误、非成功 HTTP 响应及超时都进入重试。等待采用异步计时，不阻塞画布。正常保存、首次失败、等待重试及重试成功均不弹消息、不显示状态行；不提供“重试保存”按钮。

重试复用同一张图片的目标路径；已确认上传的副本不重复上传，响应丢失而结果不确定时也不会每次生成一个新副本文件名。图片全部保存成功后才写配置。保存期间有新调整时，旧配置的后续重试与过期错误被取消，随后保存最新快照；已经发出的请求会先结束，避免旧请求在新请求之后覆盖配置。

8 次都失败后，面板出现可选择复制的完整错误文本，并发出一条错误通知；通知不自动消失，关闭面板时也能获知失败。诊断包含配置版本、保存目录、参数快照、图片名称／比例／副本字节数／类型，以及每次尝试的 UTC 时间、失败步骤、POST 请求路径、文件位置、HTTP 状态、服务端请求标识（若提供）、响应正文、请求耗时、超时限制和异常堆栈。网络错误没有响应时明确标注。诊断不包含图片二进制或请求认证头，服务端响应按普通文本展示，不作为 HTML 执行。

耗尽重试后不会无限循环请求；下一次有效调整会自动发起新的保存过程，无需手动重试按钮。之后保存成功会静默清除旧错误，不再弹恢复成功通知。诊断保留在当前页面，刷新后不保留。

## 性能与文件边界

- 图片在浏览器解码，背景副本保存到当前 ComfyUI 用户目录；不调用模型或图片生成 API。
- 保存的是最长边不超过 `1024` 像素的背景副本与原始比例；原图文件不修改。缩略副本的像素取整不会改变用于计算布局的原始比例。
- 空间随机按视口逐层裁掉不可见区域；这里裁掉的是无需绘制的画布区域，不是裁剪照片。放大时直接绘制完整图片，缩小时给实际选中的局部布局生成缩略图，不替换成另一种周期布局。单张缩略图最长边不超过 `256` 像素，最多缓存 `512` 项，且总像素不超过 `4,194,304`（像素缓冲约 16 MiB，不含浏览器对象开销）；清除缓存后按相同空间种子恢复。
- 投影宽或高不足 `0.8` 屏幕物理像素的区域以面积加权平均色近似；极端总览一次涉及超过 `2048` 个最外层区域时也使用平均色，防止无限枚举。重新放大恢复原位置的细节。透明素材的平均色包含透明度，不将透明处强行填成黑色。
- 始终使用空间布局，已删除固定重复贴图分支。空间区域选择最多缓存 `512` 项；10 层保留共享的布局定义，不展开全部图块。所有缩略方式都受像素采样和取整限制，不是对源图片裁边。
- 动图作为静态背景副本使用，不持续播放。支持浏览器能成功解码的格式；不支持的文件会报错并保留旧背景。
- 存储位置与恢复规则见上节。网络中断、用户目录不可写、磁盘不足或用户身份错误均可能导致保存失败；按面板提示排查，不把当前预览当成保存成功。

## 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 右键没有入口 | 刷新页面，必要时 `Ctrl+F5`；在经典画布空白处右键，不是在端口或控件上 |
| 选图后看不到背景 | 检查开启勾选、不透明度是否为 0、面板是否出现解码错误，以及是否有其他背景扩展覆盖 |
| 图片太小或太密 | 增大“图片缩放”，可拖到 `100%` 或 `200%` 对应圆点，再用滚轮或悬停浮层微调；也可试不同嵌套层数 |
| 照片中的文字太淡 | 增大“图片不透明度”；可独立降低“网格不透明度”，避免网格干扰图片 |
| 背景图片干扰分组辨认 | 增大“组内背景淡化”，`100%` 完全隐藏分组内的背景图片；组外不受影响。若希望组内外一致，设为 `0%` |
| 想完全隐藏网格 | 将“网格不透明度”设为 `0%`；图片、节点和连线不受影响，刷新后保持 |
| 网格设为 100% 仍较淡或缩小后消失 | 保留原生缩放渐隐和 `0.5` 显示阈值；放大画布检查。100% 表示未额外减弱网格，不是取消原生渐隐 |
| 某些图出现多次 | 这是预期行为；有限图片持续填充基础和嵌套区域，不保证每张只出现一次或显示面积相同 |
| 仍然像固定贴图重复 | 现在始终启用空间变化；可提高嵌套层数或重新随机。局部重复仍可能出现，不保证任意两处都不一样 |
| 同一张图仍然相邻 | 分散是几何约束下的优化，单图必然相邻，少图或保底布局也可能接触；可增加不同图片或重新随机，不会通过裁图破坏比例 |
| 10 层没有处处变成极小图 | 深层主要细分内部，外边界保持较浅模板，子像素处以平均色显示；放大局部查看。层数不等于所有位置都展开同样次数 |
| 图片数量多或比例差别大时混排不理想 | 点击种子右侧的“生成”，或调整嵌套层数和缩放。分区等比密铺不会偷偷裁成正方形，未承诺全局最优美学排列 |
| 缩到极远处颜色变成细碎色块或平均色 | 达到子像素或总览绘制阈值；放大后原位置的图案会恢复，不会重新随机 |
| 放大后背景不如原图清楚 | 背景使用 1024 像素副本，不是原图查看器；极小比例的块缩小时还受屏幕采样限制 |
| 刷新后背景丢失或恢复旧值 | 检查当前 ComfyUI 用户、服务地址及本地 background.json；保存或自动重试尚未结束就刷新，会恢复旧配置。首次更新需在旧图片所在浏览器完成迁移；多次保存失败会显示完整诊断，无需手动点击重试 |
| 想找回之前的随机布局 | 填回之前记下的种子，并保持图片集合、顺序、缩放、层数及算法版本相同；面板不保存历史种子列表或完整配置快照 |
| 想恢复纯底色背景 | 取消“显示图片背景”；网格仍使用独立的不透明度，若也不需要网格就设为 `0%`。不再需要图片副本时展开图片区点击“清空” |

## 方法来源与核对

电路类比源于 R. L. Brooks、C. A. B. Smith、A. H. Stone、W. T. Tutte 关于矩形剖分的工作，不是本功能使用者提出的新方法。相关历史论文为 *The Dissection of Rectangles into Squares*, Duke Mathematical Journal 7 (1940), 312–340。

本次实际查阅的公开说明：

- [Squaring.net：Brooks、Smith、Stone、Tutte，第二部分](https://www.squaring.net/history_theory/brooks_smith_stone_tutte_II.html)：说明水平分界线与网络顶点、图片块与电路边、基尔霍夫守恒、总电流与外框宽度、电势差与外框高度之间的关系。原说明主要讨论单位电阻的正方形；这里按 `电导 = 图片宽高比` 扩展到矩形，并对每个实际结果做几何校验。
- [Squaring.net：简单完美正方形](https://www.squaring.net/sq/ss/spss/spss.html)：核对 1978 年 Duijvestijn 的 21 块、边长 112 的基础剖分。
- [Squaring.net：相关作者与论文](https://www.squaring.net/history_theory/brooks_smith_stone_tutte.html)：核对上述论文的作者、年份与出处。

没有复刻视频中的八千块兔子图案，也没有运行时访问这些网站。以上为开发核对资料；不把未取得的论文全文说成已经阅读全文。

## 开发与验证

前端入口是 [`canvas_background.js`](../canvas_background.js)，几何计算位于 [`canvas_background_layout.js`](../canvas_background_layout.js)，面板专用样式位于 [`canvas_background.css`](../canvas_background.css)。沿用根目录 `WEB_DIRECTORY = "."` 的自动前端加载方式和 [`menu_source.js`](../menu_source.js) 的菜单标签，没有新增 Python 节点或修改工作流序列化。面板参照本包 `graph_layout.js` 的普通 `div` 轻量容器，复用 ComfyUI 主题变量；优先挂载在画布容器内，缺少该容器的旧环境回退到 `document.body`，画布限定快捷键的作用范围仍由对应前端决定。
