# 预览超长图片

- 宽高比大于 `16:9` 时允许横向滚动，小于 `9:16` 时允许纵向滚动。恰好等于阈值的图片按普通图片显示。
- 普通图片完整、等比、居中显示，至少宽或高的一边铺满预览容器；正方形图片不会随容器变形。
- 超宽图片按容器高度缩放，超高图片按容器宽度缩放。容器足够大、没有溢出时，图片自动居中。
- 调整节点尺寸时立即重新计算图片布局和四边阴影。阴影只提示仍有内容超出当前视口的方向，无需滚动来刷新。
- 横向和纵向的起点、滚轮方向仍由节点的两个方向选项控制。多图点击进入单图，Esc 返回网格，左右方向键切换图片。

- 预览文件按输入像素尺寸写为 PNG，不再使用 16384 像素的最长边限制或 JPEG 有损编码。保留灰度和透明通道。

修改了 Python 后端时需重启 ComfyUI、`Ctrl+F5` 刷新页面并重新执行节点。旧执行结果没有分级预览文件，会继续使用原图显示。

多图缩略图现与「从批次中选择保存图片」共用官方列数计算，支持质数数量、末行不足和条件合适时贴节点外缘。
具体排列及本轮检查范围见 [缩略图排列规则](ThumbnailGrid.md)。

## 2026-10-24 缩放及画布进出优化

原来的网格和单图都加载完整原图；被隐藏的原生画布预览还会额外在后台加载原图。
现在仅该自定义节点停用默认图片预览加载，原始 PNG 仍按输入尺寸无损保存。

- 网格预先生成最长边 192 / 768 / 1536 像素及原尺寸的取景缩略图，小图不放大；按查看方向截取开头区域。排版继续使用原始尺寸，保持原来的比例和边缘贴合规则。
- 单图生成逐级减半的图像和每边最多 1024 像素的无损图块。只请求画布中可见范围及相邻图块，最近使用的图块限制缓存数量。
- 图块加载期间先显示对应区域的低清预览，加载完成后替换；透明区域不会与底图重复叠加。
- 画布滚轮缩放开始时立即隐藏高清缩略图、移除可见清晰图块，只显示预加载的小图；连续缩放期间不请求新的清晰图，停下约 250 毫秒后恢复。小图与清晰图不会同时叠加，透明度保持正确。图块保留在有数量上限的缓存中供恢复复用。
- 画布缩放不重新排列网格。拖动节点或画布时根据画布坐标选择可见图块，无需逐帧测量 DOM 边界。
- 网格停稳后按实际显示像素和屏幕像素密度选清晰档位，按离画布视窗中心的距离恢复可见缩略图，每次最多加载两张。原尺寸取景图消除了此前 768 像素的清晰度上限。
- 画布外暂停更新，再次出现时复用已有布局和图块；URL 不再附加随机时间戳。
- 缩略图和图块由现有临时预览缓存管理，同输入复用，输入变化后清理旧结果，不留独立的永久缓存。

首次执行会增加预览生成时间和临时磁盘占用，换取浏览器更小的解码和缩放工作量。

验证包括原图像素、灰度、透明度、四个取景方向、图块完整拼回原图、缓存复用与事务清理，以及前端调度模拟。
在 395×700 节点视口、画布缩放 1、屏幕像素比 2 的测试中，790×36153 长图首次请求 3 块清晰图；
网格大缩略图为 432×768，相比整图减少约 98.8% 的待解码像素。这是文件和调度指标，不代表已测得浏览器帧率。
前端模拟还检查了滚轮处理前立即切换小图、100 次连续缩放期间不发起高清请求、停稳恢复缓存、缩放中切图、画布进出、少量滚动复用、调整容器后立即更新阴影和节点删除后的清理；实际交互体验由用户验收。
