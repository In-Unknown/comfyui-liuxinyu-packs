# 传出虚拟连接

虚拟连接的**接收端**：根据键找到唯一的[传入虚拟连接](LiuxinyuVirtualOutput.md)，把它各路输入的上游结果提供给当前位置的下游。同一键可以在不同位置添加多个本节点，共用唯一传入端。适合在远处或嵌套子图中使用图片、文本、路径及结构化数据。

“传出”指从此处将数据传给下游，所以本节点左侧没有数据输入端口，右侧只有数据输出端口。两端之间不画线；运行时接收输出会替换成发送端的真实上游连线，自然建立执行依赖。

## 输入

| 参数 | 描述 | 数据类型 | 必需 |
| --- | --- | --- | --- |
| `键` | 与发送端完全相同的名称，默认空字符串；文本框填写，无连线端口。区分大小写和空格 | STRING | 是；建立配对时须填写 |

没有数据输入端口，也没有顺序、缓存或其他配置项。键用于提交前配对，不能连接动态字符串来改变运行中的连接对象。

## 输出

| 输出名称 | 描述 | 数据类型 |
| --- | --- | --- |
| `输出 1`、`输出 2`…… | 一一对应发送端输入 1、输入 2……；保留原始类型与原有执行列表语义。填键后按连接动态增长，无固定数量上限；空键时一个输出也没有 | ANY；确定后显示 STRING、IMAGE、ARRAY 等实际类型 |

单值仍是单值，完整数组整体传递，执行列表仍由下游逐项处理。不同输出互不合并或补齐。

## 直接照做：在子图中读取远处的记录数组

1. 用“字符串转为字面量”解析：

   ```json
   [{"imageIndex":1,"topic":"承重"},{"imageIndex":2,"topic":"收纳"}]
   ```

2. 添加“传入虚拟连接”，键填 `原始记录`，将“完整字面量”输出接其“输入 1”。
3. 在需要记录的子图中添加本节点，键同样填 `原始记录`。
4. 将本节点“输出 1”接到“js对象转换为字符串”，再接预览节点运行。

输出对应一个完整数组，内容为：

```json
[
  {"imageIndex":1,"topic":"承重"},
  {"imageIndex":2,"topic":"收纳"}
]
```

在另一子图再添加一个同键 `原始记录` 的传出节点，它的“输出 1”也得到上面的完整数组，各位置无需增加传入端。

两条记录不会被本节点拆成两次执行。需要逐条处理时，继续连接[将任意数组转为执行列表](LiuxinyuArrayToExecutionList.md)。

## 先放哪一端都可以

| 操作 | 界面变化 |
| --- | --- |
| 新增本节点，键为空 | 没有任何数据端口 |
| 填写键，尚无发送端 | 出现一个 ANY 输出 |
| 先将输出接到 STRING 下游 | 输出显示 STRING，并预留下一个空口 |
| 此时新增同键发送端 | 发送端取得对应输入数量和类型 |
| 发送端已有多路输入，再填写本节点的键 | 本节点同步对应输出数量及类型 |
| 任意一端连接末尾空口 | 传入端与全部同键传出端同步增加下一路空口 |

连接按同键通道对应。传入端或任意传出端新增连接时，全部同键端点同步增长。断开某一路时，检查传入端和所有同键传出端：任一端仍连接就全部保留；全部断开才同步删除该路，包括中间空路。删除后，后续通道编号依次前移，相关连线随端口一起调整，不改变实际数据来源。末尾始终保留一个灰色任意备用口。

## 同键配对与重复提示

当前工作流的主图和全部嵌套子图共用键空间，一个键只能有一个传入端（发送端），但允许多个传出端（接收端）。新增或复制传出端并填写同键时，会直接同步已有通道，不会因其他传出端使用该键而清空。仅新增重复传入端时才提示并清空其键。

需要多个下游使用同一结果时，可以从一个传出端分叉，也可以在各子图各放一个同键传出端。仅包含传出端的子图可以重复实例化，全部实例使用同一来源；若复用的子图包含同键传入端，则运行前报告带子图路径的重复来源，需调整传入端的位置或键。

键精确匹配：`原始记录` 与 `原始记录 ` 不同。修改某个端点的键不会自动改其他端点；该端点改为与新来源同名后重新配对，其他传出端保留原配对。键与端口布局随工作流文件保存，刷新和重新打开后恢复。

## 数据类型、执行列表与多路输出

| 发送端某路上游 | 本节点对应输出 |
| --- | --- |
| 文本 `"01-综合"` | 一个同内容字符串 |
| 完整数组 `[1,2,3]` | 同一个完整数组 |
| 执行项分别为 `[1,2]`、`[3,4]` 的执行列表 | 两个数组执行项，保留嵌套结构 |
| 图片批次 IMAGE | 完整批次，不拆图 |
| 字典、数字、布尔值、`None` | 保留原类型和对象引用 |
| 空执行列表 | 零项，与普通连线相同 |

例如发送端输入 1 是三个执行项、输入 2 是一个字符串，本节点输出 1 仍有三个执行项，输出 2 仍只有一项。是否逐项配对由各自下游节点决定。

两端不执行保存、读取或复制。实际运行的上游、下游和缓存关系与还原后的直接连线相同；只使用一路输出时，不会额外强制执行发送端其他未使用的路。

## 类型检查和执行依赖

同键全部端点同步类型，运行前逐个核对每个传出端的实际下游要求。某个传出端不兼容时，错误给出配对键、通道编号、该传出节点编号与相关类型。一个通道只有一种上游数据，不能因接到不同传出端而自动转型。

接收端不会先读到“尚未写入的变量”：它的业务输入就是发送端的真实上游输出，上游完成后下游才具备执行条件。分包、循环同样使用还原后的普通连线确定边界，无需额外设置先后顺序。

虚拟连接保留普通连线的约束；不能借此制造循环依赖或绕过分包闭合条件。纯虚拟配对环和还原后形成的执行依赖环都会在提交前被拒绝。

## 多端连接的保留与收起示例

假设同键有一个传入端和传出 A、传出 B，已经连接了三路数据：

| 操作 | 同键全部端点的变化 |
| --- | --- |
| 传出 B 接上第 4 路备用口 | 传入端、传出 A、传出 B 都增加第 5 路备用口；第 4 路传入尚未接线时运行仍报缺输入 |
| 第 2 路只断开传入端 | 保留第 2 路；传出仍在使用，运行报缺输入 |
| 再断开传出 A 的第 2 路，传出 B 仍连接 | 仍保留第 2 路 |
| 最后断开传出 B 的第 2 路 | 全部端点一起删除第 2 路，原第 3 路及后续通道前移，实际数据配对不变 |
| 所有数据连接都断开 | 每端只保留一个灰色任意备用口 |

如果只是传出端全部断开，而传入端该路仍连接上游，也会保留该路。检查范围是全部同键传出端，包含嵌套子图里的节点。

## 数据端口编号与缺少输入的报错

使用[端口显示排序](PortOrder.md)调整过顺序后，删除空通道引起的编号前移会同步迁移显示偏好。每个传出节点分别保留自己的顺序；剩余真实数据口不会因为改名而被灰色备用口替代。显示位置不改变通道的数据来源。

`键`仅用于配对，不占输入或输出的通道编号。只接一条 STRING 输入时，传入端显示“输入 1 · STRING”和“输入 2 · 任意”，所有同键传出端显示“输出 1 · STRING”和“输出 2 · 任意”。灰色任意口是供后续连接的备用口，不是第二份数据；不会因为键控件而多出一个 STRING 输出。旧工作流加载后会重新计算端口标签和数量，保留实际数据连线。

检查依据是各路是否实际连入下游，不是要求所有可见端口都连接：

| 连接情况 | 运行前结果 |
| --- | --- |
| 只用输出 1，输入 1 已连接，第二路为未用备用口 | 通过 |
| 输出 2 已接下游，但输入 2 未连接或不存在 | 报错并阻止提交，不以空值代替 |
| 任一同键传出端使用了缺少输入的通道 | 报错，指出具体传出端及唯一传入端 |
| 输入连线指向已不存在的上游接口 | 报错，须恢复有效上游连接 |

例如，传出节点 `257:713` 的输出 2 已连接，但传入节点 `722` 的输入 2 未连接，会提示：

```text
键“文档目录”第 2 路缺少有效输入：传出虚拟连接 257:713 的输出 2 已连接下游，但传入虚拟连接 722 的对应输入未连接或上游接口不存在。请连接输入 2，或断开该路传出连接。
```

运行与前端 API 导出都执行此检查；修改扩展后须刷新页面才能使用新检查逻辑。

## 常见问题与报错

| 现象 | 说明或修正方法 |
| --- | --- |
| 多个传出节点填写同键 | 正常，全部从唯一同键传入端取得数据，不会清空键 |
| 无发送端时出现 ANY 输出 | 便于先接收端后发送端的编辑；使用该输出运行前仍须配对 |
| 报“未找到传入虚拟连接” | 核对名称及发送端是否存在、是否被禁用 |
| 第 N 路未连接上游 | 发送端输入 N 尚未接数据，连接后再运行 |
| 上游类型变化后报错 | 现有连线会保留供检查，修改不兼容下游或添加转换节点 |
| 清空键后输出和连线消失 | 空键零端口的正常行为；发送端的键保持原样 |
| 在 API 中看到未转换的虚拟节点 | 使用安装本扩展的前端重新导出 API 工作流 |

两端本身是连线标记，请以真实下游业务节点为执行目标。没有使用的单端可留在画布上；已有传入端重名的异常文件会在提交前报错，不静默改写保存的数据。

## 开发与验证

节点 ID：`LiuxinyuVirtualInput`，分类 `liuxinyu/虚拟连接`。Python 定义由包根自动扫描注册；前端 `virtual_connections.js` 负责配对和端口同步，并在原生子图展开后改写 API 连线。UI JSON 保留节点与键，前端导出的 API JSON 只包含还原后的普通连线。

新增 Python 节点后重启后端，再刷新页面。非 UI 验证见 `tests/test_virtual_connections.cjs` 与 `tests/test_virtual_connections.py`，包括保存恢复、传入端重复键、多个传出端、跨子图、类型检查、循环检测和实际执行器的列表/嵌套分包行为。
