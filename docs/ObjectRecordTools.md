# 记录数组与路径字段处理

这组节点用于把文本解析成记录数组、列出记录位置、读取内容、组装字典，以及向多个对象添加字段。输入可以来自文件、接口、手动填写或其他数据处理节点；数据从哪里来、结果交给谁，都不影响节点的使用规则。

各数据节点可以独立使用，循环节点按配对规则连接。字段名和路径由工作流提供，按各节点的数据类型与参数规则连接即可。

## 按需要选择节点

| 你现在有什么，需要做什么 | 选择节点 | 得到什么 |
| --- | --- | --- |
| 一段文本，需要取出其中的 JSON 对象数组，并检查每条记录的字段类型 | [解析并校验 JSON 记录数组](LiuxinyuParseJSONRecords.md) | 记录数组、是否通过、错误信息 |
| 一个对象或数组，需要按层数和遍历开关列出位置 | [可遍历字典的索引列表](LiuxinyuArrayObjectPaths.md) | 索引数组和索引执行列表 |
| 已经有键和值，需要创建一个新字典 | [组装键值对](LiuxinyuBuildKeyValuePairs.md) | `{键: 值}` 对象；多个键可共用一个完整值 |
| 已有一个字典数组，需要把各字典字段合进一个新字典 | [并和数组中的字典字段为字典](LiuxinyuMergeDictionaryArray.md) | 一个完整字典；重复键报错 |
| 要遍历多个任务，并把每轮更新后的数据交给下一轮 | [分包跳回](LiuxinyuPacketReturnStart.md)＋[携包条件回归](LiuxinyuPacketReturnEnd.md) | 退出时的完整数据；具体修改由循环体执行 |

只解析一份标准 JSON、无需字段校验时，可用[字符串转为JS对象](LiuxinyuStringToJSObject.md)。只读一个位置可用[使用js点符号语句读取对象](LiuxinyuReadJSObjectPath.md)；只向一个位置补字段，或需要向数组追加成员，可用[插入字段到字典或者js对象](LiuxinyuInsertJSObject.md)。

## 文本、完整数组与执行列表

| 数据形式 | 含义与接法 |
| --- | --- |
| 文本 `[{"id":"A"}]` | 仍是 STRING；先解析，才能按字段或路径处理 |
| 解析后的对象数组 | 一个完整 ARRAY；数组内部的对象不会自动变成多次执行 |
| ComfyUI 执行列表 | 调度层面的多个执行项；需要作为一个数组处理时，先接[执行列表收集为数组](LiuxinyuCollectExecutionList.md) |

索引节点同时提供完整数组和执行列表；其他数据输出按完整值传递。解析节点另有布尔状态和错误文本输出。需要把其他数组交给下游逐项执行，可接[将任意数组转为执行列表](LiuxinyuArrayToExecutionList.md)。详见[数组、执行列表与图片批次](DataLists.md)。

文档中的 JSON 代码块用于展示数据形状。只有解析节点的“输入文本”，以及参数表中标为 STRING 的 JSON 配置，直接填写文本；DICT / ARRAY 端口需要连接解析后的对象或数组。

## 路径以哪份数据为起点

路径是对象内部的访问位置，不是文件路径或记录的业务 ID。例如 `items[0]` 表示输入数据的 `items` 数组第一项；根输入本身是数组时写 `[0]`；空字符串 `""` 表示整个根输入。

列路径、读取和插入必须使用相同的数据根与数组顺序。如果中途过滤、排序或只取了某个子数组，原路径可能指向其他记录，应重新生成或转换路径。节点不能仅凭一个仍然有效的下标判断记录身份是否已经改变。

例如 `[0][0]` 和 `[1][0]` 指向二维数组中两组各自的第一条记录；不能把原数据先压成一维数组后继续使用这些路径。记录中的 `imageIndex` 等业务字段与数组下标没有自动对应关系。

## 跟着接：给任务分配负责人

完整任务数据：

```json
[
  {"id":"A","title":"检查文件"},
  {"id":"B","title":"核对数量"}
]
```

分配记录：

```json
[
  {"owner":"Alice","paths":["[0]"]},
  {"owner":"Bob","paths":["[1]"]}
]
```

1. 两份数据如果来自文本，分别先解析。分配记录可用“解析并校验 JSON 记录数组”，将“必需字段与类型”填为 `{"owner":"nonempty_string","paths":"string[]"}`；根据“校验通过”选择后续分支。需要失败即停止时，按解析节点文档连接 Not、条件报错节点及等待分支。
2. 完整任务数据接“可遍历字典的索引列表”，使用默认的 -1 层、字段 false、数组 true，得到 `["[0]","[1]"]`，作为本次应处理的全部位置。
3. 分配记录数组接“将任意数组转为执行列表”。从同一个执行列表接两个“使用js点符号语句读取对象”，分别读取 `owner` 和 `paths`；每次处理同一条记录的两部分。
4. 第一个“组装键值对”的键填 `owner`，值接读取到的负责人，得到 `{"owner":"Alice"}` 等字段对象。
5. 第二个“组装键值对”的键接读取到的 `paths` 数组，值接上一步字段对象。第一条记录得到 `{"[0]":{"owner":"Alice"}}`，第二条得到 `{"[1]":{"owner":"Bob"}}`；此时原任务仍没有变化。
6. 将这些字典执行项接“执行列表收集为数组”，得到 `[{"[0]":{"owner":"Alice"}},{"[1]":{"owner":"Bob"}}]`。
7. 收集结果接“并和数组中的字典字段为字典”，重复路径键会报错。用结构化数据变换等节点核对这些键与第 2 步的路径数组完全一致，再整理成 `[{"path":"[0]","fields":{"owner":"Alice"}},{"path":"[1]","fields":{"owner":"Bob"}}]`。查找路径字典中的值时可用 JSONata 的 `$lookup`，按字面键查找。
8. 方案数组先接“将任意数组转为执行列表”，再接“分包跳回”的分包数据1，完整任务数据接被处理数据1。把分包回归条件直接连接“携包条件回归”。
9. 从当前分包数据1 分别读取 `path` 和 `fields`，接“插入字段到字典或者js对象”的挂载访问语句和新增值。当前被处理数据1 接插入节点的对象或数组。
10. 插入节点返回的完整结果接“携包条件回归”的处理完成数据1，选“与”，输入布尔 true；处理完成数据1 是所有包处理完后的结果。

最终输出：

```json
[
  {"id":"A","title":"检查文件","owner":"Alice"},
  {"id":"B","title":"核对数量","owner":"Bob"}
]
```

如果需要按多个路径取值并形成一个路径字典，可以用“索引执行列表 → 逐项读取”，再把路径与原值接“组装键值对”，收集后交给“并和数组中的字典字段为字典”。详细接线及空路径处理见[合并节点文档](LiuxinyuMergeDictionaryArray.md)。如果方案本来就是逐项的 `{path,fields}` 数组，先转换为执行列表再分包，不必先构造路径字典。

合并结果是一个完整字典；路径键对应的值保留整条记录，不是多项执行列表。若要把当前分组及这些记录交给模型，分别序列化后用 `{"group":{t1},"records":{t2}}` 组合。完整输入、输出以及引号规则见[从模板生成文本](LiuxinyuTextFromTemplate.md#把两份-json-文本组合成一份模型输入)。分组中的路径清单与记录字典的键应对应，不能将两套示例路径混用。

## 完整覆盖检查与输入保护

循环节点只管理包和回归的数据，不推断是否遗漏了业务记录。要求完整覆盖时，在循环前将方案路径集合与应有路径集合比较：两者必须没有重复，且不能少、不能多；顺序不限。应有路径为 `[]` 表示要求没有方案，不表示取消检查。

“组装键值对”只创建字典，键名无需是路径。合并字典数组检查重复键；单次插入检查路径是否存在、目标类型是否可插入、字段是否已经存在。路径可能有不同写法指向同一位置，要求每个位置只处理一次的工作流应统一使用索引节点生成的规范路径，并拒绝不在预期集合中的方案。

插入节点返回新结果，不原地修改原输入；路径上的容器会复制，未修改的分支与原值可以复用。后续某一包失败时，不会向循环外输出部分完成的数据，但循环体已经发生的其他副作用（例如写文件）不会自动撤销。

如果只允许处理某个分组，工作流应在组内检查成员，最后再核对全量覆盖。全量覆盖不能代替组内检查；分组名称是否唯一同样属于工作流的数据规则。
