# 工作区侧栏、文件后缀与系统打开

节点包自带的工作区扩展，无需在画布添加节点。提供工作区名称、完整文件名显示，以及通过 Windows 默认程序打开非工作流文件（包括普通 JSON 文档）的入口。安装或更新后端接口后重启 ComfyUI，再刷新页面；以后仅修改显示脚本时刷新页面即可。

## 显示范围

| 位置 | 显示效果 |
| --- | --- |
| 左侧原“工作流”入口及其悬停提示 | `工作区`（快捷键提示仍由原生界面附加） |
| 打开后的侧栏标题 | `工作区` |
| 侧栏搜索框 | `搜索工作区…` |
| 书签、浏览列表和搜索结果中的文件 | 显示完整文件名，保留真实后缀 |
| 设置为侧栏显示的“已打开”列表 | 同样显示完整文件名 |
| 单击普通文档的名称或文件图标 | 非 JSON 文件直接交给 Windows；JSON 先做保守结构检查，明确不是工作流时才交给 Windows |

这是界面扩展，没有节点输入或输出。侧栏仍使用 ComfyUI 原生文件树、搜索与书签；可能是工作流的 JSON 文件继续使用原生工作流打开操作，明确的普通文档使用下述系统打开操作。

## 使用示例

1. 刷新页面，点击左侧“工作区”。
2. 展开包含工作流和说明文档的文件夹。
3. 原先显示为 `快速设计详情页` 和 `渠道报告系统提示词` 的文件，现在分别显示为 `快速设计详情页.json` 和 `渠道报告系统提示词.md`。
4. 搜索文件或将文件加入书签，相应列表继续保留后缀。
5. 单击 `渠道报告系统提示词.md`，Windows 用已关联的 Markdown 程序打开该文件；当前 ComfyUI 画布不被这份文档替换。
6. 单击 `渠道分析报告模板（销量）.json` 这样的报告模板，检查确认没有工作流结构后，由 Windows 默认 JSON 程序打开，当前画布和打开的标签页保持不变。
7. 单击 `快速设计详情页.json`，识别到工作流结构后仍在 ComfyUI 中打开。

后缀来自文件树记录的真实路径，不统一补成 `.json`。例如 `方案.v2.json` 完整保留多个点；没有后缀的文件不凭空增加后缀。文件夹名称保持原样。

## 文件名与实际文件

文件名显示功能不重命名磁盘文件，不改变路径、书签记录或工作流保存内容。顶部工作流标签页、画布节点名称及其他界面的“工作流”用语不在此扩展的修改范围内。

重命名时，输入框沿用原生内容和保存规则；本扩展不向编辑框补入后缀。退出编辑后，列表根据更新后的文件路径重新显示完整名称。此扩展也不新增文件格式支持：显示 `.md` 后缀不代表原生工作流加载器可以将 Markdown 当作工作流执行。

## 用 Windows 默认程序打开

在工作区的浏览、书签、搜索结果或侧栏已打开列表中，**单击文件的行或图标**即可按其类型打开。双击的第二次点击不会重复发送打开请求；同一文件的打开请求未返回时也不会重复发送。

| 文件或操作 | 处理方式 |
| --- | --- |
| `.json`、`.JSON`、`.app.json` | 先读取并检查文件结构；只有明确是普通 JSON 文档才交给 Windows，可能是工作流时恢复原生点击处理。具体判断见下一节。 |
| `.md`、`.txt`、图片及其他非 JSON 文件 | 使用 Windows 的 `open` 动作，由系统文件关联选择程序；没有硬编码记事本、VS Code 或浏览器。 |
| 没有后缀的文件 | 同样交给 Windows，能否打开取决于系统关联。 |
| 文件夹 | 保留原生展开/收起操作，不打开资源管理器。 |
| 书签按钮、右键菜单、重命名输入框 | 保留原生行为，不触发系统打开。 |

请求传给 **ComfyUI 后端所在的电脑**：本机部署时在本机打开；另一台电脑通过浏览器访问时，程序仍在服务器的 Windows 桌面打开，不会下载到访问者电脑或替访问者选择程序。需要该 Windows 会话具备可交互桌面。

操作只请求系统打开文件，不修改内容、不执行工作流，也不等待外部程序关闭。若默认关联的动作本身是运行脚本或程序，Windows 会按其关联执行；这不是统一的“以文本编辑器编辑”功能。想更换打开程序，请在 Windows 中调整该格式的默认应用。

## JSON 的保守检查规则

检查发生在原生文件打开事件之前，后端只读取文件内容，不尝试加载画布或运行节点。

- 发现 `nodes`、`links`、`last_node_id`、`last_link_id`、`definitions`、`subgraphs` 等图结构字段，保留原生工作流处理。字段类型错误或内容不完整也不据此排除工作流。
- 发现 `graph`、`workflow`、`prompt`、`templates`、`version`、`class_type`、`inputs`、`widgets_values` 等可能的包装、版本或节点字段，或数字/冒号编号键，也保留原生处理。会检查嵌套对象和数组，避免误分流带包装的数据。
- JSON 语法损坏、编码无法解析以及空对象 `{}` 无法可靠排除工作流，仍交给 ComfyUI 诊断。
- 解析成功且没有这些工作流痕迹的普通对象、数组或标量，才交给 Windows。例如包含 `dataset_metadata`、`metrics_calculation_reference` 等章节的报告模板。

这是保守分流，不是完整的工作流合法性验证。普通业务 JSON 恰好含上述字段时也可能保留在 ComfyUI；不会为了提高外部打开比例而把可疑工作流排除。缺节点、节点参数错误、断线、版本不兼容、执行报错，都不是交给 Windows 的判据。

**被判定为普通文档的文件不会进入原生工作流加载，也不会新建标签页、切换活动画布或覆盖当前内容。** 检查请求失败时只提示错误，不尝试通过加载画布来判断。结构可能是工作流时则恢复正常打开行为，之后由 ComfyUI 自行报告问题，不在报错后回退到 Windows。

## 打开失败与修正

失败时页面显示“无法打开工作区文件”，包含相对路径和具体原因；不会回退成将文档加载为工作流。

| 现象 | 检查或修正 |
| --- | --- |
| 文件不存在或不是普通文件 | 文件可能已删除、移动或列表过期，刷新工作区列表后重试。 |
| Windows 尚未设置默认程序 | 在 Windows 的“打开方式”或默认应用设置中为该格式关联程序，然后再次单击。 |
| Windows 拒绝访问或其他启动错误 | 根据提示检查文件访问权限、默认程序是否安装正常。 |
| 提示需要 Windows | 当前后端运行在其他操作系统；此功能只提供 Windows 实现，侧栏显示功能仍可使用。 |
| 接口不存在或请求失败 | 确认后端已重启加载本包新接口，再刷新浏览器；查看后端日志或网络错误。 |
| 请求成功但当前浏览器所在电脑没有窗口 | 检查运行 ComfyUI 的 Windows 桌面，以及该格式已有程序的标签页；接口成功仅表示 Windows 接受了打开请求。 |

后端只接受当前 ComfyUI 用户 `workflows` 目录内的文件，按实际解析路径检查范围；拒绝绝对路径、上级目录跳转、目录本身和解析到工作区之外的链接。不接受任意系统文件路径。

## 刷新与兼容

- 展开目录、切换侧栏、更新书签、搜索和重命名后，会自动重新处理相应列表，不需要每次刷新整页。
- 只针对工作区侧栏进行处理，不修改“应用”、模型或节点侧栏的文件树。
- 当前按 ComfyUI 前端 1.53.6 的侧栏组件结构适配。原生文件树没有公开的显示名称扩展接口，因此使用限定侧栏范围的 DOM 显示适配；侧栏入口沿用包内的 Pinia store 访问方式。
- 更新后仍显示旧文字时，先强制刷新页面。前端升级若更改侧栏 store、元素标记或文件树结构，需要重新核对适配。禁用 `liuxinyu.WorkspaceLabels` 扩展并刷新页面后恢复原生显示。

## 开发与验证

前端实现位于 `workspace_labels.js`，通过本包 `WEB_DIRECTORY = "."` 自动提供给前端，并使用 `app.registerExtension` 注册。后端 `workspace_files.py` 沿用根目录 Python 自动扫描加载机制注册接口，不新增用户节点。不修改 ComfyUI 安装目录中的前端构建文件。

接口：`POST /liuxinyu/workspace/open-file`，请求类型为 `application/json`，内容例如 `{"path":"项目/说明.md"}`。`path` 是当前用户 `workflows` 目录下的相对路径，保留原文件名，不额外做 URL 编码。请求沿用原生 `comfy-user` 用户选择；系统接受外部打开时返回 `{"opened":true}`；JSON 可能是工作流时返回 `{"opened":false,"action":"workflow"}`，由前端恢复原生点击；失败返回 `{"error":"具体原因"}` 及对应 HTTP 状态。后端调用 Windows `os.startfile(..., "open")`，不拼接 Shell 命令。

针对性验证：`node tests/test_workspace_open.cjs`；使用 ComfyUI 的 Python 执行 `tests/test_workspace_files.py`。后端测试模拟系统打开调用，不实际启动桌面程序。

修改后检查脚本语法、扩展资源可访问性、文件路径与显示名称对应关系。页面最终验收应覆盖侧栏入口和标题、搜索提示、书签、目录展开和搜索结果中的后缀，以及重命名时的原生编辑行为。
