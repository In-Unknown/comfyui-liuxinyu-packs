# 解析并校验 JSON 记录数组

将整个输入文本作为一份完整 JSON 解析，要求它是由对象组成的数组，再逐条检查必需字段和字段类型。输出记录数组、校验是否通过以及错误信息，由下游决定如何处理失败。数组作为完整内容处理，不拆成多份文档或执行列表。

节点 ID：`LiuxinyuParseJSONRecords`；分类：`liuxinyu/结构化数据`。文本可以来自文件读取、接口响应、手动填写或任意输出 STRING 的节点；本节点不限定上游来源。

## 什么时候使用

适合“接收一组结构一致的记录，后续处理前先检查输入”的场景，例如导入任务清单、读取标注结果或接收字段赋值表。

| 需求 | 选择 |
| --- | --- |
| 已有一份完整 JSON 对象数组文本，需要检查字段 | 使用本节点 |
| 文本带说明或代码围栏，需要提取其中的记录数组再检查 | 先使用正则表达式提取节点，再把提取出的完整 JSON 文本接入本节点 |
| 只需解析标准 JSON，顶层可能是对象或含数字、字符串的数组 | 使用[字符串转为JS对象](LiuxinyuStringToJSObject.md) |
| 输入已经是原生对象数组 | 本节点只接收文本；通常直接交给后续数据节点，无需再解析 |
| 需要复杂嵌套规则、可选字段、枚举或数值范围验证 | 本节点的简单字段规则不足以表达这些要求 |

## 输入

| 参数 | 描述 | 数据类型 | 必需 |
| --- | --- | --- | --- |
| `输入文本`（`text`） | 一份完整 JSON 记录数组文本，支持多行和前后 JSON 空白；不能附带说明、代码围栏或第二份 JSON。本节点不截取内容 | STRING | 是 |
| `必需字段与类型`（`fields`） | JSON 对象文本，键是必需字段名，值是类型名称；默认 `{"id":"string"}` | STRING | 是 |
| `允许其他字段`（`allow_extra`） | 默认关闭；打开后允许并保留未列入规则的字段，这些额外字段不作类型检查 | BOOLEAN | 是 |

规则中的字段名对应每条记录的直接键，不是访问路径。例如 `"a.b"` 检查名为 `a.b` 的键，不会进入 `a` 对象读取 `b`。

## 输出

| 输出名称 | 描述 | 数据类型 |
| --- | --- | --- |
| `已校验记录数组` | 全部记录通过检查后的对象数组；校验不通过时为 `[]`。一个完整值，不展开为执行列表 | ARRAY |
| `校验通过` | 全部检查通过为 `true`；文本语法、字段规则或记录内容不合格为 `false` | BOOLEAN |
| `错误信息` | 通过时为 `""`；不通过时返回首个失败原因。记录内容错误包含记录序号、字段位置和期望类型；类型错误还包含实际类型和值预览，类型数组定位到具体元素 | STRING |

任意一条不合格，返回 `([], false, 错误信息)`，不输出部分通过的记录，也不主动报错停止工作流。节点不删除错误记录、不补默认字段，也不把数字字符串自动改成数字。

**需要同时使用状态输出判断结果。** 有效的空数组是 `([], true, "")`，校验失败也是空数组，但状态为 `false`；只看数组是否为空无法区分二者。

## 校验失败后怎么连接

| 需要的行为 | 连线方式 |
| --- | --- |
| 显示原因，继续处理其他分支 | “错误信息”接文本预览，“校验通过”接条件分支 |
| 换用备用数据 | “校验通过”接 If/Else Switch；true 分支接本节点数组，false 分支接备用数组 |
| 明确停止当前执行 | “校验通过”先接 Not，再接[条件为真时报错停止](LiuxinyuRaiseIf.md)；“错误信息”接该节点的错误信息输入 |
| 重试产生输入数据的过程 | 将状态、错误信息和待处理数据交给工作流的条件回归；自行设置重试条件、次数和重新生成输入的方法 |

本节点不内置重试，不清空其他节点内容，也不决定哪种来源应重新运行。若选择报错停止且要求数据下游必须先等待检查，可把停止节点的“继续执行”接到 If/Else Switch 的条件，true 分支接本节点数组，再将分支输出交给下游。只把停止节点挂在旁路，不能保证其他独立分支尚未执行。

## 字段类型怎么写

| 类型名 | 接受的值 | 不接受的例子 |
| --- | --- | --- |
| `string` | 任意字符串，包括 `""` 和空白字符串 | 数字 `12` |
| `nonempty_string` | 去掉首尾空白后仍有内容的字符串；检查后保留原文本，不裁剪空白 | `""`、`"   "` |
| `integer` | JSON 整数，如 `0`、`-2` | `1.0`、`true`、`"2"` |
| `number` | JSON 整数或有限浮点数 | `true`、`"2.5"`、`NaN` |
| `boolean` | `true`、`false` | `0`、`1`、`"true"` |
| `object` | 对象，包括 `{}`；不进一步规定内部字段 | 数组 |
| `array` | 数组，包括 `[]`；不规定成员类型 | 对象 |
| `null` | `null` | 缺少字段，或字符串 `"null"` |
| 上述类型加 `[]` | 该类型的一层数组，例如 `string[]`、`object[]`；空数组也通过 | `string[]` 中出现数字，或使用 `string[][]` 规则 |

所有列出的字段都必须存在，没有“可选字段”语法。类型名区分大小写；未知类型返回校验不通过和原因。这里使用简单的“字段名 → 类型名”对象，不是 JSON Schema。

空记录数组 `[]` 可以通过有效规则，因为没有记录需要逐条检查；本节点不规定最少记录数。规则为 `{}` 时，关闭“允许其他字段”只接受空对象记录；打开后可接受任意对象记录。

## 示例：检查任务记录

“输入文本”：

```json
[
  {"id":"A","count":2,"tags":["待检查"],"enabled":true},
  {"id":"B","count":0,"tags":[],"enabled":false}
]
```

“必需字段与类型”：

```json
{"id":"nonempty_string","count":"integer","tags":"string[]","enabled":"boolean"}
```

关闭“允许其他字段”。数组输出与输入 JSON 内容相同，状态为 `true`，错误信息为空；`count` 保持整数，`enabled` 保持布尔值。把 `count` 改成 `"2"` 后返回空数组、`false` 和类型错误说明；额外增加 `note` 时，需要打开“允许其他字段”才会保留该字段并通过。

## 完整文本与显式提取

本节点直接解析整个输入。前后空格、制表符和换行可以保留；JSON 字符串内部的文字、引号、转义和括号按 JSON 语法处理。它不会删除解释文字、剥离代码围栏、查找子数组或选择多份 JSON 中的一份。

例如以下文本直接接入会返回空数组、`false` 和解析错误：

```text
结果如下：
[{"id":"A"}]
以上是结果。
```

如果需要允许前后说明，应明确连接：

```text
原始文本 → 正则表达式提取（RegexExtract）→ 本节点的输入文本
```

针对上例以及 `recordPath` / `subtopic` 这类字段值为字符串、没有嵌套数组的记录，可在提取节点填写：

```regex
(\[\s*(?=\{|\])(?:[^"\[\]]|"(?:\\.|[^"\\])*")*\])
```

模式用 `First Match`，忽略大小写、多行和点号匹配所有均关闭；分组索引可保持 `1`（`First Match` 实际返回整个匹配，不使用分组索引）。上例提取出 `[{"id":"A"}]`，规则填 `{"id":"string"}` 后校验通过。无匹配时提取节点输出空字符串，本节点校验失败；匹配出的文本不合法或字段不合格也会失败。

该表达式不是通用 JSON 解析器，不适用于含嵌套数组的字段；例如 `recordPaths` 为字符串数组时，应另设支持该结构的提取表达式。若文本中有多份数组，选哪一份由提取节点的规则决定，不能用校验节点暗中筛选或回退。输入有两份 JSON（例如 `[]\n[]`）时，本节点直接判定失败。

完整 JSON 的顶层可以是对象、数组或标量，这是 JSON 语法的范围；本节点另有“记录数组”契约，因此最终只有对象数组符合要求。普通对象或其他 JSON 值虽然可解析，也会返回类型校验失败。只需解析对象或任意 JSON 值时，使用[字符串转为JS对象](LiuxinyuStringToJSObject.md)。

**旧工作流迁移：** 本节点已取消隐式选取最后一份 JSON 的行为。原先直接传入 LLM 带说明的回复、围栏文本或多份 JSON 的工作流，需要在前面显式接提取节点；已经输出完整 JSON 的上游无需改变。节点 ID、输入输出端口及字段规则保持不变。更新 Python 后需重启 ComfyUI，重新加载修改后的工作流。

## 错误信息如何定位

记录序号、数组元素序号从 **1** 开始；`位置` 中的数组下标从 **0** 开始。`$` 表示输入的完整 JSON 文档的根，字段用带 JSON 引号的方括号表示，因此字段名包含点号、引号或方括号时也不会与访问路径混淆。

例如规则为 `{"count":"integer","recordPaths":"string[]"}`，第一条记录为 `{"count":"2","recordPaths":[]}`，返回：

```text
第 1 项的 'count' 必须是 integer。位置 $[0]["count"]；实际为 string，值为 "2"。
```

若前面的记录通过，而第 2 条记录的 `recordPaths` 是 `["[0][0]","[0][1]",123]`，返回：

```text
第 2 项的 'recordPaths' 第 3 个元素 必须是 string。位置 $[1]["recordPaths"][2]；实际为 integer，值为 123。
```

这是定位到数组字段内部第一个类型错误的元素，不会笼统地只说“需要 string[]”。若字段本身不是数组，则仍报告完整字段要求，例如 `recordPaths` 必须是 `string[]`，并说明实际收到的类型和值。

| 问题 | 错误信息示例 |
| --- | --- |
| 第一项 topic 为空白字符串 | `第 1 项的 'topic' 必须是 nonempty_string。位置 $[0]["topic"]；实际为 string，值为 "  "。` |
| count 收到布尔值而不是整数 | `第 1 项的 'count' 必须是 integer。位置 $[0]["count"]；实际为 boolean，值为 true。` |
| 第一项缺少 count | `第 1 项字段不符合契约；缺少 ['count']，额外 []。位置 $[0]。` |
| 第 2 项是 null 而不是对象 | `第 2 项需要是对象。位置 $[1]；实际为 null，值为 null。` |

一次只报告首先发现的问题：先检查文本和字段规则，再按记录顺序检查；每条记录先检查缺失或不允许的额外字段，再按规则字段顺序检查类型，类型数组按元素顺序检查。修正后再次校验，才会报告后续错误。打开“允许其他字段”后，允许的额外字段不会被列为字段错误。

字符串实际值以 JSON 字符串形式显示，保留换行、引号等转义；超过 120 个字符只预览前 120 个字符，并明确标记截断。实际值为数组或对象时只显示类型及元素/字段数量，不展开整个容器。该预览限制不改变输入或通过后的输出。

上述字段路径适用于已成功解析后的记录内容。输入不是一份完整 JSON、重复键、无效字段规则等问题仍返回相应解析或规则错误，不保证具有记录索引或字段路径。本节点不会把所有错误汇总成列表，也不自动补写修复后的数据。

## 校验不通过的情况

| 情况 | 检查方法 |
| --- | --- |
| 输入包含说明、围栏、多份 JSON 或语法错误 | 在上游显式提取一份完整 JSON；本节点不会自动截取或去除包裹文本 |
| 输入为空或只有空白 | 提供完整 JSON 记录数组；空记录数组应写为 `[]` |
| JSON 顶层需要是记录数组 | 顶层应为 `[{...},{...}]`，不能是 `{...}`、`[1,2]` 或 `[null]` |
| 缺字段或有额外字段 | 对照规则中的直接键；需要保留额外字段时打开对应开关 |
| 字段类型不符 | 按实际类型填写，数字与数字字符串不会自动互转 |
| 字段规则无效 | 规则自身必须是合法 JSON 对象，类型名必须受支持 |
| 重复键或非标准数值 | 同一个 JSON 对象不能重复写同名键；`NaN`、`Infinity` 和浮点溢出会使校验失败 |

以上输入与规则问题均通过状态和错误文本输出；程序缺陷、内存不足等非校验故障不在失败状态转换范围内。检查不包含 ID 唯一性、业务含义、引用是否存在或完整覆盖。校验通过后，可用读取节点取字段，再接[组装键值对](LiuxinyuBuildKeyValuePairs.md)；需要写回数据时，用[分包跳回](LiuxinyuPacketReturnStart.md)配合单次插入；是否完整覆盖目标由工作流显式检查。只查看内容可接[预览JS对象或数组](LiuxinyuPreviewJSObject.md)。
