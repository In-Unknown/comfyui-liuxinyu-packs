# 整理节点

框选一组节点，右键选择 **整理节点**，优先寻找零冲突的节点位置与端口显示顺序；未找到时，采用本次搜索中优于现状的方案，并继续压缩空白、居中对齐。适合已经完成连线、希望把多条支线整理清楚的区域；不需要添加工作流节点，也不执行工作流或调用付费模型。

本功能沿用[端口显示排序](PortOrder.md)的保存方式。计算在运行 ComfyUI 的电脑上完成；只有按实际端口位置复核后仍优于原布局的方案才修改画布。

## 入口与操作

1. 在经典画布中框选 **2～40 个节点**，连线样式使用“样条 / Spline”。
2. 右键所选节点或画布空白处，点击 **整理节点**。
3. 右下角显示拓扑检查、搜索、压缩和居中对齐阶段，以及已尝试布局数、耗时和冲突数量。可随时点“取消整理”。
4. 使用原生撤销可撤回本次整理；满意后正常保存工作流。

成功后节点移动、端口显示顺序更新；没有找到更好的方案或取消时保留原布局。计算期间菜单显示“整理节点（计算中）”，不会重复发起请求。

菜单项右侧带有小号灰蓝色 `liuxinyu` [来源标签](MenuSource.md)，便于与默认选项区分。在所选节点上右键也能看到“整理节点”；即使与本包其他选项相邻，每项也各自显示标签。标签不影响点击和计算中禁用状态。

**等待期间可以缩放、平移画布，结果不会因此作废。** 检测只比较节点位置、尺寸、端口几何与身份、显示排序、固定/折叠状态和连线；不比较保存于 `extra.ds` 的视口缩放与平移，也不因与布局无关的文本或属性修改而中止。真正拖动节点、改线、增删端口或切换画布时才放弃旧结果，保留你的编辑。

## 输入

本功能没有节点输入口，读取当前画布的几何快照。

| 参数 | 描述 | 数据类型 | 必需 |
| --- | --- | --- | --- |
| `所选节点` | 一次选择 2～40 个节点；读取位置、尺寸、端口坐标和现有显示顺序 | 画布节点集合 | 是 |
| `当前画布连线` | 源、目标节点 ID 和实际端口索引，包括连接到未选节点的线 | 连线集合 | 是 |
| `未选节点与子图边界` | 作为固定障碍与固定端点参与检查 | 画布几何信息 | 自动读取 |

发送给后端的内容包含 ID、位置、尺寸、端口几何、连接索引及本次搜索种子。提示词、文本框内容、API 配置和工作流业务数据不会发送到整理接口。变化检测在浏览器内比较布局相关字段，不序列化整个工作流来判断视口操作。

## 输出

没有执行输出口，不产生图片、文本结果或执行列表。

| 输出名称 | 描述 | 数据类型 |
| --- | --- | --- |
| `节点位置` | 仅更新所选节点的位置，不移动未选节点、子图边界或分组框 | 画布坐标 |
| `端口显示顺序` | 输入侧、输出侧分别排序，绑定输入框随端口整行移动，原始索引不变 | 节点显示属性 |
| `结果提示` | 已应用改善方案、未找到更好布局、取消或当前模式不支持；报告冲突数量的前后变化及剩余冲突的节点 ID 与连线方向 | 界面消息 |

节点高度可能因输入框重新排列而增加，处理方式与手动端口排序相同。节点 ID、类型、参数值、输入输出数组原始顺序、连线 ID、源目标索引及执行语义均保持不变。

## 使用示例：两条分支汇合

```text
A → B → D 的“输入 2”
A → C → D 的“输入 1”
```

假设 B 在上、C 在下，D 当前从上到下显示“输入 1、输入 2”，两条汇入线交叉。

1. 选中 A、B、C、D，右键选择“整理节点”。
2. 算法可以将 D 的显示顺序调整为“输入 2、输入 1”，也可以同时调整节点位置。
3. B 始终连接 D 原来的“输入 2”参数，C 始终连接原来的“输入 1”参数，不会因视觉排序互换业务输入。
4. 若旁边有未选节点 E，E 不移动，新的连线也需要避开它。

这里的“输入 1/2”表示端口名称，底层索引仍按原工作流保存，整理不会重建连线。

## 平面性与几何检查

计算依次进行：

1. 对所选节点间的连接做无向拓扑平面性检查。方向不影响这一步，重复边只在拓扑判定中合并，实际几何检查保留每条连线。非平面拓扑只说明不能消除全部交叉，仍继续搜索可改善的布局。
2. 以现有位置为起点尝试端口排序，再使用分层、长边占位、支线顺序调整及有界位置搜索寻找布局。长边占位只是内部算法数据，不向工作流添加节点。
3. 根据未选的上游、下游端点约束链条的起点和终点，避免把入口排到固定上游的后方。每一列按实际节点宽度留距；已连接端口优先排序，未连接的控件端口保留相互顺序放在后面。
4. 检查节点重叠、连线交叉和连线穿过节点。保留本次搜索中较好的候选，找到零冲突方案或搜索时限到达后，继续压缩空白、拉近松散的来源支线、对齐短链；已有冲突不阻止这些整理步骤。
5. 对相邻的独立支线进行同列垂直居中，再从主链尾端开始合并水平中心线，最后尝试将跨越支线的连接也对齐。每次合并整组移动，保持已经形成的行列关系，并重新检查交叉和遮挡。
6. 浏览器用实际布局函数测量候选的端口和输入框位置，再交由后端复核；测量后先恢复画布，与整理前的实际几何比较，仍有改善才正式应用。

初步搜索采用曲线采样；最终复核按经典画布左右端口的三次贝塞尔曲线自适应细分，几何误差目标为 0.25 画布像素，并为相邻曲线留出余量。共用同一端口的线允许在端口附近 12 像素内自然汇合，超出此范围的重叠仍检查。节点检查包括标题栏，节点之间保留间距。

检查范围是**涉及本次整理的几何关系**：选中节点、关联连线与当前画布其他节点和线之间的关系。完全位于未选区域且不受整理影响的旧交叉或旧重叠，不要求同时消除。分组背景、框外附加名称标签和其他扩展自定义绘制内容不作为实体障碍。

## 如何判断比现状更好

候选与原布局按以下顺序比较，前一项相同时才比较下一项：

1. 节点重叠数量更少。
2. 连线穿过节点的数量更少。
3. 连线之间的交叉数量更少。
4. 三项数量全部相同时，连接更紧凑、向左回折更少。

第 4 项使用相连端口之间的直线距离之和，再加上向左回折水平距离的三倍作为代价；减少超过 1 个画布像素才算改善。这是布局评价指标，不是样条曲线实际弧长。优先保证节点可读，因此搜索时减少重叠可能伴随较低优先级的交叉增加；结果提示会显示各项前后数量。

例如原来有 8 处交叉，整理后仍有 2 处，但重叠、穿框均为 0，就会应用并继续对齐。三项冲突数相同但连线明显缩短，也可以应用。三项均未改善且连接代价未下降，则保留原样。

压缩和对齐阶段要求三项冲突数分别不增加；若对齐后不再优于原布局，会退回仍有改善的候选。最终是否应用以浏览器实际测量的端口与控件几何为准，不只看搜索阶段的预测。

## 水平和垂直居中

- **同一行**：以包含标题栏的节点框中心为基准，使能安全合并的主链节点处在同一条水平中心线上。预览节点比工具节点高时，整体节点框居中，不再为了对齐顶部端口而让预览框挂在主链上方。
- **同一列**：对位置相近、彼此没有先后依赖的支线节点对齐水平中心坐标。节点宽度不同时也按中心对齐，不只是左边缘贴齐。
- 优先沿最长依赖链对齐，再处理侧支和跨越连接；不会把有前后依赖的连续处理节点硬塞进同一列。
- 每次对齐都检查全部受影响的连线和节点。只有交叉、穿框、重叠三项数量均不增加时才接受合并。某处尚有交叉时，其他行列仍可以对齐；已经通过检查的对齐继续保留。
- 不同高度或不同端口行数的节点，框中心对齐后，端口之间仍可能有小幅弯曲；连接端口和参数身份保持原样。固定的外部节点、子图边界始终不移动。

例如条件回归节点后面连接“恢复内存检查和回收 → 预览任意”时，优先让这段尾链与主链共用水平中心线；主链旁边的常量支线按附近的列中心排列，减少零交叉但上下左右散乱的观感。

## 如何理解结果

| 提示 | 含义及处理 |
| --- | --- |
| 已整理若干节点 | 已通过候选及实际端口几何检查，报告冲突数量的前后变化、尝试数和耗时；正常保存即可 |
| 连接拓扑无法消除全部交叉，继续搜索 | 这是搜索阶段提示，不是终止。例如 K₅、K₃,₃ 或其细分结构无法全部消除交叉，仍搜索并应用优于原布局的方案 |
| 已采用本次找到的改善方案，仍有剩余冲突 | 已应用更好的布局，并报告剩余冲突，例如“2→4 与 12→2 交叉”；可以保存或撤销 |
| 本次没有找到比现状更好的布局 | 原布局保留；不代表不存在更好的排列，只代表本次搜索没有找到 |
| 按实际端口位置复核后，没有优于原布局 | 搜索预测有改善，但实际控件和端口位置测量后未改善；保留原布局，并列出相关冲突 |
| 计算期间工作流已变化 | 实际节点或连线布局已改变，原快照过时；缩放、平移不会触发此提示 |
| 已取消整理 | 浏览器中止请求，后端收到断开后停止搜索，画布保持原样 |

主要搜索上限约 **45 秒**，找到零冲突候选可提前进入压缩、居中对齐和复核；否则在搜索结束后处理当前最佳候选。复杂画布的当前几何检查、压缩、对齐和实际坐标复核可能使总耗时更长。搜索连接等待上限为 90 秒，实际几何复核请求为 30 秒；进度从后端流式传回，不是模拟百分比。每次新操作使用新的搜索种子。

算法不穷举全部位置和端口排列，因此不是任意约束布局问题的完备求解器。“本次最佳”指有限搜索中找到的候选，不保证数学上的全局最优。根据剩余冲突，可将相应外部节点加入选择、调整起始位置，或重新搜索其他候选。

## 示例：带固定入口的条件回归链

例如选中 `2、4、5、6、7、8、9、10、11、13`，上游 `3→12` 保持未选，而 `12→2` 是进入所选区域的连线。内部既有 `2→4→7→8→11→6→13→10`，也有跨越中间节点的 `2→6` 与 `7→6`。

整理时会把固定的 12 当作入口锚点，保留它的位置，避免为了居中铺开长链而将 2 放到 12 左侧，制造新的回折交叉。长连线与短支线共同参与排序和几何检查。这条规则适用于任意节点 ID，不是专门识别“调回点”或硬编码这个示例。

## 子图、外部连线与保存

- 子图内部只整理当前打开的一层，输入输出边界作为固定端点，不递归改动其他嵌套层。外层的子图节点作为普通节点框处理，不改其内部。
- 未选节点的位置和端口顺序不变，其连接线一起参与检查。
- 选中的 Note 与无连线节点一样参与位置和重叠处理；不改写文字，也不自动绑定它所解释的节点。没有端口的 Note 不写入端口排序，文本框使用原生尺寸布局，重复整理不会持续增高；旧空排序记录也不会触发重排。
- 分组框不移动、不增删、不自动调整大小；需要重新打组时使用原生分组操作。
- 成功应用作为一次原生画布编辑，可撤销、重做。位置按原字段保存，端口顺序保存到 `properties.liuxinyu_port_order`，与手动 ↑ / ↓ 排序兼容。
- 已经手动调整端口或自动整理过的节点可以再次整理。保存和还原端口顺序时按版本号、输入顺序、输出顺序复制为独立数据，支持前端响应式属性及数组；不会因已有排序记录而出现 `structuredClone` 无法复制对象的错误。

## 兼容范围与常见问题

| 现象或条件 | 说明 |
| --- | --- |
| 右键没有入口 | 至少选中两个当前画布节点；更新 JS 后刷新页面 |
| 提示需要重启后端 | `/liuxinyu/layout` 尚未加载，重启 ComfyUI 后刷新页面 |
| Vue Nodes、只读画布或其他连线样式 | 当前支持可编辑经典画布的样条曲线模式，不自行切换全局设置 |
| 选中折叠、固定或水平端口节点 | 先展开、取消固定；当前要求标准左右端口布局 |
| 画布包含连线转接点 | 当前不求解转接点路径，会明确提示，保持原样 |
| 端口指定上/下方向 | 当前不建立这类曲线的几何模型，会明确提示 |
| 规模太大 | 最多选 40 个节点，当前层快照最多 500 个节点、1000 条线，可进入较小子图处理 |
| 其他扩展绘制特殊端口或控件 | 实际测量后复核；自定义画法可能超出标准模型，页面视觉效果仍需核对 |
| 旧版整理后 Note 持续变长 | 更新并刷新页面后停止增长；已经拉长的尺寸可手动缩回后保存。修复不猜测原始尺寸，也不改 Note 文字 |

`graph_layout.js` 使用现有扩展菜单，`graph_layout.py` 沿用包根模块自动加载与 `PromptServer` 路由注册，没有新增用户节点。复用 ComfyUI 环境中的 NumPy、NetworkX 和 aiohttp。

命令行回归入口（在节点包目录运行）：

```shell
node tests/test_graph_layout.cjs
node tests/test_port_order.cjs
../../../python_embeded/python.exe -B -s tests/test_graph_layout.py
```

Python 测试覆盖非平面图继续搜索并返回改善方案、无改善时不生成应用计划、残余交叉不阻止其他行列对齐、冲突优先级与等冲突紧凑度比较、对齐期间取消，以及分支汇合、外部障碍、实际方案重建检查、打乱的 16 节点区域和固定入口条件回归链的多个搜索种子；另验证不同高度节点的水平中心线、不同宽度支线的垂直中心线和主链对齐后仍保持零交叉。还通过本地 aiohttp 测试验证流式进度、最终复核与原布局比较（接受有剩余冲突的改善方案、拒绝相同或更差结果）和断开后停止计算。

JS 测试覆盖原索引保留、失败不应用、缩放/平移不误判、实际移动节点作废、无关属性保留、一次撤销事务、子图边界、分块 UTF-8 进度解码及取消操作；还覆盖响应式端口属性和嵌套数组、连续再次整理，以及失败时还原原有排序。另覆盖部分改善方案的一次撤销事务、发送原始几何作为比较基准、实际复核否决预测改善，以及提示采用实际测量的冲突数。`tests/fixtures/layout_theta.json`、`layout_loop.json` 只包含脱敏几何与连线，不含原工作流提示词或凭据。
