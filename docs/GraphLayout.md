# 整理节点

框选一组节点，右键选择 **整理节点**，优先寻找零冲突的节点位置与端口显示顺序；未找到时，采用本次搜索中优于现状的方案。完成原有压缩与居中对齐后，继续按相连端口拉直线条、将共同汇入同一节点的支路归列，并收紧局部间距。适合已经完成连线、希望把多条支线整理清楚的区域；不需要添加工作流节点，也不执行工作流或调用付费模型。

本功能沿用[端口显示排序](PortOrder.md)的保存方式。计算在运行 ComfyUI 的电脑上完成；只有按实际端口位置复核后仍优于原布局的方案才修改画布。

**优先保持当前端口显示顺序，只移动节点来消除交叉与穿框。** 找到零交叉、零穿框、零重叠的保序方案后，继续在保序条件下压紧和对齐；即使换序方案线更短，也优先采用保序方案。固定顺序的搜索未找到无冲突方案时，才开放端口换序继续搜索。

## 入口与操作

1. 在经典画布中框选 **2～40 个节点**，连线样式使用“样条 / Spline”。
2. 右键所选节点或画布空白处，点击 **整理节点**。
3. 右下角显示拓扑检查、保持端口顺序的位置搜索、必要时开放换序、压缩、居中对齐及“按输入顺序拉直、联合避让挡路节点，并整理输入/输出侧同列支路”阶段，以及已尝试布局数、耗时和冲突数量。可随时点“取消整理”。
4. 若找到多个接近最优方案，会默认应用一个并打开“整理方案”浮窗；点击列表即可立即切换，拖动顶部可以移动浮窗，点“确定”保留当前方案并关闭窗口。
5. 使用原生撤销可撤回整理或方案切换；满意后正常保存工作流。

成功后节点移动、端口显示顺序更新；没有找到更好的方案或取消时保留原布局。计算期间菜单显示“整理节点（计算中）”，不会重复发起请求。

菜单项右侧带有小号灰蓝色 `liuxinyu` [来源标签](MenuSource.md)，便于与默认选项区分。在所选节点上右键也能看到“整理节点”；即使与本包其他选项相邻，每项也各自显示标签。标签不影响点击和计算中禁用状态。菜单通过公共入口按 `menu_order.js` 的稳定 ID 排序，“计算中”文字不改变位置。

**等待期间可以缩放、平移画布，结果不会因此作废。** 检测只比较节点位置、尺寸、端口几何与身份、显示排序、固定/折叠状态和连线；不比较保存于 `extra.ds` 的视口缩放与平移，也不因与布局无关的文本或属性修改而中止。真正拖动节点、改线、增删端口或切换画布时才放弃旧结果，保留你的编辑。

## 输入

本功能没有节点输入口，读取当前画布的几何快照。

| 参数 | 描述 | 数据类型 | 必需 |
| --- | --- | --- | --- |
| `所选节点` | 一次选择 2～40 个节点；读取位置、尺寸、端口坐标和现有显示顺序 | 画布节点集合 | 是 |
| `当前画布连线` | 源、目标节点 ID 和实际端口索引，包括连接到未选节点的线 | 连线集合 | 是 |
| `未选节点与子图边界` | 作为固定障碍与固定端点参与检查 | 画布几何信息 | 自动读取 |

发送给后端的内容包含 ID、位置、尺寸、端口几何、连接索引及本次搜索种子。提示词、文本框内容、API 配置和工作流业务数据不会发送到整理接口。变化检测在浏览器内比较布局相关字段，不序列化整个工作流来判断视口操作。

## 输出

没有执行输出口，不产生图片、文本结果或执行列表。

| 输出名称 | 描述 | 数据类型 |
| --- | --- | --- |
| `节点位置` | 仅更新所选节点的位置，不移动未选节点、子图边界或分组框 | 画布坐标 |
| `端口显示顺序` | 优先保持原显示顺序；需要换序时，输入侧、输出侧分别排序，绑定输入框随端口整行移动；子图接口同步内部边界与同定义实例，原始索引不变 | 节点与子图显示属性 |
| `结果提示` | 已应用改善方案、未找到更好布局、取消或当前模式不支持；报告冲突数量的前后变化及剩余冲突的节点 ID 与连线方向 | 界面消息 |
| `接近最优方案` | 存在多个通过实际几何复核的接近最优布局时，浮窗提供最多 5 个不同方案，点击即显示 | 临时布局列表 |

节点高度可能因输入框重新排列而增加，处理方式与手动端口排序相同。节点 ID、类型、参数值、输入输出数组原始顺序、连线 ID、源目标索引及执行语义均保持不变。

## 多方案选择浮窗

搜索与精修会保留评分靠前、接近最优的不同布局。先按重叠、穿框、交叉数量及综合布局代价排序；候选必须与第一名的三项冲突数量分别相同，综合布局代价最多高出第一名的 15%（代价很小时至少允许相差 1），再保留前 5 名。方案不需要同分，各方案也仍须优于整理前的布局。仅仅交叉数量相同、但穿框更多或连线明显更长的方案，不会混入列表。

若存在保留原端口顺序的无冲突方案，优先从这些保序方案中排名并提供最多 5 项，15% 的差距相对于其中的第一名计算。前端实际复核也采用这一优先级。应用保序方案时只改变节点位置，不新建或改写端口排序属性；完成提示会显示“已保留原端口顺序，仅调整节点位置”。

整体平移不用于凑方案数，相对坐标按一个画布单位的精度去重；去重同时检查节点身份、相对位置和端口显示顺序，存在固定节点时也保留相对于固定节点的位置关系。初步搜索保留最多 10 个不同候选，不同候选会在共同的精修时限内继续拉直与压紧，最终按上述评分排序筛选。最多保留 5 个方案，不足 5 个按实际数量展示，只有一个时直接应用而不开窗。所有方案都必须优于整理前的布局。

显示前逐个用前端的真实端口和控件布局测量，并由后端重新评分。测量后差距超过阈值或不再有改善的候选会被排除，因此窗口中的数量可能少于搜索阶段保留的数量。

完成提示会明确说明选择窗是否出现：本次只找到一个符合条件的最佳方案时，提示没有其他差距足够小的方案可切换；搜索曾保留多个、但实际复核后只剩一个时，显示搜索候选数及复核后的数量。全部零交叉仍可能只有一个最佳方案，因为评价还比较穿框、重叠、连线长度、对齐和占地。

例如本次找到 3 个接近最优布局：

1. 整理完成后直接显示评分最低的“方案 1（推荐）”，浮窗内该项高亮；其他方案标出相对第一名的评分差距，例如“↓4.2%”，表示评分表现低于推荐方案，即综合布局代价高出 4.2%。悬浮提示说明“分数越低越好”；该百分比不是交叉数或实际线长的百分比。
2. 点击“方案 2”，画布立即切换位置与端口显示顺序；再点“方案 1”可以来回比较。
3. 拖动窗口顶部“整理方案”标题，把它移到不遮挡节点的位置。
4. 点击“确定”，关闭窗口并保留当前显示结果；之后照常保存工作流。

窗口有外描边，没有模态遮罩、不抢焦点、不注册键盘拦截。画布的快捷键、缩放和平移照常使用。初次应用和每次切换分别是一次完整的原生撤销操作；“确定”只关闭窗口，不增加空的撤销记录。保存时写入当前显示的布局，不需要等到确定后才能保存。

如果继续移动节点、改变连接或端口、执行撤销，或者切换工作流／子图，旧候选窗口会自动关闭并保留当前操作。再次整理也会结束上一次选择。浮窗位置与候选列表只在当前页面保留，不写入工作流；工作流正常保存的是所选方案的节点位置和端口顺序。

## 使用示例：两条分支汇合

```text
A → B → D 的“输入 2”
A → C → D 的“输入 1”
```

假设 B 在上、C 在下，D 当前从上到下显示“输入 1、输入 2”，两条汇入线交叉。

1. 选中 A、B、C、D，右键选择“整理节点”。
2. 算法先尝试交换 B、C 的上下位置等位置调整，保留 D 的端口顺序；若保序搜索未找到无冲突方案，再尝试将 D 的显示顺序调整为“输入 2、输入 1”。
3. B 始终连接 D 原来的“输入 2”参数，C 始终连接原来的“输入 1”参数，不会因视觉排序互换业务输入。
4. 若旁边有未选节点 E，E 不移动，新的连线也需要避开它。

这里的“输入 1/2”表示端口名称，底层索引仍按原工作流保存，整理不会重建连线。

## 平面性与几何检查

计算依次进行：

1. 对所选节点间的连接做无向拓扑平面性检查，并保留平面嵌入，用其方向顺序和当前位置构造额外的分层候选。方向不影响平面性检查，重复边只在拓扑判定中合并，实际几何检查保留每条连线。非平面拓扑只说明不能消除全部交叉，仍继续搜索可改善的布局。
2. 先保持当前端口显示顺序，以现有位置和较早／较晚分层、等距／按实际高度密集排布等起点搜索节点位置。在固定顺序的搜索时限内未找到无冲突方案，再允许端口换序；拓扑已确定非平面时直接继续寻找改善方案。密集排布按每个节点自己的宽高留距，结合相连端口相对节点中心的偏移调整支线；长边占位只是内部算法数据，不向工作流添加节点。
3. 根据未选的上游、下游端点约束链条的起点和终点，避免把入口排到固定上游的后方。每一列按实际节点宽度留距；已连接端口优先排序，未连接的控件端口保留相互顺序放在后面。
4. 检查节点重叠、连线交叉和连线穿过节点。优先调整实际冲突涉及的节点与端口，保留多个较好候选分别细化；找到第一个零冲突方案后仍继续比较。后续尝试具体端口交换、冲突局部移动、空白压缩和短链对齐；已有冲突不阻止这些整理步骤。
5. 对相邻的独立支线进行同列垂直居中，再从主链尾端开始合并水平中心线，最后尝试将跨越支线的连接也对齐。每次合并整组移动，保持已经形成的行列关系，并重新检查交叉和遮挡。
6. 对齐后按整行、整列再次收紧空隙。某一对节点已经靠近时，仍可压缩其他位置的大间隔；收紧不拆散已形成的中心线，也不改变顺向连接的左右关系。
7. 在原有结果上追加联合精修：先处理靠下游的目标节点，其输入口按实际显示位置从上到下处理。尝试固定目标拉直上游，或固定上游移动目标；在相关节点边界处试摆横坐标，联合移动挡路节点，再从下游向上游压紧中间支路。中间试摆可以暂时有冲突，只在完整候选的三类冲突均不增加且评价改善时接受。
8. 继续将共同主目标的上游支路、同一输出口分出的下游独立节点归列。已经拉直的链整体移动，再逐支路及整行整列收紧间距；已确定的主线不会被后处理的输入再次拉弯。
9. 保留原搜索与精修结果，再对候选追加整组坐标约束压缩，并比较结构构造的候选。新步骤没有改善时沿用之前的结果。
10. 浏览器用实际布局函数测量候选的端口和输入框位置，再交由后端复核；测量后先恢复画布，与整理前的实际几何比较，仍有改善才正式应用。

### 结构构造、缓存与整组压缩

- **端口顺序参与结构构造**：根据相邻层和对方实际端口的上下关系排列节点。每层不超过 10 个内部顶点时，使用子集动态规划精确求该层在当前邻层位置下的最少逆序排列；长边占位也计入这 10 个。更大的层采用稳定插入排序。这个局部最优不等于整个画布的几何最优，仍须检查节点框和真实曲线。
- **换序时补充独立起点**：保序阶段未找到无冲突结果时，在继续原有搜索的同时，额外准备独立的较早／较晚密集分层候选。补充候选不重置原有搜索的随机状态，也不挤占原候选的精修预算。压缩和对齐后已经变成同一布局的候选按现有的一画布单位精度去重，避免重复精修，为其他方案留出时间。
- **精确坐标缓存**：一次整理中复用未变化曲线、曲线之间和曲线与节点框之间的几何检测结果。缓存键包含端点坐标、精度模式和端口共用关系，不以四舍五入坐标代替检查；节点移动、端口改变或尺寸变化会形成不同的键。缓存有容量上限，请求完成、取消或异常后释放。
- **筛选与最终评分一致**：进入精修的候选按冲突数和最终采用的连线评分排序，避免仅因框中心不齐，就丢弃端口连线更短、更直的方案。原有搜索仍可利用框中心对齐发现起点，最终以实际连接几何比较。
- **整组坐标压缩**：通过线性规划同时调整一组节点的横纵坐标，保持固定节点、现有直线、已对齐的列，以及节点与连线通道的相对分隔。目标考虑连线端点距离、纵向偏差和占地；求出坐标后仍按真实曲线和原有综合评分复核，必要时只尝试部分移动量。无改善或求解超时就保留输入布局。节点数乘连线数超过 60000 时跳过此附加步骤，原有整理流程继续工作。

所有最终候选都要求交叉、穿框、重叠三项分别不多于整理前；不能用减少重叠来换取新增交叉。三项相同时，综合布局代价必须降低才应用。中间搜索可以经过较差位置，但不会直接应用到画布。此规则以当前几何模型和评分为准，不宣称任意一次新搜索都胜过历史上所有搜索结果。

初步搜索采用曲线采样；最终复核按经典画布左右端口的三次贝塞尔曲线自适应细分，几何误差目标为 0.25 画布像素，并为相邻曲线留出余量。共用同一端口的线允许在端口附近 12 像素内自然汇合，超出此范围的重叠仍检查。节点检查包括标题栏，节点之间保留间距。

对于连线自己的源节点和目标节点，仅排除连接端口附近必然进入节点的一小段；节点整条侧边仍参与穿框检查。长曲线沿节点右边缘返回、或靠左边缘穿入时，不会因为落在边缘窄带而被忽略。

检查范围是**涉及本次整理的几何关系**：选中节点、关联连线与当前画布其他节点和线之间的关系。完全位于未选区域且不受整理影响的旧交叉或旧重叠，不要求同时消除。分组背景、框外附加名称标签和其他扩展自定义绘制内容不作为实体障碍。

## 如何判断比现状更好

候选与原布局按以下顺序比较，前一项相同时才比较下一项：

1. 节点重叠数量更少。
2. 连线穿过节点的数量更少。
3. 连线之间的交叉数量更少。
4. 三项数量全部为零时，优先保留原端口显示顺序的方案。
5. 前面的条件相同时，连接更紧凑、向左回折更少。

第 5 项的最终精修与浏览器复核使用以下代价：相连端口直线距离之和、向左回折水平距离的三倍、相连端口纵向落差的两倍、同目标上游支路横向中心偏离其中位数的距离之和、同输出口下游独立节点左边缘偏离其中位数距离的两倍，以及所选节点整体包围框宽高之和的四分之一。包围框包含标题栏，代价减少超过 1 才算改善。这样既鼓励短直线，也使无连线 Note 周围的大块空白参与紧凑度比较。这是布局评价指标，不是样条曲线实际弧长。

前面的拓扑搜索及居中步骤保留原来的节点框中心评价，先形成整体结构；最后的连线精修改用上述端口评价，避免高矮不同的节点为保持框中心一致而留下不必要的弯线。三类冲突仍比这些美观指标优先；精修不能通过增加冲突来换取短线。

端口排序读取**对方端口的实际纵坐标**，不只看对方节点顶部。同一对节点之间有多条线时，仍能区分各自落点；每侧排序后更新坐标，再处理另一侧，避免两端同时反转却保留原交叉。候选细化还尝试冲突相关端口的直接交换，并用曲线检查决定是否保留。

例如原来有 8 处交叉，整理后仍有 2 处，但重叠、穿框均为 0，就会应用并继续对齐。三项冲突数相同但连线明显缩短，也可以应用。三项均未改善且连接代价未下降，则保留原样。

压缩和对齐阶段要求三项冲突数分别不增加；若对齐后不再优于原布局，会退回仍有改善的候选。最终是否应用以浏览器实际测量的端口与控件几何为准，不只看搜索阶段的预测。

## 同列支路、端口直线与紧密间距

- **端口水平直连**：最终优先对齐相连输出口和输入口的纵坐标。两个节点高矮不同、端口距顶部的位置不同，也可得到水平直线；节点框本身不必水平居中。
- **已拉直的链整体移动**：继续调整下一条线时，已经水平连通的节点作为一个整体上下移动；收紧间距也保留这些端口高度关系。
- **同目标支路同列**：一组彼此无先后依赖、共同汇入同一主目标的节点，不必原本就很近，也会尝试对齐横向中心。额外连向没有后续连线的预览／保存终端，可以视为侧支路；若同时连向多个继续处理的目标，则不强制归入这一列。是否接受仍取决于实际几何和代价。
- **同输出口的下游同列**：同一个输出口连接多个彼此独立的下游节点时，尝试对齐这些节点的左边缘，使输入侧排列整齐。节点宽度不同也不会为了居中而让输入侧错开。若下游节点之间还有先后依赖，例如 `55 → 62 → 61` 同时存在 `55 → 61`，则不把 62、61 当作并列分支强行同列。
- **同列后整体压紧**：已有横向中心对齐或左边缘对齐的独立节点，联合试摆和最后收紧时按整列平移，保留不同宽度节点之间的横向偏移。不会为了让其中一个节点靠近目标，又把这一列拆散。
- **更小的目标间距**：最后收紧阶段以节点框之间水平 24、垂直 24 个画布单位为目标；垂直距离包含标题栏。已有更小且有效的间隔不会被刻意撑大。曲线、固定节点或其他障碍可能要求保留更大间距。
- **局部收紧**：单独拉近较短的支路或整列，不再让另一区域的高大节点阻止所有局部靠近。固定节点保持不动，原来向右的阶段不会移成反向关系。

例如 `A → B → C` 的节点高度分别为 200、500、300，精修可以使两条相连端口各自水平，而不是要求三个节点框中心相等。若另有 `A → C` 跨过 B，直线经过 B 会穿框，则 B 可以留在这条线下方；无法安全拉直的连接继续保留曲线。

### 联合试摆示例：55、62、61

这种保序试摆在允许换端口之前就执行：先从当前布局尝试拉直直连线并把中间处理节点放到线下方；进入精修时，仍保持原端口顺序的候选也先进行位置避让，再考虑换序。不会要求先靠其他搜索找到整个选区零冲突，才有机会尝试这个排列。原布局预处理最多约 2 秒，每个保序候选的前置避让最多约 1 秒并计入精修预算；实际冲突检查仍覆盖选区外固定节点和连线。

“原端口顺序”指点击整理时的顺序。如果已经应用过换序方案，再次整理会把该顺序视为当前基准；如需保留更早的顺序，应先撤销或手动恢复，再整理。

对于 `55 → 61 的输入1`、`55 → 62`、`62 → 61 的输入2`：

1. 先以 61 的第一个输入口为高度基准，尝试让 55 的输出口与它水平。
2. 即使这次试摆让直线碰到 62，也先在候选中把 62 的标题栏移到主线下方，并检查被它挤到的其他节点能否一同向下避让。固定或未选节点不能被移动。
3. 反向沿依赖关系压缩：先让 62 靠近 61，再让 55 靠近 62；同时试验附近节点边界对应的横坐标。
4. 将 62 尽量抬到主线下方保留间距的位置，缩短两条支路。用完整曲线检查联合结果，优于原布局才保留；失败则撤销这次试摆，继续比较其他候选。

上述中间步骤都在后台几何副本上计算，不会在画布上留下临时交叉或部分移动。它是有限时间内的边界候选搜索，不是遍历所有连续横坐标的数学最优证明。

这一步是在已有结果上继续改良，不承诺所有连接都能变成直线或达到全局最小面积。最终仍保留原布局与此前候选作为比较对象，没有改善就不替换画布。
- 优先沿最长依赖链对齐，再处理侧支和跨越连接；不会把有前后依赖的连续处理节点硬塞进同一列。
- 每次对齐都检查全部受影响的连线和节点。只有交叉、穿框、重叠三项数量均不增加时才接受合并。某处尚有交叉时，其他行列仍可以对齐；已经通过检查的对齐继续保留。
- 不同高度或不同端口行数的节点，框中心对齐后，端口之间仍可能有小幅弯曲；连接端口和参数身份保持原样。固定的外部节点、子图边界始终不移动。

例如条件回归节点后面连接“恢复内存检查和回收 → 预览任意”时，优先让这段尾链与主链共用水平中心线；主链旁边的常量支线按附近的列中心排列，减少零交叉但上下左右散乱的观感。

## 对齐后的紧凑间距

- 完成居中对齐后，再按中心线把节点分成行、列，整组靠近。不同宽高的节点仍保持原来的水平或垂直中心对齐，不通过缩小节点、压缩输入框或改变 Note 尺寸来节省空间。
- 第一轮整行整列压缩以横向约 **48 画布单位**、纵向约 **32 画布单位**为目标；后续连线精修再把两方向目标收紧到 **24 画布单位**。间隔按节点外框计算，纵向包含标题栏；页面缩放后视觉像素会变化，已有更小且有效的间隔不会为了凑目标值而拉大。
- 按不同位置分别压缩：一处已经靠近，不会让整个方向都停止收紧。例如一条链的三个间隔为 `20、1430、1250` 时，在没有其他约束的情况下，可以收紧为 `20、48、48`，同时保持整条链水平对齐。
- 每次尝试都复核交叉、穿框和重叠，三项数量均不增加才接受。遇到固定障碍或需要绕行的曲线时缩小移动量；也会尝试从空隙另一侧靠近。顺向连接保留原有左右关系，固定的上游、下游和子图边界不移动。
- 为了让回路线或跨越支线通过，实际间距可能大于目标值；算法在限定时间内尽量压缩，不保证所有间距相等或达到数学上的最小面积。收紧可取消，并受最终实际端口复核约束。

## 如何理解结果

| 提示 | 含义及处理 |
| --- | --- |
| 已整理若干节点 | 已通过候选及实际端口几何检查，报告冲突数量的前后变化、尝试数和耗时；正常保存即可 |
| 连接拓扑无法消除全部交叉，继续搜索 | 这是搜索阶段提示，不是终止。例如 K₅、K₃,₃ 或其细分结构无法全部消除交叉，仍搜索并应用优于原布局的方案 |
| 已采用本次找到的改善方案，仍有剩余冲突 | 已应用更好的布局，并报告剩余冲突，例如“2→4 与 12→2 交叉”；可以保存或撤销 |
| 本次没有找到比现状更好的布局 | 原布局保留；不代表不存在更好的排列，只代表本次搜索没有找到 |
| 按实际端口位置复核后，没有优于原布局 | 搜索预测有改善，但实际控件和端口位置测量后未改善；保留原布局，并列出相关冲突 |
| 计算期间工作流已变化 | 实际节点或连线布局已改变，原快照过时；缩放、平移不会触发此提示 |
| 已取消整理 | 浏览器中止请求，后端收到断开后停止搜索，画布保持原样 |

主要搜索上限约 **45 秒**。结构构造最多约 4 秒；找到零冲突候选后通常继续比较约 6 秒，并尝试初始分层变体，再进入压缩、居中对齐和复核。压缩对齐共享约 20 秒，连线精修共享约 18 秒；随后追加最多约 8 秒的约束压缩和结构候选精修，新增步骤受本次计算约 82 秒的截止时间限制。单次线性规划限时约 1 秒，取消会在步骤边界检查。复杂画布的单次几何检查、构造和实际坐标复核可能使总耗时超过阶段预算。搜索连接等待上限为 90 秒，实际几何复核请求为 30 秒；进度从后端流式传回，不是模拟百分比。每次新操作使用新的搜索种子。

算法不穷举全部位置和端口排列，因此不是任意约束布局问题的完备求解器。“本次最佳”指有限搜索中找到的候选，不保证数学上的全局最优。根据剩余冲突，可将相应外部节点加入选择、调整起始位置，或重新搜索其他候选。

## 示例：带固定入口的条件回归链

例如选中 `2、4、5、6、7、8、9、10、11、13`，上游 `3→12` 保持未选，而 `12→2` 是进入所选区域的连线。内部既有 `2→4→7→8→11→6→13→10`，也有跨越中间节点的 `2→6` 与 `7→6`。

整理时会把固定的 12 当作入口锚点，保留它的位置，避免为了居中铺开长链而将 2 放到 12 左侧，制造新的回折交叉。长连线与短支线共同参与排序和几何检查。这条规则适用于任意节点 ID，不是专门识别“调回点”或硬编码这个示例。

## 子图、外部连线与保存

- 子图内部只整理当前打开的一层，输入输出边界作为固定端点。整理外层子图节点的端口时，其内部对应边界同步显示顺序；不移动内部业务节点或改动其连接。
- 未选节点的位置不变，其连接线一起参与检查。端口顺序一般保持不变；若它与所选子图节点引用同一个子图定义，则共享该定义的接口显示顺序，会一起同步。候选试排撤回时一并还原受影响实例的顺序和尺寸。
- 选中的 Note 与无连线节点一样参与位置和重叠处理；不改写文字，也不自动绑定它所解释的节点。没有端口的 Note 不写入端口排序，文本框使用原生尺寸布局，重复整理不会持续增高；旧空排序记录也不会触发重排。
- 分组框不移动、不增删、不自动调整大小；需要重新打组时使用原生分组操作。
- 初次应用及每次方案切换各作为一次原生画布编辑，可撤销、重做。位置按原字段保存，普通节点端口顺序保存到 `properties.liuxinyu_port_order`，子图共享接口顺序保存到子图定义的 `extra.liuxinyu_port_order`，与手动 ↑ / ↓ 排序兼容。
- 已经手动调整端口或自动整理过的节点可以再次整理。保存和还原端口顺序时按版本号、输入顺序、输出顺序复制为独立数据，支持前端响应式属性及数组；不会因已有排序记录而出现 `structuredClone` 无法复制对象的错误。

## 兼容范围与常见问题

动态多行文本采用与手动端口排序相同的控件组计算：一个输入口对应的标题行和编辑框整体占位，连接后只计算标题行。标题不会再次被计入底部自由控件，零高度内部存储也不会虚增节点高度。

单端口不触发排序重排，后端几何预测也保留其原生行位置，避免把整数等节点的数值框移到输出标签旁边并缩窄。动态输出若绑定输入行，仍跟随该输入行的位置。

文件／目录选择按钮归入对应路径输入的控件组，不会在搜索时被当成独立底部控件重复计高。输入排列起点使用实际最上方输入行，支持键值对等“控件在预留端口上方”的布局。输出排序保留原有行间距；动态文本的输出行根据排列后的各输入块高度计算，收起块与展开块混合时也不会按统一 20 像素压缩。最终仍使用页面的实际几何复核候选。

| 现象或条件 | 说明 |
| --- | --- |
| 右键没有入口 | 至少选中两个当前画布节点；更新 JS 后刷新页面 |
| 提示需要重启后端 | `/liuxinyu/layout` 尚未加载，重启 ComfyUI 后刷新页面 |
| Vue Nodes、只读画布或其他连线样式 | 当前支持可编辑经典画布的样条曲线模式，不自行切换全局设置 |
| 选中折叠、固定或水平端口节点 | 先展开、取消固定；当前要求标准左右端口布局 |
| 画布包含连线转接点 | 当前不求解转接点路径，会明确提示，保持原样 |
| 端口指定上/下方向 | 当前不建立这类曲线的几何模型，会明确提示 |
| 规模太大 | 最多选 40 个节点，当前层快照最多 500 个节点、1000 条线，可进入较小子图处理 |
| 其他扩展绘制特殊端口或控件 | 实际测量后复核；自定义画法可能超出标准模型，页面视觉效果仍需核对 |
| 旧版整理后 Note 持续变长 | 更新并刷新页面后停止增长；已经拉长的尺寸可手动缩回后保存。修复不猜测原始尺寸，也不改 Note 文字 |
