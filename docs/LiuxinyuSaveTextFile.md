# 保存文本到文本文件

将字符串写入指定绝对目录下的文件，适合保存提示词、分析报告、JSON 文本、代码和配置。节点 ID 为 `LiuxinyuSaveTextFile`，添加菜单分类为 `utils/string`。

参数与[保存图像到绝对路径](SaveImageToAbsolutePath.md)类似，但本节点只负责写入文本字节，不根据文件后缀解析、校验或转换内容。

## 输入

| 参数 | 描述 | 数据类型 | 必需 |
| --- | --- | --- | --- |
| `文本` | 要写入的字符串，默认空字符串。可直接填写多行文本或连接上游；空字符串会写出空文件 | STRING | 是 |
| `文件夹` | 保存目录的绝对路径，默认 `D:\AI\outputs`。可手动输入、连接上游或点击“选择文件夹”；不存在的目录自动创建 | STRING | 是 |
| `文件名` | 纯文件名，默认 `test.txt`。支持任意扩展名和无扩展名，不接受目录路径 | STRING | 是 |
| `覆盖已有文件` | 默认开启。开启则覆盖同名文件；关闭则在最后一个扩展名前追加 `_1`、`_2`…，选择第一个未占用的名称 | BOOLEAN | 是 |

文件夹和文件名两端的空白会去掉；文本内容不会去掉空白。

## 输出

没有输出端口。本节点是保存用的终端节点，接好输入后即可作为工作流的执行出口，不必再连接预览节点。保存完成后执行结果中包含实际保存路径。

## 照做示例：保存渠道报告

1. 添加“保存文本到文本文件”。
2. 将生成报告的字符串输出接入 `文本`，例如实际内容为 `{"渠道":"综合","结论":"强调稳定性"}`。
3. 将 `文件夹` 设为 `D:\AI\outputs\渠道报告`。
4. 将 `文件名` 设为 `综合.json`，保持 `覆盖已有文件` 开启。
5. 运行后得到 `D:\AI\outputs\渠道报告\综合.json`，内容就是上述字符串。

若上游输出的是字典或数组，先用[js对象转换为字符串](LiuxinyuJSObjectToString.md)转换，再连接本节点。需要完整 JSON 时，由上游负责产生完整 JSON 文本。

也可以直接在文本框输入 `public class Demo { }`，文件名填 `Demo.cs`。保存结果是包含这段代码的 UTF-8 文件。

## 文件扩展名与实际内容

| 文件名示例 | 实际写入行为 |
| --- | --- |
| `report.txt`、`report.md` | 原样写入文本 |
| `report.json` | 原样写入文本，不检查 JSON 是否有效 |
| `Demo.cs`、`config.yaml` | 原样写入代码或配置，不检查语法 |
| `data.png` | 仍写入 UTF-8 文本，不生成 PNG 图像 |
| `README` | 不自动添加后缀，直接创建无后缀文件 |

例如将 `这不是 JSON` 保存为 `report.json` 也能成功。节点只负责文本落盘；系统默认程序能否识别该文件取决于实际内容。

## 编码、空白与换行

- 使用 UTF-8，不额外添加 BOM。
- 保留输入文本的所有空格、实际换行与末尾换行，不自动追加换行。
- LF、CRLF 和 CR 按输入原样编码，不因 Windows 系统而转换换行。
- 文本中的反斜杠不会被解释：两个字符 `\n` 仍写为两个字符，不变成换行。
- 空字符串写成零字节文件；开启覆盖时，也会把原文件内容清空。
- 不自动对对象序列化，也不把文本当作可执行代码运行。

## 覆盖、自动编号与目录

开启覆盖时，`report.json` 每次被实际执行就重新写入；较短的新文本会完整替换旧文本，不残留旧文件尾部。若同名路径是目录，会报错，不删除目录。

关闭覆盖时，如果 `report.json` 已存在，依次尝试 `report_1.json`、`report_2.json`。候选名称被文件或目录占用时都会跳过。无后缀的 `README` 对应 `README_1`；多个后缀的 `report.backup.json` 对应 `report.backup_1.json`。

父目录缺失时自动递归创建。文件名不能包含路径分隔符、冒号，不能是 `.` 或 `..`，也不能以句点结尾；其他操作系统不允许的名称或权限问题会由文件系统报错。

## 执行列表与重复运行

每个执行项保存一个文本文件。本节点使用 ComfyUI 普通逐项输入规则，不把执行列表收集成一个大字符串，也不自动生成批次子目录。

- 一个文本执行列表配一个固定文件夹和文件名时，每项都会保存。
- 同名且覆盖开启时，后项覆盖前项，最终保留最后一项。
- 要保留各项，可关闭覆盖，或提供与文本对应的文件名执行列表。
- 多个输入的执行列表长度不同时，沿用 ComfyUI 的规则：较短输入重复使用最后一项。
- 本节点不复用保存结果缓存；再次运行包含此节点的执行链，即使输入未改变，也会重新写入。关闭覆盖时，会继续生成编号文件。

如果要把整个数组存为一个文件，先将完整数组字符串化，再把这一条字符串传入；不要把数组展开成执行列表。

## 目录选择与端口显示

“选择文件夹”复用图片保存节点的 Windows 原生目录对话框，在运行 ComfyUI 的电脑上打开；远程浏览器仍保存到后端电脑的目录。

文本输入连接后，多行文本框按本包通用规则收起，断开后恢复。端口可按[端口显示排序](PortOrder.md)调整显示顺序；文件夹控件与选择按钮作为一组移动，仍修改原来的 `文件夹` 参数。

## 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 提示文件夹必须是绝对路径 | 填写类似 `D:\AI\outputs` 的完整路径，不使用 `outputs` 等相对路径 |
| 文件名不合法 | 文件夹单独填入 `文件夹`，`文件名` 只填 `report.json` 等名称 |
| 保存 `.json` 成功，但其他软件无法解析 | 检查上游文本是否为有效 JSON；本节点不做内容校验 |
| 执行多项后只保留了一份 | 同名且开启覆盖会依次覆盖；关闭覆盖或为每项提供不同名称 |
| 权限不足、目标被占用或同名目录 | 选择可写目录，关闭占用文件的程序；同名目录可改名避开，或关闭覆盖自动编号 |
| 想继续读取保存的文本 | 使用[从文本文件中获取字符串](LiuxinyuLoadTextFile.md)，填写实际保存路径 |
