# 比较运算符

通过下拉菜单选择 Python 比较运算，将两个输入转换为一个布尔判断。适合判断渠道名称、数值范围、字段是否存在，再接官方 `If/Else Switch` 选择需要的数据或处理分支，无需手写表达式。

节点 ID：`LiuxinyuCompare`；分类：`liuxinyu/逻辑运算`。

## 输入

| 参数 | 描述 | 数据类型 | 必需 |
| --- | --- | --- | --- |
| `运算符`（`operation`） | 默认“等于”；界面选项为“等于”“不等于”“小于”“小于或等于”“大于”“大于或等于”“同一对象”“不是同一对象”“属于”“不属于”。前端加载旧工作流时会把原有符号迁移为对应中文名称；旧 API 请求中的符号值也可正常验证与执行 | COMBO | 是 |
| `A`（`a`） | 左操作数；成员判断时是待查找的值 | ANY | 是 |
| `B`（`b`） | 右操作数；成员判断时是容器 | ANY | 是 |

两个数据口都必须连接。ANY 表示可以传递不同类型，不表示所有类型组合都支持排序或成员判断。节点不将字符串、整数、数组等互相转换。

## 输出

| 输出名称 | 描述 | 数据类型 |
| --- | --- | --- |
| `结果` | 对当前一对 A、B 求值后得到的单个 `true` 或 `false`；不输出逐元素比较数组 | BOOLEAN |

## 直接照做：按渠道选择模板

1. 将提取出的渠道名称接 `A`，例如 `综合`。
2. 添加字符串节点，填写 `综合`，接 `B`，选择运算符“等于”。
3. 将 `结果` 接官方 **If/Else Switch** 的 `switch`。
4. 将 `summary_conclusion-comprehensive.json` 接切换节点的 `on_true`，将 `summary_conclusion-sales.json` 接 `on_false`。
5. 切换输出接路径拼接或后续读取节点。

| A | B | 结果 | 切换输出 |
| --- | --- | --- | --- |
| `综合` | `综合` | `true` | `summary_conclusion-comprehensive.json` |
| `销量` | `综合` | `false` | `summary_conclusion-sales.json` |

这里的二选一规则是“等于综合／其他值”。若有第三种渠道，需要继续组合判断，不会自动识别额外类别。

## 各运算符的含义

| 界面名称（Python 含义） | 求值方式 | 示例及结果 |
| --- | --- | --- |
| 等于（`==`） | Python 值相等 | `1 == True` → `true`；`"1" == 1` → `false` |
| 不等于（`!=`） | Python 值不等 | `"综合" != "销量"` → `true` |
| 小于（`<`） | 小于 | `1 < 1.5` → `true` |
| 小于或等于（`<=`） | 小于等于 | `2 <= 2` → `true` |
| 大于（`>`） | 大于 | `"2" > "10"` → `true` |
| 大于或等于（`>=`） | 大于等于 | `3 >= 2` → `true` |
| 同一对象（`is`） | 两个输入是否为同一个 Python 对象 | 同一数组对象分别接 A、B → `true` |
| 不是同一对象（`is not`） | 是否不是同一个对象 | 两个内容相等但身份不同的数组 → `true` |
| 属于（`in`） | A 是否是 B 的成员 | `"topic" in {"topic": "承重"}` → `true` |
| 不属于（`not in`） | A 是否不是 B 的成员 | `"承重" not in {"topic": "承重"}` → `true` |

比较不短路，A、B 都要准备好；分支按需执行由后面的切换节点负责。

## 字符串、数值与容器

- 字符串按 Unicode 码点做字典序比较，逐位寻找首个不同字符；公共前缀相同时，较短字符串在前。不是拼音排序、自然数字排序或地区排序。
- `"2" > "10"` 为真。如果要按数字比较，先用“字符串转为字面量”转换数值，再连接本节点。
- Python 支持整数与浮点数混合比较；并不要求 A、B 类型完全相同。`1 < "2"` 则会报错，不自动将 `"2"` 转成整数。
- 列表比较遵循 Python 的逐项字典序；集合的 `< / <= / > / >=` 表示真子集、子集、真超集、超集，不是比较元素个数。
- `in` 对字符串判断子串，对字典判断键，对列表或集合判断成员。需要查字典值时，先用字段访问节点取值。
- 支持迭代器时，成员查找可能消耗迭代器，与 Python 相同。

## 值相等和对象身份

“等于”（`==`）判断值；“同一对象”（`is`）判断节点实际收到的两个引用是否指向同一个对象。不用对象内容的哈希代替身份，也不复制输入后再比较。身份运算每次执行重新判断，不复用旧的比较结果。

两个独立创建的列表 `[1, 2]` 可以 `==` 为真而 `is` 为假。小整数或字符串可能被 Python 复用；不要用 `is` 判断文本内容。应比较节点运行时实际收到的对象，不能仅从两个来源节点的外观推断身份是否相同。

图片、NumPy 数组等对象的 `==` 可能产生多个布尔元素。本节点要求一个明确布尔结果；多元素结果不能转换成单个 bool 时，按 Python 行为报错，不擅自采用“全部相等”或“任意相等”。需要比较完整图片等数据内容时，可使用[判断哈希相等](LiuxinyuHashEqual.md)。

## 数组与执行列表

完整数组作为一个对象参与比较或成员查找。若上游是执行列表，ComfyUI 按项调用本节点，输出对应的布尔执行列表；两路列表按框架规则对齐，短的非空列表重复末项，不做笛卡尔积。

例如要判断整数 `2` 是否属于 `[1, 2, 3]`，将字面量节点的 **完整字面量** 输出接 B。若误接展开后的“字面量”，B 将逐项成为 `1`、`2`、`3`，整数不能作为 `in` 的容器。

## 常见问题与报错

| 现象 | 原因及处理 |
| --- | --- |
| 少连接一个输入无法运行 | 所有比较都是二元运算，A、B 都要连接；`None` 是实际值，不等于缺少连线 |
| 排序比较抛出 TypeError | 当前 Python 类型组合不可比较；先明确所需类型，再使用转换节点 |
| 成员判断报“不可迭代” | 检查 B 是否真的是容器，是否误把执行列表展开成了标量 |
| 空值或空容器的结果 | `None` 使用“等于”比较为真；`1 in []` 为假；其他行为遵循 Python，不把空值当作错误替代值 |
| 多元素数组的真值不明确 | 当前对象的比较结果不是单个布尔；先明确整体判断规则或改用完整内容比较节点 |
