# 条件为真时报错停止

根据布尔条件明确决定是否报错。条件为 `true` 时，将输入的错误信息作为当前执行的失败原因；条件为 `false` 时正常完成，并输出 `true` 表示检查已经放行。

节点 ID：`LiuxinyuRaiseIf`；分类：`liuxinyu/流程控制`。条件和错误文本可以来自任意上游，不要求使用某一种校验节点。

## 输入

| 参数 | 描述 | 数据类型 | 必需 |
| --- | --- | --- | --- |
| `停止条件`（`condition`） | 默认 `false`；为 `true` 时才报错 | BOOLEAN | 是 |
| `错误信息`（`message`） | 需要停止时报告的文本；默认“条件满足，停止当前执行。”；空文本也使用这条默认信息 | STRING | 是 |

“错误信息”采用按需读取：停止条件为 false 时，不会为了这个节点执行已连接的错误信息生成分支。其他节点也依赖该分支时，仍由那些节点决定是否执行。

## 输出

| 输出名称 | 描述 | 数据类型 |
| --- | --- | --- |
| `继续执行` | 停止条件为 false 时输出 true；停止条件为 true 时节点报错，没有正常输出 | BOOLEAN |

“继续执行”表示本次检查完成后的放行信号，不是原条件的原样转发。本节点也可作为末端节点，不接输出时仍会参与正常的整图提交执行。

## 示例：校验失败时停止

```text
校验节点的“校验通过” → Not → 停止条件
校验节点的“错误信息” ─────→ 错误信息
```

| 校验通过 | Not 结果 | 本节点行为 |
| --- | --- | --- |
| true | false | 正常完成，输出“继续执行”true |
| false | true | 用上游错误信息报错停止 |

如果上游输出的本来就是“有错误”，直接接停止条件即可，无需 Not。

## 让数据处理等待检查

工作流可能有多个独立执行分支。仅把报错节点接在旁边，不能保证另一条数据分支尚未执行。需要先检查后使用数据时，可这样连接：

```text
本节点“继续执行” → If/Else Switch 的 switch
待处理数据 ──────→ If/Else Switch 的 on_true
                   分支输出 → 后续处理
```

停止时分支节点无法拿到放行信号，因此受这条依赖控制的下游不会继续处理数据。这里使用 ComfyUI 已有的 If/Else Switch，无需把任意业务数据传入报错节点。

## 停止范围与其他选择

报错针对当前执行任务，不取消其他排队任务，也不撤销此前已经保存的文件、发送的请求或其他外部操作。

如果校验失败后需要备用结果、条件回归或重试，应直接使用校验状态与错误文本组织对应分支，不连接这个停止节点。本节点只负责显式报错，不提供重试次数、回退或循环功能。
