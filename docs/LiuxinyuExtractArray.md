# 下标提取数组元素为新数组

按一个整数下标数组，从原数组中选取元素并组成新数组。适合抽取指定记录、按指定顺序重排部分元素，或重复选取某些元素。

节点 ID：`LiuxinyuExtractArray`；分类：`liuxinyu/结构化数据`。输入输出采用同包数组重排序节点的完整数组约定，下标采用“从字符串数组读取字符串”的从 0 开始及越界报错规则。

## 输入

| 参数 | 描述 | 数据类型 | 必需 |
| --- | --- | --- | --- |
| `数组` | 待提取的完整原生数组，元素可以是数字、字符串、字典、嵌套数组、null 等任意类型；无默认值，需要连接 | ARRAY | 是 |
| `下标数列` | 完整整数数组，如 `[2,0,2]`；每项必须是 int，不能是布尔值、小数或数字字符串；无默认值，需要连接 | ARRAY | 是 |

两个输入均接收解析后的数组，不解析 JSON 文本、不接受元组或单个对象。下标从 `0` 开始，合法范围是 `0` 到原数组长度减 `1`，不支持负数倒数索引。

## 输出

| 输出名称 | 描述 | 数据类型 |
| --- | --- | --- |
| `提取出来的数组` | 按下标数列的顺序组成一个完整数组，保留重复项、元素类型和嵌套结构，不展开为执行列表 | ARRAY |

## 示例：指定顺序并重复提取

1. 用“字符串转为JS对象”解析 `[{"名称":"甲"},{"名称":"乙"},{"名称":"丙"}]`，结果接 `数组`。
2. 用另一个“字符串转为JS对象”解析 `[2,0,2]`，结果接 `下标数列`。
3. 将 `提取出来的数组` 接“预览JS对象或数组”，运行后得到：

```json
[{"名称":"丙"},{"名称":"甲"},{"名称":"丙"}]
```

也可使用“多个数值组成数组”提供下标，但所有数值必须是整数；该节点混入浮点数时会统一为浮点数，不符合本节点的下标要求。使用“字符串转为字面量”时，应连接其保留完整数组的输出。

## 顺序、重复项与原数据

输出顺序完全由下标数列决定，不排序、不去重、不补齐未指定项。例如 `[1,0]` 先取第二项再取第一项，`[0,0]` 两次选取第一项。

节点创建新的外层数组，不修改原数组或下标数组。元素保留原对象，不深拷贝；字典、嵌套数组和图片张量等均作为一个元素保留，不展开。重复下标引用同一个原始元素，不生成独立副本。

## 空数组与输入错误

| 输入情况 | 结果 |
| --- | --- |
| 下标数列是 `[]` | 输出 `[]`，包括原数组也是空数组的情况 |
| 原数组是 `[]`，下标数列非空 | 越界报错 |
| 下标包含 `-1` 或不小于数组长度的整数 | 报告下标位置、下标值和原数组长度，不截断或跳过 |
| 下标包含 `1.0`、`"1"`、`true` 或 null | 类型错误，不自动转换 |
| 原数组或下标数列是 JSON 文本 | 先用独立解析节点转换为数组 |

若任何下标不合法，本次节点报错，不交付部分提取结果。

## 执行列表怎样处理

本节点不主动收集或展开执行列表，遵循 ComfyUI 原生逐项调用：每次调用的两个输入值都必须是数组。上游执行列表的每项都是数组时可以直接连接；每项是单个整数或单个字典时，不能代替完整数组。

例如 `数组` 上游有两项 `["甲","乙"]`、`["丙","丁"]`，`下标数列` 提供一个完整数组 `[1,0]`，分别输出 `["乙","甲"]` 和 `["丁","丙"]` 两个数组执行项，不将两组数据合并。两路都有执行列表时，按原生规则逐项配对；非空短路输入复用最后一个执行项。

若需要把多个整数执行项整体作为下标数列，先连接“执行列表收集为数组”。空执行列表交由原生执行器处理，本节点不会将其自动收集为完整空数组。

## 开发与验证

节点位于包根目录 `array_extract_node.py`，沿用 V3 `io.Schema` / `io.NodeOutput` 和根目录自动扫描注册，无需额外前端脚本。新增后重启 ComfyUI 后端并刷新页面，搜索中文节点名即可添加。验证应覆盖顺序与重复项、元素引用保留、空输入、类型与越界错误，以及执行列表中的数组逐项映射。
