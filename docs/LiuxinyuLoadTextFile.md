# 从文本文件中获取字符串

按路径读取一个文本文件，输出文件内容以及字符总数、行数，方便把整段提示词、名单或说明文字接入工作流。

## 输入

| 参数 | 描述 | 数据类型 | 必需 |
| --- | --- | --- | --- |
| `文件路径` | 文本文件的路径，可手动填写、连接上游或点击“选择文件”按钮；路径两端成对的英文双引号会自动去掉 | STRING（默认空） | 是 |

## 输出

| 输出名称 | 描述 | 数据类型 |
| --- | --- | --- |
| `文本内容` | 整份文件内容的一个字符串，保留原有空格和换行，不含 BOM，不把反斜杠解释为转义；文件路径接执行列表时按路径逐项各运行一次 | STRING |
| `字符总数` | 按 Unicode 码点计数，包含换行字符（CRLF 占 2 个） | INT |
| `行数` | 换行次数加一；CRLF、LF、CR 都算一次换行，空文件为 0 行 | INT |

## 怎么用

在“文件路径”填入文本文件路径（例如 `D:\素材\提示词.txt`），也可以连接上游字符串或点击“选择文件”按钮挑选。路径两端成对的英文双引号会自动去掉，不填路径时报错“请填写或选择文本文件路径。”

文件内容没有变化时复用上次读取结果；文件被修改后再次运行会自动重新读取。

| 输出 | 文件内容为 `苹果`、换行、`香蕉` 时的结果 |
| --- | --- |
| 文本内容 | 原样两行文本 |
| 字符总数 | 5 |
| 行数 | 2 |

## 编码与内容

- 优先按 UTF-8 读取（自动忽略 BOM），识别带 BOM 的 UTF-16/32，都不是时尝试 GB18030（兼容 GBK），仍失败才提示把文件保存为 UTF-8。
- 输出保留原有空格和换行，不包含 BOM，也不会把文本里的反斜杠解释为转义；要按转义解析文本时用[字符串转为字面量](LiuxinyuStringToLiteral.md)。

## 字符总数与行数

字符总数按 Unicode 码点计数，包含换行字符：CRLF 一次换行占 2 个字符，LF、CR 各占 1 个。行数为换行次数加一，CRLF、LF、CR 都算一次换行；空文件为 0 行，末尾换行会保留一个空行。

例如文件内容为 `苹果\n香蕉\n`：字符总数 6，行数 3，最后一行是空行。

## 常见问题

- 想按行拆开内容时，把“文本内容”接到[切分字符串为数组](LiuxinyuStringArraySplit.md)，分隔符传入实际换行。
- 文件是 JSON 时，可接[字符串转为JS对象](LiuxinyuStringToJSObject.md)解析成对象再读取字段。
