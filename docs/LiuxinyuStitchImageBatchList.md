# 从批次列表拼接图片

收取“图片”输入的整个图片执行列表，按顺序展开全部图片拼成长图：横拼统一高度、竖拼统一宽度，图片之间不留间隔。这是一个整体收集执行列表的节点，放在“分包执行子流回归”的起点与回归之间时只处理当前包。本节点不保存文件，需要保存时另接保存节点。

## 输入

| 参数 | 描述 | 数据类型 | 必需 |
|---|---|---|---|
| `图片` | 普通 IMAGE 接口：单张图片、单个批次、多个批次的列表都可以接，整批收取 | IMAGE | 是 |
| `拼接方向` | 从左到右、从右到左、从上到下、从下到上；反向只反转排列顺序，不翻转图片。默认“从左到右” | COMBO | 是 |
| `目标格式` | 仅控制分段上限，不保存或编码图片：PNG 单边最大 2147483647、JPEG 65500、WebP 16383 像素。默认 PNG | COMBO | 是 |

## 输出

| 输出名称 | 描述 | 数据类型 |
|---|---|---|
| `拼接图片` | 拼接结果，IMAGE 执行列表，下游逐批各执行一次；总长超过所选格式单边上限时沿拼接方向连续切分、不丢失像素，每个批次只有一张图，最后一段可以较短，分段按最终画面从左到右或从上到下的顺序输出；不分段时输出仅一个批次（一张完整长图） | IMAGE |

## 直接照做：多个详情页目录各自拼接

1. “字符串转为字面量”填 `["产品A","产品B"]`，把目录执行列表接“分包执行子流回归”起点的输入1。
2. 起点输出1接“从目录中匹配路径或目录”，再接“从路径加载图像批次”。
3. 加载结果接本节点“图片”，“拼接方向”选“从上到下”。
4. “拼接图片”接回归节点的输入1；起点的“分包回归条件”直连回归的同名输入。
5. 回归输出1接“预览超长图片”或保存节点，得到每个目录各一张长图。

```text
目录列表 → [起点：输入1]
             输出1 → 匹配 → 加载 → 本节点 → [回归：输入1]
             条件 ────────────────→ [回归：条件]
                                         输出1 → 预览/保存
```

不使用分包、把多个目录的图片都接到“图片”时，所有图片会收进同一张长图；分包用法详见 [分包执行子流回归](LiuxinyuPacketStart.md)。

## 拼接行为

- 展开与顺序：按列表顺序、各批次内部顺序展开全部图片。
- 尺寸统一：横拼把所有图片等比例放大到其中的最大高度，竖拼放大到最大宽度，像素尺寸四舍五入；不裁剪、不留间隔。
- 通道补齐：按输入中的最多通道数补齐，缺少的通道补白色。
- 内存检查：估算总输出超过当前可用显存/内存约六成时直接报错，分段只减小单次分配，不减少总量。

例如竖拼总高 20000 像素、选 WebP，会得到 16383 与 3617 两段。

## 常见问题

- 提示“统一后的高度（或宽度）超过……单边上限……请换用目标格式”：横拼只能统一高度，无法沿拼接方向把它切小。换用 PNG/JPEG 目标格式，或先缩小图片再拼接。
- 提示“拼接结果需要约 X GB 显存/内存……无法完成”：分段只减小单次分配，不减少总量；估算超过当前可用显存/内存约六成时直接报错。请减少输入图片数量，或在拼接前降低分辨率。
- 多个目录的图片混成一张长图：拼接位于回归之后，或全部图片直接进入本节点，都会被收进同一张。把“加载 → 拼接”放进起点与回归之间，回归输出才会是每目录各一张。
- 结果没有落盘：本节点只拼接不保存，接“保存图像到绝对路径”等保存节点；实际保存格式由保存节点决定，与“目标格式”无关。
- 想按自定义位置切分长图：用“最终切分（按边界）”，见 [最终切分（按边界）](LiuxinyuSplitSegments.md)；本节点的分段只为满足格式上限。
- 小图被放大：统一到最大高度/宽度是等比例放大，不缩小、不裁剪。
