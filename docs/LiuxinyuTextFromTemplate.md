# 从模板生成文本

把模板里的 {t1}、{t2}…占位符替换成对应输入文本，可直接接 CLIP 文本编码等提示词输入。

## 输入

| 参数 | 描述 | 数据类型 | 必需 |
|---|---|---|---|
| `模板` | 含 {t1}、{t2}…占位符的文本；模板里写了却没提供的占位符原样保留，替换进去的内容不会再被递归解析。默认 `你好，我喜欢喝{t1}，且我喜欢吃{t2}，我在{t3}里面做{t4}`，支持多行 | STRING | 是 |
| `参数组合` | 连接[字符串排列组合](LiuxinyuStringCombinations.md)的输出；连接后忽略单独的 t1、t2…输入，由 ComfyUI 逐条处理组合 | TEMPLATE_PARAMETERS | 否 |
| `t1`～`t100` | 对应模板中的 {t1}、{t2}…占位符的输入文本，可接单个字符串或字符串执行列表；端口随连接增加，动态参数最多 100 个 | STRING | 否 |

## 输出

| 输出名称 | 描述 | 数据类型 |
|---|---|---|
| `字符串数组` | 生成的文本，STRING 执行列表，下游逐项处理（见[数组、执行列表与图片批次](DataLists.md)）：接参数组合时每条组合生成一行文本；直接接列表时多路按行对齐，第 i 行取各路第 i 项，较短的一路复用其最后一项凑齐行数，某一路为空列表时输出空列表 | STRING |

## 单独填写参数

在 t1、t2…输入口接上字符串即可替换对应占位符。

## 模板编辑框与端口连接

“模板”端口未连接时，节点显示可编辑的多行模板框。只有“模板”本身接入上游字符串时，编辑框才收起，执行时使用上游文本；框内原有文字保留，断开模板连线后恢复显示和编辑。

收起后只保留带“模板”名称的一行端口，后续控件上移、节点自动缩短；端口索引与连线保持不变。使用 ↑ / ↓ 调整端口顺序后，断开连线时编辑框仍随该端口恢复。提升到子图外部的模板输入也采用相同规则，详见[多行输入连接后收起](MultilineCollapse.md)。

连接 t1、t2、t3 或“参数组合”不会隐藏模板。动态端口增加、重排或工作流重新加载后，收起状态按“模板”端口的当前连接重新判断，不依赖它位于第几个输入口。

例如模板填写 `渠道：{t1}`，仅将字符串 `综合` 接 t1：模板框应继续显示，输出为 `渠道：综合`。再将另一个字符串节点的 `当前渠道为{t1}` 接到“模板”：模板框收起，输出为 `当前渠道为综合`；断开“模板”连线后，恢复原先的 `渠道：{t1}`。

| 现象 | 检查方法 |
| --- | --- |
| 接了 t1 后找不到模板框 | t1 不是模板输入，模板框应该保留。更新前端后，先保存当前画布，再刷新页面 |
| 模板已连接，原文字在哪里 | 仍保存在模板控件中，断开模板输入后可继续编辑 |
| 旧画布保存的节点高度过小 | 加载时会根据可见编辑框所需高度恢复；足够高的手动尺寸保持不变 |

## 连接参数组合（推荐）

把[字符串排列组合](LiuxinyuStringCombinations.md)的“参数组合”接到本节点“参数组合”输入后：

1. 单独的 t1、t2…输入被整体忽略，不再参与。
2. 每条组合生成一行文本，输出为字符串执行列表。
3. 下游逐条执行，例如逐条提示词编码出图。

## 示例

| 模板 | 参数 | 输出 |
| --- | --- | --- |
| `你好{t1}` | t1 接 `苹果` | `你好苹果` |
| `你好{t1}` | t1 未提供 | `你好{t1}` |

模板 `{t1}{t2}` 接参数组合（t1：红、蓝；t2：S、M）时输出四行：红S、红M、蓝S、蓝M。

## 把两份 JSON 文本组合成一份模型输入

模板只替换文本，不会自动加引号、转义内容、解析 JSON 或核对业务字段。若 t1 和 t2 来自对象，分别先接[js对象转换为字符串](LiuxinyuJSObjectToString.md)，再接本节点。

例如 t1 为分组信息：

```json
{"topic":"承重","definition":"产品承受重量和负载的能力","recordPaths":["[0][0]","[1][0]"]}
```

t2 为按同一份路径清单读取、组装并合并的记录字典：

```json
{
  "[0][0]":{"imageIndex":1,"designAnalysis":"通过多人同时使用，强调承重能力","visualDescription":"多人站在产品上，标注承重数值","topic":"承重"},
  "[1][0]":{"imageIndex":1,"designAnalysis":"通过重物测试展示承重能力","visualDescription":"产品上堆放重物，旁边标注重量","topic":"承重"}
}
```

模板填写：

```text
{"group":{t1},"records":{t2}}
```

当两路各有一项时，输出一个字符串执行项，完整文本内容为：

```json
{
  "group": {
    "topic": "承重",
    "definition": "产品承受重量和负载的能力",
    "recordPaths": ["[0][0]", "[1][0]"]
  },
  "records": {
    "[0][0]": {
      "imageIndex": 1,
      "designAnalysis": "通过多人同时使用，强调承重能力",
      "visualDescription": "多人站在产品上，标注承重数值",
      "topic": "承重"
    },
    "[1][0]": {
      "imageIndex": 1,
      "designAnalysis": "通过重物测试展示承重能力",
      "visualDescription": "产品上堆放重物，旁边标注重量",
      "topic": "承重"
    }
  }
}
```

上例排版便于阅读；实际空格与换行由两段输入文本和模板决定。输出端口是 STRING 执行列表，文本内部的 `group`、`records` 是 JSON 对象。不要将模板写成 `{"group":{t1},"records":"{t2}"}`：对象文本里的引号和换行没有转义，直接套引号会形成无效 JSON。普通字符串若要作为 JSON 字符串值，需要先正确 JSON 编码，不能简单加引号。

本场景中 `records` 的键应与 `group.recordPaths` 一致；模板节点不会检查或修正不一致的路径，也不会重新读取记录。`imageIndex` 是业务字段，不决定记录所在的数组下标。路径读取与合并接法见[记录数组与路径字段处理](ObjectRecordTools.md)。

## 开发与验证

模板替换由 `string_node.py` 实现，多行控件收起由 `multiline_collapse.js` 处理。`tests/test_multiline_collapse.cjs` 覆盖端口重排、加载时替换端口对象、连接和断开模板、文字保留、过小高度恢复及已有回调；`tests/test_dynamic_multiline.cjs` 检查动态多行节点的相关交互逻辑。前端脚本修改后刷新页面生效，无需重启后端。
