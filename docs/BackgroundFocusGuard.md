# 页面失焦时不抢回浏览器焦点

切换到其他程序、切换标签页或最小化浏览器后，ComfyUI 的旧版属性编辑框和节点搜索框不应继续请求焦点。本扩展限制这些原生控件的回焦行为，使用户能够离开页面。

## 修复范围

当前前端的原生属性编辑和旧版搜索输入框有三处 `blur` 回调，会无条件执行 `this.focus()`。旧版搜索框关闭时，还会立即聚焦画布，并在 20 毫秒后再次聚焦。页面处于后台时，这些调用可能干扰窗口切换。

失焦过程中的 `document.hasFocus()` 不一定已反映最终状态。离开窗口时如果它仍为真，仅凭该值判断会放行原生回焦，从而可能导致任务栏请求注意或最小化后恢复。现在还检查失焦事件的 `relatedTarget`：没有明确的页面内焦点目标时，不允许这些输入框在失焦回调里同步抢回焦点。

| 情况 | 行为 |
| --- | --- |
| 页面已经失去焦点或标签页隐藏 | 阻止上述原生输入框在失焦回调中重新聚焦 |
| `relatedTarget` 为空，焦点目标在浏览器工具栏、其他窗口或无法确定 | 即使 `hasFocus()` 暂时仍为真，也不允许同步回焦；点击页面内不可聚焦的空白区域时同样不强制抢回 |
| 后台搜索框关闭后请求画布焦点 | 忽略立即调用和延迟调用 |
| 页面处于前台，焦点转向明确的页面内控件 | 保留原生焦点行为 |
| 其他输入框、普通文字输入、参数值保存 | 不拦截其失焦事件，不修改输入内容 |

画布背景面板另在自身控件中处理：鼠标移出数值浮层时仍提交输入和隐藏浮层，但只有移到明确的页面内目标、页面可见且仍有焦点时才把焦点还给滑条；离开窗口或最小化时不会主动聚焦滑条。

本功能不设置操作系统的“始终置顶”，不主动切换窗口，不监控屏幕内容，也不关闭用户的编辑框。它处理明确找到的页面回焦路径；系统置顶工具、浏览器插件或其他程序主动激活窗口，属于另外的原因，不能仅凭相似现象认定已被本修复覆盖。

## 使用

更新后刷新页面即可，无需重启后端。打开属性编辑框或旧版节点搜索框，再切换到其他窗口，检查浏览器是否仍反复回到最前；返回 ComfyUI 后应能正常继续输入。

偶发问题需要分别检查：编辑一个原生属性后切换窗口或标签页、最小化并等待、返回继续编辑，以及编辑背景数字后直接离开窗口。重点看任务栏是否无故高亮、最小化是否能保持；它们可能是同一回焦请求的不同表现，截图或录屏本身不能确定具体 JavaScript 调用栈。

## 开发与验证

常规保护实现位于 [`focus_guard.js`](../focus_guard.js)。对 `.graphdialog input.value` 的捕获阶段失焦事件检查页面活动状态及 `relatedTarget`，阻止后台或目标不明确时的原生强制回焦，并为当前画布的 `focus()` 增加活动状态检查。背景浮层对应检查位于 [`canvas_background.js`](../canvas_background.js)。常规保护没有修改全局 `HTMLElement.prototype.focus` 或安装定时抢焦点逻辑。

```powershell
node tests/test_focus_guard.cjs <当前前端 settingStore-*.js 的完整路径>
```

测试提取安装版本的三个原生失焦回调和旧版搜索关闭回调，验证后台回焦被阻止、延迟回调也受限制，以及 `hasFocus()` 仍为真但 `relatedTarget` 已为空的切换时序。检查前台向明确控件转移焦点保持原生行为，其他输入的失焦提交仍执行。背景交互回归另覆盖离开页面、后台及隐藏标签页不聚焦滑条。操作系统实际窗口切换效果需要用户验收；命令行测试不等同于现场复现每一次偶发抢焦点。
