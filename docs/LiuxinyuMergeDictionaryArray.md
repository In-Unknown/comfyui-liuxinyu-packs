# 并和数组中的字典字段为字典

把一个数组内所有字典的第一层键值对合并到一个新字典。例如输入 `[{"a":1},{"b":2,"c":3}]`，输出 `{"a":1,"b":2,"c":3}`。

节点 ID：`LiuxinyuMergeDictionaryArray`；分类：`liuxinyu/结构化数据`。适合汇总分别构造的配置字段、命名内容、编号映射等。字典可以来自文件、接口、手动构造或其他节点，没有固定字段名，也不要求键是路径。

## 什么时候使用

| 你现在需要做什么 | 选择 |
| --- | --- |
| 已有一个字典数组，希望把各字典的字段放进同一个字典 | 使用本节点 |
| 上游给出多个字典执行项，希望合成一个字典 | 先接[执行列表收集为数组](LiuxinyuCollectExecutionList.md)，再接本节点 |
| 已有一个键和一个值，需要创建字典 | 使用[组装键值对](LiuxinyuBuildKeyValuePairs.md) |
| 希望保留多条记录，每条记录各自含有相同字段 | 保留数组；或先用唯一键分别包装记录，再合并 |
| 希望向已有完整数据的某个位置新增字段 | 将组装结果交给[插入字段到字典或者js对象](LiuxinyuInsertJSObject.md) |
| 希望递归合并嵌套对象、覆盖重复字段、拼接同名数组值 | 本节点只合并最外层字段，不执行这些操作 |

## 输入

| 参数 | 描述 | 数据类型 | 必需 |
| --- | --- | --- | --- |
| `字典数组`（`dictionaries`） | 一个完整原生数组，每一项都必须是字典；例如 `[{"name":"A"},{"score":8}]` | ARRAY | 是 |

没有额外配置项。DICT 或 ARRAY 端口中的对象是解析后的数据，不是 JSON 文本。若输入来自文本，先用[字符串转为JS对象](LiuxinyuStringToJSObject.md)解析；若来自执行列表，先收集为一个数组。

数组的一项可以包含零个、一个或多个字段。字段值可以是文本、数字、布尔值、null、数组、字典、图片或其他原生值，不会被自动转成字符串。

## 输出

| 输出名称 | 描述 | 数据类型 |
| --- | --- | --- |
| `合并后的字典` | 包含全部输入字典第一层字段的一个新字典；作为一个完整值输出，不拆成执行列表 | DICT |

输出按输入数组顺序、各字典内部的键顺序建立。原数组和各个输入字典都不被修改；没有“挂载位置”或“原始容器”输入。

## 示例：合并多个字段对象

输入：

```json
[
  {"name":"A","score":0},
  {"enabled":false},
  {"tags":["x","y"],"options":{"mode":"fast"}},
  {"note":null}
]
```

输出：

```json
{
  "name":"A",
  "score":0,
  "enabled":false,
  "tags":["x","y"],
  "options":{"mode":"fast"},
  "note":null
}
```

`tags` 数组和 `options` 字典完整保留在各自的键下，不向外展开。0、false 和 null 都是有效值，不会因其为空或为假而丢弃。

## 执行列表怎样连接

假设上游分别输出三个字典执行项：

```text
执行项 1 → {"name":"A"}
执行项 2 → {"score":8}
执行项 3 → {"enabled":true}
```

1. 将这条执行列表接“执行列表收集为数组”，得到完整数组 `[{"name":"A"},{"score":8},{"enabled":true}]`。
2. 把这个数组接入本节点的“字典数组”。
3. 得到一个完整字典 `{"name":"A","score":8,"enabled":true}`，下游收到一个执行项。

如果上游没有执行项，收集节点得到 `[]`，本节点输出 `{}`。如果直接传入多份“字典数组”执行项，ComfyUI 会分别执行本节点，各次结果独立；不会自动跨执行累计合并。

## 多条记录需要先确定如何保留身份

下面两条记录都有 `name` 字段：

```json
[{"name":"A"},{"name":"B"}]
```

直接合并会因为重复键 `name` 而报错。一个字典无法同时保留两个同名的最外层字段；如果要保留两条完整记录，可以继续使用原数组，或者先用各自编号包装：

```json
[{"A":{"name":"A"}},{"B":{"name":"B"}}]
```

合并后得到：

```json
{"A":{"name":"A"},"B":{"name":"B"}}
```

包装由“组装键值对”完成：编号接“键”，整条记录接“值”。本节点只合并包装后的字段，不猜测编号、不自动生成键，也不从记录中提取字段。

## 多路径读取：读取、组装、收集、合并

原数据为 `[{"name":"A"},{"name":"B"}]`，需要按路径读取两个对象并保留其位置：

1. 路径数组 `["[0]","[1]"]` 接[将任意数组转为执行列表](LiuxinyuArrayToExecutionList.md)，得到两个路径执行项。
2. 路径执行列表接[使用js点符号语句读取对象](LiuxinyuReadJSObjectPath.md)的“读取语句”；完整原数据接“对象或数组”，逐项读出两个对象。
3. 同一条路径执行列表接“组装键值对”的“键”，读取结果接“值”，分别得到 `{"[0]":{"name":"A"}}` 和 `{"[1]":{"name":"B"}}`。
4. 接“执行列表收集为数组”，再接本节点，得到：

```json
{"[0]":{"name":"A"},"[1]":{"name":"B"}}
```

这里的路径只是本节点收到的普通字典键。路径是否存在由读取节点检查；重复路径会在合并时表现为重复键。两条执行列表应来自同一份路径清单并保持顺序，不能在其中一条上独立过滤或排序。

路径可能为空时，应先判断路径数组：空路径直接使用空字典数组 `[]`，跳过逐项读取和组装，再交给本节点输出 `{}`。这样可避免 ComfyUI 把固定原数据与零个路径执行项配对时发生空列表取值错误。旧的“按路径读取多项完整内容”已移除，改用上述基础节点组合。

## 重复键、嵌套和空输入

| 输入情况 | 行为 |
| --- | --- |
| `[]` 或 `[{},{}]` | 输出 `{}` |
| 数组中某项为 `{}` | 没有字段，跳过该项 |
| `[ {"a":1}, {"a":2} ]` | 重复键，报错，不覆盖 |
| `[ {"a":1}, {"a":1} ]` | 即使值相同，也因重复键报错 |
| `[ {"settings":{"a":1}}, {"settings":{"b":2}} ]` | 最外层 `settings` 重复，报错；不会递归合并内部对象 |
| `[ {"left":{"name":"A"}}, {"right":{"name":"B"}} ]` | 成功；两个内部对象中的同名字段互不冲突 |
| `[ {"":null} ]` | 空字符串是合法键，原样保留 |
| `[ {"a.b":1}, {"items[0]":2} ]` | 键按原文保留，不解释为路径 |
| 数组中出现 null、数字、字符串或子数组 | 报错，并指出不是字典的项的位置；不跳过、不递归展开 |
| 输入单个字典或 JSON 文本 | 报错；输入必须是完整字典数组 |

键按原生字典规则比较，不做重命名、大小写转换、去空格或字符串化。JSON 对象的键是字符串；其他上游产生的原生字典键也保持原类型，最终能否保存为 JSON 由后续节点决定。

## 输入保护和错误处理

节点创建新的外层字典，内部值保留原引用，不深拷贝图片、模型或嵌套容器。如果发生重复键或类型错误，本次不返回部分合并结果，所有输入仍保持不变。

本节点不检查业务字段是否完整，不要求固定字段类型，不向原数据写回。合并成功后可以接预览、序列化或任何接受 DICT 的节点；含图片、模型等值的字典不一定能直接转成 JSON 文本。
